# Design review · P3-14 Home trending sounds row

Reviewed 15 Nov 2026 against `docs/ux/specs/P3-14-home-trending-sounds.md`, P0-05, P3-02/03/04 and P3-11. Evidence: 13 desktop renders in `docs/ux/reviews/P3-14/` and `HomeTrendingSounds.kt`. Desktop renders are not emulator screenshots: motion, TalkBack and real-device behavior are checked at phase-end QA.

## Verdict: Pass with polish
No must-fixes that block the ticket. Polish item 1 is a visible defect (the spec was my error); fix it before phase-end QA.

## What passes
- **Tokens only.** The section file uses `MemixSpacing`, `MemixColors`, `MemixShapes`, `MemixSize`, `MemixTheme.type`, `MemixMotion`. No raw hex, dp or font. No new token, no new icon.
- **Layout.** Top-aligned scrolling column, cards at the board's size side by side, heading row 48 dp with See all at the end, no dividers, no heart. At 360x640 three rows plus a peek of the fourth show (spec said three). At 360x800 all five fit with `space-6` under the last row.
- **Playing row.** Steps up to `surface`, pause disc, waveform in primary over the unplayed gray. Matches P3-02/03.
- **Loading.** Heading plus three static placeholders (40 dp disc, two bars), no shimmer. Under 300 ms nothing is drawn (`home-loading-under-300ms`).
- **Offline, cached.** Strip, saved rows normal, unsaved rows dimmed with "Not saved for offline", disc disabled, no Use block, names stay aligned (the slot stays empty). Matches P3-04.
- **Empty.** Section absent, cards at the top, nothing says content is missing.
- **Copy.** The six `home_sounds_*` keys in en, id, es, pt, hi are word for word the spec's text (checked in all five `strings.xml`). All fit their budgets; the longest, `home_sounds_offline` in es, is 78 of 90 characters. The es heading "Sonidos en tendencia" (20 of 26) fits beside See all at 360 dp with no wrap (`home-es`).
- **200% and 150% font.** `home-hi-200`: the cards stack (P3-11 note honored, also at 1.5x: `home-150-cards-stacked`), the heading and "सभी देखें" share a line at this width, names stop at two lines with an ellipsis, meta wraps in full (a CC-BY credit is never cut), nothing is clipped, Devanagari line height is generous. `FlowRow` guarantees See all drops under the heading when it doesn't fit.
- **TalkBack (by code).** The heading is a heading node; See all has the `_a11y` name that contains the visible words; the loading announcement is a polite status. Row semantics are the shared SoundRow's, already reviewed in P3-02/03/04. Verify on a device at QA: order, the row actions, focus return after the sheet and the picker.

## Polish (fix before phase-end QA)
1. **"Try again" has no visible shape (`home-error`).** A Secondary button is `surface-raised`; it sits inside a `surface-raised` message block, so it reads as indented plain text and looks misaligned with the message above. The spec said to use a raised block, so this is my error. **Fix (spec updated):** the message block (error and offline) is `surface`, so the raised Secondary button shows. Request to the principal mobile engineer: in `MessageBlock`, `MemixColors.surface` instead of `surfaceRaised`. The Secondary text and the block text keep over 12:1 on `surface`. The offline strip on the cached state stays `surface-raised`.
2. **Loading shows "See all".** The spec lists only the heading and three placeholders. Harmless (the Sounds tab works while loading), and I accept it as built. If the engineer prefers, hiding it matches the error and offline-nothing states, which have none. No change required.
3. **Region-change fade.** It fades 0 to 1 over 200 ms (a fade-through, not a true cross-fade) and 120 ms with reduce motion, the same helper as the Sounds tab, which I already accepted. Accepted. Check on a device that the playing preview stops and `region_changed_a11y` is spoken.
4. **Rotation (below).** Log it as a known difference.

## Your four points
1. **The Use block icon: no change needed.** `create` is the plus drawing. The design system lists `create` as "plus; also Add media and every add" and says the Use button reuses it (`DESIGN_SYSTEM.md`). The renders correctly show a plus. The word "create" in my spec was the icon's id, not a different icon. Keep it: the same Use block as the Sounds tab.
2. **Rotation ending a Home preview and closing the details sheet: acceptable.** Previews are 2 to 6 seconds and nothing is lost by hearing it again. The sheet's content is a reading view and one tap reopens it from the same row. Memix is a portrait phone app and there is no sign the manifest allows rotation as a feature, so this is rare. Polish only: if a cheap way exists to keep the details sheet open (its state is in the ViewModel), do it later; not for this ticket. Record it as a known difference from the Sounds tab in the phase-end QA notes.
3. **No heart on Home rows: confirmed.** Spec Layout 4. One tap on the name opens the details sheet, which has the heart. The renders show none.
4. **Offline with nothing cached, and online failure with nothing cached: confirmed.** Offline: heading (no See all) and one message block, no button (`home-offline-nothing`). Online failure: heading (no See all), the message and Secondary Try again (`home-error`), after polish item 1. The code chooses by the `online` flag, as the spec's table does.
