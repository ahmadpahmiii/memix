## Must-fix

**M1. The two spoken-only announcements are zero-size nodes** (spec Accessibility → Order: status messages polite, SC 4.1.3).
- `SoundsScreen.kt:149` (result count) is a childless `Box` with no size. `SoundsBlocks.kt:153` (`LoadingAnnouncement`) is `size(0.dp)`.
- Compose reports a node with empty bounds as not visible to the user, and TalkBack ignores live-region changes from such nodes (Assumption, from how the accessibility delegate builds node bounds; the builder's "unverified" is right).
- Fix: give both nodes real bounds, for example `Modifier.fillMaxWidth().height(<smallest stroke token>)`, no drawing. Or put the live region on a visible node.
- Owner check with TalkBack on: type "bruhh" and it says "1 result" once per settled query, not per keystroke. Cold first load says "Loading sounds".

**M2. Tabs are narrower than 48 dp** (spec Accessibility → Targets lists tabs; principle 4).
- `Tabs.kt:73` sets only `minHeight`. In the render, "Local" is about 33 dp wide and "Global" about 37 dp, with 20 dp dead gaps between them.
- Fix: `defaultMinSize(minWidth = MemixSize.touchTarget, minHeight = MemixSize.touchTarget)`. The underline then spans the 48 dp box, which is fine. If the five tabs no longer fit at 360 dp, the row scrolls, as designed.
- `Tabs` is shared, so check its other users still look right.

## Check by check

**Tokens and palette.** Pass. No `Color(0x`, no v1 values, no shadows, outlines or gradients. Depth is by value: the strip and the search field are `surface-raised`, the playing band is `surface`. The selected chip is white with `on-primary` text. Placeholders are static and have no shimmer.

**States that can exist now.** All rendered and match the spec: default, first load, load error, refresh-failed toast, footer loading and failed, offline, every empty state, search results, none, offline, offline none, searching, play-failed toast. Missing, and waiting on later tickets: Favorites with both sections, the unfavorited row, and offline dimmed rows (P3-04, P3-06).

**Chips.** Correct: "All" plus 8. The catalog has 10 sound categories and `TAB_CATEGORY_IDS` drops `sound_trending` and `sound_local` (spec Q2). They are 36 dp inside a 48 dp hit area, scroll sideways, hide on Favorites, My sounds and while a search has text, and reset to All on tab change. The chips render in English under the Spanish render only because the harness had no `es` names; the seed has them.

**Motion.**
- Tab fade: 200 ms, 120 ms with reduce-motion, matching the spec. It is a fade-in, not a true cross-fade: the old list leaves at once. That is acceptable. One risk: `snapTo(0f)` runs in a `LaunchedEffect`, which may show one frame of the new list at full alpha before it drops to 0. Record the tab switch on the owner's phone. If it flashes, derive the alpha from state so it starts at 0 in the same frame.
- Pull to refresh with no indicator: matches the spec ("Refreshing: nothing extra"). The 96 dp threshold and the offline no-op are right. It is a gesture only, with no accessible route. That is fine because refresh also runs on open and on Try again, but don't add anything that depends on it.

**Copy.** The spec wording is used. There are no exclamation marks, no emoji and sentence case. Strings in all five languages exist. Over budget, all of them wrapping strings, so nothing is cut: `es` search hint (33 of 32), offline strip (57 of 56), trending empty title (31 of 28), mine empty title (29 of 28), offline no-results body (82 of 80). Engineer to apply these `es` replacements in `values-es/strings.xml` (I can't edit string files):

- `hi` `sounds_empty_favorites_body` says "दिल दबाएं" (press the heart), which is not how Hindi speakers say it. Use "किसी साउंड के हार्ट पर टैप करें, वह यहाँ सेव रहेगा।".
- The Hindi tab "मेरी आवाज़ें" (from my own spec table) and `sounds_search_hint_mine` use "आवाज़ें" while the rest of the screen says "साउंड". Pick "साउंड" ("मेरे साउंड", "अपने साउंड खोजें"). P5-06 has the last word.
- The search hint is a literal translation in every language. The spec says to swap in sounds people there know; that is a P5-06 job.

**200% font.** Hindi and Spanish renders show no clipped control: tabs and chips scroll, names wrap, the placeholder cuts with an ellipsis (allowed), and the empty-state button stays reachable because the list scrolls. Two items:
- The empty-state headline is huge in Teko at 200%. In the Hindi no-results render, the title takes three lines and about a third of the screen. Still usable.
- The spec says the query wraps to two lines, then an ellipsis. `EmptyState` has no `maxLines`, so a long pasted query becomes a wall of Anton. Fix in P1 below.

**TalkBack (code reading only).** The order is correct: title as heading, search, Clear, tabs, chips, strip, rows, and each row's disc then text. Disc labels are "Play/Pause {name}". The strips are visible live regions. Chips are `Role.RadioButton` inside a `selectableGroup`, which is right for single-select; the spec said "toggle button", so I corrected the spec. Needs a device check: the search field's `contentDescription` must not hide the typed text, and the tabs must say "1 of 5".

**Layout.**
- Rows are 64 dp, there are no dividers, and the playing band is `surface`. Good.
- The tab strip no longer shows a cut-off fourth tab at 360 dp: all five fit in English. The spec's "three and a half" note was wrong; the scroll still works for the longer languages.

## Polish

1. **P1.** Cap the empty-state title at 3 lines with an ellipsis, or trim the query in `sounds_search_none_*_title` to about 24 characters plus "…" (full text stays spoken). `EmptyState` is shared, so add an optional `titleMaxLines`.
2. **P2.** Hide the category chips on the defensive Local-with-no-region state (`local-no-region.png`). They filter a list that can't exist.
3. **P3.** When a tab change resets the category to All, scroll the chip row back to the start (`rememberScrollState` survives the item).
4. **P4.** The Favorites empty state has a 48 dp gap between the heart and the headline, wider than headline to body. Tighten it to `space-4`.
5. **P5.** Placeholder rows are 4 dp left of the real rows' discs (16 dp against 20 dp) and their bars start 4 dp earlier. Match them so the swap doesn't jump. The real disc also sits 4 dp inside the title's 16 dp gutter; look at it again when the heart and Use block land.
6. **P6.** Focus return: "Clear search" button goes to the search field; "Show all" goes to the "All" chip. (Spec changed from "first row", which may not exist.)
7. **P7.** `PLACEHOLDER_DISC` 40 dp, `EMPTY_ICON_SIZE` 32 dp and `SEARCH_ICON_SIZE` 20 dp are raw dp in the feature. Documented and spec-matching, so tolerated; move them next to `SoundRow`'s own 40, 36 and 20 when P3-06 next touches the component. **No token change is needed now.**
8. **P8.** Update `docs/qa/` hand checks: the tab fade flash, the scroll position kept across a bottom-nav trip (the spec says it is kept; `rememberLazyListState` is saved only if navigation saves state), and the pull-to-refresh feel.
