# Design review · P0-04 Design system in Compose

**Verdict: Approved with polish** (7 Oct 2026). Reviewed from the screenshots in `docs/ux/reviews/P0-04/` (Pixel_9 emulator, API 35; iPhone 17 simulator, iOS 26.5) against `docs/ux/specs/P0-04-design-system.md`.

## Matches the spec
- Tokens: every color, type style, spacing, radius, stroke, size, shadow and motion value matches `design/tokens.json`; the audit finds no raw values outside `:core:designsystem` and no v1 colors.
- Type: Anton, Space Grotesk 400/500/700 and Space Mono render on both platforms from bundled files.
- One blue per context: primary button, Video meme card, sound controls; selection is white (chip, tab underline, slider thumb).
- Icons follow the grammar (flat caps, one solid core), read as one family next to the type, and are tinted per state.
- Sheet: scrim, grabber, `shadow-sheet`, bottom safe area respected on iOS; closes on close button, scrim, drag, system back and Escape.
- Toggle states read by the thumb (off gray 16, on dark 22 on blue), as specced.

## Polish (fixed in this PR unless noted)
1. Entry cards in a row must share one height when one description wraps. Fixed in the catalog; Home uses the same pattern in P0-05.
2. Scrolled content ran under the status bar. Fixed: safe-area padding sits outside the scroll area.
3. Focus rings were checked in code only: the emulator session had no hardware keyboard attached. **Not verified on screen**; QA checks it with a keyboard at the phase end.
4. 200% font scale not yet checked on the catalog; QA covers it in the phase pass.
