# Design review · P2-13 Add image layers

**Verdict: Approved** (28 Oct 2026, provisional, from 10 desktop renders and code). No must-fixes and no code changes asked. Two small spec updates came out of the builder's questions and are made in the spec. The feature is small and the build follows the spec: the tool, the panel button, the landing, the one-step edit, the strings in five languages.

Nothing was seen on a phone: the renders are desktop renders (`ImageComposeScene`, generated pictures), so the picker, the import sheet, the 120 ms fade, the announcement, TalkBack focus and undo on a device are on the QA list at the end. Reviewed against `docs/ux/specs/P2-13-image-layers.md`, the P2-01 and P2-03 specs and the tokens.

Read:
- **Renders:** all 10 in `docs/ux/reviews/P2-13/` plus the README.
- **Code:** `PhotoEditorScreen.kt` (main bar, `addPhotoTool`), `LayersPanel.kt` (the first list item, the scroll rule), `PhotoEditorViewModel.kt` (`landLayer`, `requestPick`, `showLanding`), `Button.kt` (default variant).
- **Strings:** `tool_add_photo`, `a11y_layer_added`, `edit_add_photo` in en, id, es, pt, hi.
- **Token audit:** no raw color, dp or font in the new code; the button is the design system's `Button` (Secondary, the default) with the `create` icon.

## Matches the spec
- **Main bar** (`30-main-bar-add-photo`): **Add photo** (plus icon) then **Layers**, with nothing selected, `text-secondary`, labels under the icons. On an empty canvas (`30-empty-canvas-main-bar`) both tools are still there, so Add photo is the way out.
- **Layers panel** (`30-layers-panel-add-photo-button`, `-360x640`): a full-width Secondary button with the plus icon and the label, 48 dp tall, as the **first item of the list**, above the front row, whether or not a layer is selected; `space-1` from the first row; it scrolls with the list.
- **Landing** (`30-landed-9x16-on-4x3-selected`): a 9:16 photo on a 4:3 canvas is **fitted inside** (its height equals the canvas's, the background shows beside it), centered, scale 1, no turn, **on top of the stack**, **selected** with the two-tone frame and handle and the selected-layer bar. A same-shape photo covers the frame (`30-landed-same-shape-covers-selected`); the frame and handle still show it is there, and the frame sits outside the canvas edge as P2-01 says. With the Layers panel open (`30-landed-with-layers-panel-open`) the new row is first, selected (white ring), with its thumbnail fitted inside.
- **Code, landing:** `landLayer` commits one step (`PhotoEdit.ADD_PHOTO`, tool `add_photo`, one `tool_use`), then selects the new layer; a nothing-picked, cancelled or failed pick commits nothing (`Declined`). `requestPick` ignores taps while a pick or the import sheet is up (P1-02). The announcement is spoken only ("Photo added in front"), polite, no toast shown, as specified. The edit name `edit_add_photo` gives "Undo: Add photo".
- **The panel's button is never a reorder target** (a keyed item outside the rows) and the Opacity item (tight panels) sits before it, as the spec's TalkBack order says (Move buttons, Opacity row, then Add photo, then the rows).
- **200% font:** the tool's label wraps to two lines in Hindi and Spanish (`30-hindi-200-main-bar`, `30-spanish-200-main-bar`) with the icons still aligned across both tools (the two-line room rule); the panel's button label stays on one line in Hindi (`30-hindi-200-layers-panel`) with the first row whole beneath it.
- **Copy:** the five-language strings are within budget and keep the same word for "photo" as the Photo meme row; the spoken line reads right in each language ("in front" is "delante", "na frente", "di depan", "सबसे ऊपर").

## Answers to the builder's questions
**1. Should the empty-canvas card now mention Add photo? No, not in this ticket.** The card's wording (`photo_empty_body`: "Tap Undo to bring your layer back, or close this and start a new photo meme.") is still true. It is rewritten by P2-03, the next build, which names **Text** and **Add photo** in one pass (`photo_empty_body` and `photo_empty_body_blank`, five languages; P2-03 spec → The empty-canvas card), and the card stays while the canvas is plain (P2-02 starts every photo meme plain; it gives way only while a format with its own hints is active). Changing five translations now to change them again one ticket later is churn. The empty canvas already has the answer in plain sight: Add photo is the first tool of the bar (`30-empty-canvas-main-bar`).

**2. The Layers list scrolls to the Add photo button with the new row beneath it after a landing: right.** My spec said the new row "scrolled into view"; scrolling to the button keeps both visible, which is better: the user sees what landed and the button for the next photo, and the list shows from its top, which is where a new layer lives. The rule as built is also right for every other case: a selected **front** row shows with the button above it, any other selected row scrolls to the top, and tight panels shift every index by one for the Opacity item (`itemsAbove`). One consequence in a tight panel: the Opacity item is scrolled off after a landing; the selected-layer bar's Opacity tool is one tap away. I updated the spec (Entry and exit → "If the Layers panel is open").

**3. The bar's Add photo icon is `create`: right.** The spec chose it (the plus, the same icon as the video editor's Add media and every "add"), the label carries the meaning, and the icon set has no photo-with-plus glyph worth drawing for one tool. The tool and the panel button use the same icon, so the two entries read as one action.

## Polish
None required. One thing to watch on the device (QA 4 below): the Add photo button has the same `surface-raised` fill as the rows. The centered plus-and-label layout and the missing thumbnail, lock and eye tell it apart in the renders; if testers take it for a layer, the fix is the Quiet button variant (no fill, `primary`-free `text` label), still one component.

## Needs a device (QA list)
1. **The pick:** Add photo from the main bar and from the panel: the picker (images only, one item), the 300 ms rule, the "Adding your photo" sheet, "Not enough space", "None went in", cancelled and nothing picked (no layer, no step, no event). Two taps from the bar: Add photo, a photo.
2. **After landing:** the 120 ms fade-in of the picture and frame (instant with reduce motion); "Photo added in front" is announced and takes no focus; the bar switches to the selected-layer bar; where TalkBack's focus lands (the same open check as P2-01's P4; expected: the first tool of the new bar).
3. **Undo and redo:** one Undo removes the layer and shows "Undo: Add photo"; Redo restores it in the same place; the file stays while Undo can use it; `tool_use add_photo` fires once.
4. **The Layers panel after a landing,** at 360 × 800 and 360 × 640 (tight: the Opacity item above the button) and at 200% Hindi: the button and the new row both in view; the rule for a non-front selected row; a row dragged near the button never drops onto it; the button looks different enough from a row.
5. **A 12 MP photo added to `photo-layers-10`:** decoded at the drawn size, the next drag under 5% janky frames; LeakCanary, 5 cycles of add, drag, undo.
6. **Reopen:** kill after landing, reopen from Drafts: the layer, its place and its picture are there; duplicate the draft and delete the original: the added photo still shows.
7. **Blank canvas (from P2-03):** Add photo on an empty canvas lands fitted inside the 1:1 canvas and the empty card goes.
