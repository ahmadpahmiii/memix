## Your decisions
1. **Not-enough-space notice at 360 × 640: the spec's estimate was wrong, so I corrected the spec.** The sheet already uses about 88% of the window without a notice, and a two-line notice with its Free up space button adds about 75 dp. I don't want to squeeze the controls to hide that. The rule is now: no scroll without a notice; with a notice (or at 200% font) the middle scrolls and **the title and the Copy and Save buttons stay pinned**, and the middle scrolls to the notice. The builder's scroll-to-notice is what the spec wants (`03-sheet-no-space`, `05-sheet-failed-size`).
2. **`Button` with `enabled`, used by "Saving…": keep it, renamed and restyled.** It is a progress state on the button the user just tapped, not a disabled variant, so it doesn't conflict with the P2-07 rule (blocked controls keep their look and explain on tap). Two changes: call it **busy**, and the label is `text-secondary`, not `text-muted` (`text-muted` is under 4.5:1 on `surface-raised`, and "Saving…" is the only status text the user has). The neighbour (Copy) takes the same look while the other runs. Added to `design/system/components/Button/README.md` and `docs/DESIGN_SYSTEM.md`. No token change. Kotlin: rename the state (or keep `enabled` internally) and use `MemixTheme.colors.textSecondary` for the label.
3. **Format, Size and the slider ignore taps while saving, undimmed: accept.** The wait is two to five seconds, Close cancels, and a dimming token for a transient state isn't worth a token. Mark them disabled for TalkBack so the screen reader says why nothing changes. Spec amended.
4. **Export during Draw mode silently ignored: not acceptable; the fix is to act.** Draw mode is a mode, and every stroke is already committed, so tapping Export should end Draw mode (as Done does) and open the sheet, like text editing commits first. Any other open panel closes first the same way. Spec amended (Entry).

## Polish
- **P1. Draw mode and Export (above).** Build the rule: Export ends Draw mode, then opens the sheet.
- **P2. The main bar's labels collide at 200% in Spanish** (`07-top-bar-spanish-200`: "Formatos Texto Stickers Añadir" run together, "foto" wraps under). Not this ticket's code, but visible here: each tool in the main bar should grow to its label's width plus `space-2` (the ToolBar rule), never share a fixed width. Fix in the shell, note for QA at 200%.
- **P3. The Export button when the sheet is open** is dimmed behind the scrim: correct; nothing to do. The pill sits left of center on a 4:3 canvas (clamped by Undo and Redo), as specified.
- **P4. Estimate honesty.** "About 1.0 MB" for a 1440 × 1080 JPG at 90 is plausible; QA logs estimate and actual per export (the spec) and the table is retuned from the numbers.
- **P5. The Exported picture** is shown at about 60% of the screen at 360 × 800 with empty bands above and below: fine. At 200% Hindi and Spanish it keeps at least 40% of the height (`09-*-200`): confirm Share, Make another and Done are reachable by scrolling.
