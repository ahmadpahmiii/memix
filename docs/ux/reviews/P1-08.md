## Must fix before end-of-phase QA
**M1. Move here's spoken name isn't its visible label.**
- **Where:** `ToolBar.kt`: `ToolBarItem`'s `contentDescription` parameter (`:77`) and `ToolButton` (`:120`, `:135-139`); `EditorToolBar.kt:197`.
- **The problem:** the tool shows "Move here", but its accessible name is "Move to playhead" (semantics.txt, scenes 52, 76, 79, 83), in every language (hi shows "यहां ले जाएं" and speaks "प्लेहेड पर ले जाएं"). The name doesn't contain the label, which fails WCAG 2.2 SC 2.5.3 Label in Name, Level A. A Voice Access user who says "Tap Move here" gets no match, and a sighted TalkBack user hears words that aren't on screen. My spec asked for exactly this, so it's my error, not the build's.
- **Fix:**
  - In `ToolBarItem`, replace `contentDescription: String?` with `clickLabel: String?`: extra context that TalkBack reads after the name as "Double-tap to …".
  - In `ToolButton`, always set `contentDescription = tool.label`, and inside `clearAndSetSemantics` use `onClick(label = tool.clickLabel) { tool.onClick(); true }`. TalkBack then says "Move here, button, double-tap to Move to playhead".
  - In `EditorToolBar.kt:197`, pass `clickLabel = moveHereSpoken`. Update `ToolBarItem`'s KDoc ("Move here is spoken 'Move to playhead'").
  - The item action in `TimelineSemantics.kt:365-377` keeps "Move to playhead" as its name: a custom action has no visible label, so that's right as built.
  - No new string, no new token.
- **Spec line:** Accessibility → Tool bar: "every tool's visible label is its accessible name (WCAG 2.2 SC 2.5.3), except Move here, which is spoken 'Move to playhead'". Now there's no exception; the ToolBar README says how to add context.

**M2. The Volume panel hides the timeline and tool bar from the eye, but not from TalkBack or the keyboard.**
- **Where:** `VideoEditorScreen.kt:180-190` (the `timeline` and `tools` slots of `EditorLayout`).
- **The problem:** ToolPanel draws over both regions and takes their touches, but they stay in the accessibility tree and the focus order. Scene 79's dump (panel open) lists every timeline item, both of Boing's handles and all five sound tools before pane "Volume". A TalkBack user who swipes back from the panel's title lands on tools nobody can see, and a double-tap runs them: Delete removes the sound, and the panel then closes because its item is gone. Shift+Tab from the title focuses the hidden Duplicate. That fails WCAG 2.2 SC 2.4.11 Focus Not Obscured (Minimum), AA. ToolPanel is the pattern for P1-09 Volume on clips, P1-10 Style and Position and P1-11 Canvas, so it's worth fixing once, now.
- **Fix:**
  - `val panelOpen = state.volumePanel != null` (later tickets: any panel open).
  - Wrap both slots: `timeline = { Box(Modifier.coveredByPanel(panelOpen), propagateMinConstraints = true) { Timeline(…) } }`, and the same around `ToolBarRegion(…)`.
  - `private fun Modifier.coveredByPanel(covered: Boolean) = if (!covered) this else clearAndSetSemantics { }.focusProperties { onEnter = { cancelFocusChange() } }.focusGroup()`. It's the same focus API the Sheet already uses with `onExit`.
  - The stage and the transport row stay reachable, so Play, Undo and Redo keep working while the panel is open, as the spec wants.
  - Check: with the panel open, the dump goes from "Redo" straight to pane "Volume".
  - No new string, no new token.
- **Spec line:** ToolPanel README → "It takes the place of the timeline and the tool bar"; P1-06 → Volume panel: "The panel covers exactly the timeline and tool bar region". Both now spell it out: what the panel covers is out of the accessibility tree and keyboard focus.

**M3. At 200% in Spanish and Portuguese, the pill's label is cut (computed; check first).**
- **Where:** `AddMemeSoundRow.kt:64-86` (`AddMemeSoundPill`, `maxLines = 1` at `:85`) and `LaneLayout.kt:49` (`addRowHeightPx`, which allows one label line).
- **The problem:** the label is one line, and the pill can't be wider than the timeline. Measured from render 70, "Add a meme sound" takes 119 dp at 100% (about 7.4 dp a character in `label`). At 200%, es "Añadir sonido de meme" and pt "Adicionar som de meme" (21 characters) need about 311 dp of text, plus the 24 dp plus, the 4 dp gap and 32 dp of side padding: about 372 dp, on a 360 dp timeline. The end is clipped ("…de me") on the main sound entry, in two of five languages. English (about 300 dp), Indonesian (about 313 dp) and Hindi (about 200 dp, render 71) fit. The renders have Hindi only, so this is computed, not seen. It fails WCAG 2.2 SC 1.4.4 and P1-05's "never cut".
- **Fix:**
  - First render the add row in es and pt at 200% (360 dp). If the label is whole, close M3 with those renders.
  - If it's cut:
    - Cap the pill at the timeline width minus `space-4` on each side.
    - Let the label take up to two lines, centered (`maxLines = 2`, `TextAlign.Center`).
    - Make `addRowHeightPx` count the lines: measure the label with the timeline's `TextMeasurer` at the cap minus the plus, the gap and the side padding, then use `max(touchTarget, lines × labelLineHeight + 4 × space1)`. LaneLayout is already built per text size, so pass the line count in next to `labelLineHeightPx`.
  - No new string, no new token.
- **Spec line:** P1-05 → "Add a meme sound" row (new "Long labels" rule) and Accessibility → 200% ("The pill grows").

## Polish
**P1. The playing row gets a band the sheet can show** (decision 1).
- **Where:** `SoundRow.kt:63`; `MemeSoundsSheet.kt:50-59`.
- **Change:** give SoundRow an `onSurface: Boolean = false` parameter (or an equivalent). The playing band is `surface-raised` when it's true and `surface` otherwise. The Meme sounds sheet passes `true`.
- **Why:** in render 77, Boing is playing, and only its disc shows it, because a `surface` band on a `surface` sheet is invisible. The filled blue disc still marks it, so this is polish, not a must-fix.

**P2. The pill sits out the lane slide** (decision 2).
- **Where:** `AddMemeSoundRow.kt:70` and `EditMotion`.
- **Change:** expose whether lanes are sliding (for example `laneSlide.isRunning`). While they are, don't draw the pill; when the slide ends, fade it in over `duration-press`. With reduce motion nothing slides, so nothing changes.
- **Why:** render 84-mid shows the pill covering the lower half of the new "Boing" clip at the peak of its bonk. That's the one moment the eye is on the new sound.

**P3. The pill gets a pressed state and its full target.**
- **Where:** `AddMemeSoundRow.kt:66-80`.
- **Change:**
  - Move `.clickable(…)` and `.semantics { traversalIndex = … }` before `.padding(vertical = MemixSpacing.space1)`. The target is then the whole row height (48 dp or more), while the drawn pill stays 40 dp. Keep `focusRing` after the padding, so the ring hugs the drawn pill.
  - Replace `.background(MemixColors.primarySubtle)` with a fill from `pressedColor(interactionSource, MemixColors.primarySubtle, MemixColors.surfaceRaised)`, drawn over the `canvas` base.
- **Why:** now a press shows nothing (`indication = null` and no fill change), and the target is 40 dp tall, under `touch-target`. `surface-raised` is what a sound's play disc already presses to; `primary` on it is 5.9:1. DESIGN_SYSTEM → States now names this rule for every `primary-subtle` fill.

**P4. Focus comes back after the panel and the sheet close.**
- **Where:** `EditorToolBar.kt` (`ToolBarRegion`, `rememberClipTools`), `AddMemeSoundRow.kt`.
- **Change:**
  - Volume panel closed (Done, back, Escape): focus goes to the Volume tool. Give that `ToolBarItem` a `FocusRequester` (the parameter exists) and reuse `FocusOnce` when `volumePanel` goes from open to closed with the sound still selected.
  - Sheet closed by adding: focus goes to the new sound's Volume tool once the sound tool bar has cross-faded in. The announcement still plays.
  - Sheet closed without adding: focus goes back to the opener, the Meme sounds tool or the pill (the pill needs its own `FocusRequester`).
  - Check on the phone that TalkBack's focus follows, as for P1-06 P6.
- **Why:** each close now drops focus, because none of these paths request it. Focus after a surface swap is the item I see missed most often (P1-02, P1-04, P1-06). My spec asked for focus on "the new sound on the timeline", but timeline items aren't focusable (P1-05 → Keyboard), so that line is corrected.

**P5. Keyboard and TalkBack steps land on the step grid.**
- **Where:** `Slider.kt:94-104` (keys) and `:109-113` (`setProgress`).
- **Change:**
  - Up or Right goes to the next multiple of `step` above the current value, and Down or Left to the next below, clamped to the range. Use a small epsilon so that 100% goes to 110%, not 100%.
  - For `setProgress`, pick the next multiple above or below by whether TalkBack's target is above or below the current value.
  - From 147%: up is 150%, down is 140%.
- **Why:** the double-tap reset is pointer-only, and from a dragged 147% the 10% steps go 137, 127 … 97, never 100. The spec says 100% must be easy to find again, and the snap only helps pointers (WCAG 2.2 SC 2.1.1 Keyboard). It's a component change, so every later slider gets it.

**P6. A lane band previews the new lane.**
- **Where:** `TimelinePainter.kt:161-164`.
- **Change:** when `move.laneTarget == LaneTarget.NewLane`, draw `drawBand(move.row, zeroX, endX)` (if the length is over 0) before the carried item.
- **Why:** in render 72 ("over add row"), the sound floats in an empty row with nothing saying a lane will appear there. A `surface` band from 0:00 to the end, like every other lane, shows the result before the drop (NN/g heuristic 1, visibility of system status).

**P7. Copy** (machine drafts; P5-06 has the final say).
- **hi `explain_sound_unreadable`:** "यह साउंड नहीं चल रहा।" means "this sound isn't playing", which is a status, not a promise. Change it to "यह साउंड नहीं चलेगा। कोई और आज़माएं।" ("won't play").
- **For the backend engineer and P5-06:**
  - The manifest's Hindi title for Boing, "बोइंग", is how Hindi writes the aircraft maker Boeing. Ask a native speaker for an onomatopoeia, or use "उछाल" (bounce).
  - es "Rayón de disco": check against the term Latin American editing apps use for "record scratch".

## Follow-ups (not blocking P1-08)
**F1. Sheets leave the screen behind them reachable by TalkBack** (every sheet, since P0). Scenes 77 and 78 list the editor's tracks and tools before pane "Meme sounds". Keyboard focus is already trapped (the Sheet's `onExit`); TalkBack isn't. The fix is M2's treatment at the screen root while a sheet is open. For the PM to schedule for the Sheet component: in the P1 fix pass if there's room, otherwise P2.

**F2. "That sound won't play. Try another one." when storage is full** (the engineer's known limit). Another sound fails the same way, so the message gives the wrong next step (principle 5). The library already reports StorageFull. Route it to P1-02's "Not enough space" sheet in a later ticket. It's rare: one write of 450 KB at most.

**F3. Raising a sound from 0% isn't heard until release.** A 0% sound leaves the composition, so live feedback is missing in exactly the direction the user is searching. It's an engine follow-up and acceptable for P1.

## Decisions on the engineer's notes
1. **A playing SoundRow on the sheet gets a `surface-raised` band** (P1).
   - **The rule:** a playing row sits one value step above its container: `surface` on `canvas` (the Sounds tab, Home), `surface-raised` on `surface` (any sheet). "Depth by value steps" is the system's own rule, and the board's playing row was exactly that step on `canvas`.
   - **Why not `primary-subtle`:** the tokens and DESIGN_SYSTEM did say it backs "the playing sound row", but the Sounds board, the SoundRow README and the P0 build all use a value step. A whole blue-tinted row would put a large saturated area next to the blue disc and add block ("saturated color only in small areas"). The doc drift is fixed in both token files, DESIGN_SYSTEM and the system README; no value changed.
   - **Contrast on the band:** `text` 12.4:1, `text-secondary` 5.7:1, the `primary` disc and add block 5.9:1.
2. **The pill sits out the lane slide and fades in at its new place** (P2).
   - **Rejected: drawing the pill under the lanes during the slide.** It must stay above the playhead line, and a z-order flip mid-animation is noise.
   - **Rejected: letting the add row jump while the rest slides.** Then the sliding Audio lane passes under the pill instead.
   - The pill is a fixed marker, not content, so it's fine for it to be absent for 200 ms while the new sound bonks. It reappears just under the new sound, where the next one would go.
3. **Documented as built, with this review's changes:**
   - ToolPanel README: covered region out of the accessibility tree and focus, the two Dones, an active look never seen in the video editor.
   - Sheet README: the half-height opening, focus on close.
   - SoundRow README: optional heart, two-line title, meta never cut, the playing band, sizes and spoken names.
   - Slider README: snapping, commit, grid steps.
   - ToolBar README: the sound tools; the label is the name, and context goes in the click label.
   - Timeline README: the pill's pressed state, wrapping, the slide and the new-lane band.
   - DESIGN_SYSTEM: Iconography now lists the 24-icon set; Compose notes add the ToolPanel, half-height sheet, SoundRow band and Slider snapping notes.
   - **The two icons pass the grammar:** 24 grid inside 2–22, 2 dp butt-capped mitred strokes, one solid core, one tint.
     - `volume`: two stroked bars and a solid 16 dp block with 1 dp corners, at even 3.5 dp gaps. It reads as "level", distinct from `sounds` (the speaker cone). It also resembles signal bars, but it always sits over its label.
     - `move_here`: a shaft with a solid arrowhead into a full-height bar, 2.5 dp apart. The bar is the playhead.
     - Both read at 24 dp in render 76 and in Hindi at 200% (render 80).
