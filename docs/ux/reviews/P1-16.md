## Polish
**P1. Focus comes back after a sheet, also from a sheet's button** (keyboard; computed, check first).
- **Where:** `Sheet.kt` → `SheetSurface`, `.focusProperties { onExit = { cancelFocusChange() } }`; `VideoEditorScreen.kt` → `ReturnFocus`.
- **The problem:**
  - The sheet traps focus for as long as it's composed, and that includes its 200 ms exit.
  - `ReturnFocus` asks for focus one frame after the pick ends, so mid-exit. If keyboard focus is on a button inside the import sheet (Cancel, or Continue on "1 of 2 added"), leaving it means the sheet's `onExit` runs, and that cancels the request.
  - When the sheet then leaves, focus drops to nothing. A keyboard user who tabbed to Cancel while copying lands nowhere.
  - The Meme sounds sheet's return to its opener (P1-08 P4, which you're building now) goes through the same trap.
  - When the sheet itself holds focus (its default), Compose doesn't consult its `onExit`, so the plain case works.
- **Fix:**
  - Trap only while the sheet is shown. Pass `visible` into `SheetSurface` and write `onExit = { if (visible) cancelFocusChange() }`. This is a component change, so every sheet gets it.
  - Keep `ReturnFocus`'s one frame.
  - **Check with a keyboard:** Add media, pick a long video, Tab to Cancel and let the copy finish. The ring lands on Add media. Do the same for Continue after a damaged file, and for the Meme sounds sheet's ×.
- **Spec line:** P1-06 → Accessibility → "Add media and Replace" (now says the focus moves even when it was on a sheet button). Sheet README → Focus.

**P2. The tile steps aside for any selected clip whose end handle reaches it** (answer 1 below).
- **Where:** `Timeline.kt`, the `lastClipSelected` condition before `AddMediaTile(…)`.
- **The problem:** at zoomed-out scales, a last clip narrower than about 44 dp leaves the tile under the end handle's target of the clip before it, when that clip is selected. Example: 1 s at the default zoom is 40 dp; a 5 s clip at "Show whole video" on a minute-long project is narrower still. Then the same dead tile shows, just less often.
- **Fix:**
  - Hide the tile while the selected main clip ends less than `touch-target` before the end of the video. For the last clip that's always true.
  - Read the zoom inside `derivedStateOf { … }`, so only a flip of the result recomposes, not every pinch frame.
- **Spec line:** P1-05 → Trailing area → Hidden (the rule as written now).

**P3. The tile's press takes 120 ms like every press.**
- **Where:** `AddMediaTile.kt`, `.background(if (pressed) MemixColors.hairline else MemixColors.surfaceRaised)`.
- **Fix:** `pressedColor(interactionSource, MemixColors.surfaceRaised, MemixColors.hairline)`, the helper ToolBar and the pill use. Now the swap is instant; DESIGN_SYSTEM → Motion sets 120 ms for presses.
- **Spec line:** P1-05 → Trailing area → Look ("Pressed: `hairline`, 120 ms").

**P4. The replace icon gets air between its arrowheads and the clip** (answer 2 below).
- **Where:** `ic_replace.xml`, the first path (the core).
- **The problem:** each arrowhead's inner edge passes 0.7 px from the core's corner (about 1.0 px after the 1 px rounding). That's the tightest gap in the set; `move_here` has 2.5 px and `volume` 3.5 px. At 2× density, common on the phones in our markets, anti-aliasing fills the gap, so the arrowheads read as touching the clip and the cycle turns into a blob.
- **Fix:** make the core 7 × 4 instead of 8 × 5, still centered, so the gap opens to 1.4 px (about 1.7 px after rounding):
  `M9.5,10 H14.5 A1,1 0 0 1 15.5,11 V13 A1,1 0 0 1 14.5,14 H9.5 A1,1 0 0 1 8.5,13 V11 A1,1 0 0 1 9.5,10 Z`
  The arcs and arrowheads stay as drawn.
- **Spec line:** P1-06 → request 1 (`replace`), DESIGN_SYSTEM → Iconography.

**P5. The bonk grows long clips by a few dp, not by 12% of their width.**
- **Where:** `TimelinePainter.kt` → `drawLandingItem`, `scale(scale, scale, …)`.
- **The problem:** the bonk scales an item evenly around its center, which was made for sounds and stickers. A main clip is wide:
  - In render 94c (peak), the new 3 s photo swells about 7 dp at each end. It covers the `space-1` gaps and overlaps both neighbors.
  - A 10 s video (400 dp) would swell 24 dp at each end, sweeping over the clip before it, left of the playhead.
  - P1-16 lands whole videos in every pick, so this becomes the common case. It reads as a lurch, not a bonk.
- **Fix:**
  - Scale the height by `scale`. Grow the width by the same number of pixels: `scaleX = 1 + (scale − 1) × itemHeightPx / widthPx`, at most `scale`.
  - A roughly square item (a 1 s sound) looks as before; a long clip swells 2.4 dp at each end.
  - Duplicate and Detach audio get the same, since they share this function.
- **Spec line:** DESIGN_SYSTEM → Motion (the bonk); `duration-bonk` usage in both token files; P1-06 → Motion.

**P6. The empty draft's message uses the stage's width** (Hindi at 200%).
- **Where:** `VideoEditorScreen.kt` → `FrameMessage`, `StageContent.EMPTY -> CanvasFrame(aspectRatio) { EmptyDraft() }`.
- **The problem:**
  - In render 97, the message sits inside the 9:16 frame, about 155 dp of text width. The Hindi title takes three lines and the body four, and the body's last line is cut at the stage's bottom edge. It scrolls, but nothing shows that it does.
  - With P1-16, that body is the instruction ("Add a video or photo to start").
- **Fix:** draw `EmptyDraft()` centered on the whole stage (`Box(Modifier.fillMaxSize().padding(MemixSpacing.space2))`), not in the canvas frame. The frame has no picture and the canvas is black like the stage, so nothing visible changes except the width, which doubles. The preview error keeps its frame (its `surface` box is the frame).
- **Spec line:** P1-04 → States → Empty project (now says "centered on the stage").
- It's a defensive state P1-02 never creates, hence polish.

## Answers to the engineer's questions
1. **Hiding the tile while the last clip is selected: confirmed, and extended (P2).**
   - **Measured on render 86:** the end handle is drawn from the clip's end to about 11 dp past it. Its 48 dp target runs from the end to 48 dp past it. The tile's 40 dp body, at 8 to 48 dp past the end, sits entirely inside that target, and the handle overlaps the tile by 3 dp. A visible tile there would look tappable and do nothing, and the handle would cover its edge.
   - **Rejected: shifting the tile right by the handle's target** (52 to 92 dp past the end while selected).
     - A target that jumps sideways right after the tap that selected the clip is a classic mis-tap trap (layout shift).
     - The 37 dp gap breaks the tile's tie to the end of the video in exactly the state where it shows.
     - A position that depends on selection adds a rule for one state.
   - **Rejected: shrinking the handle's target to leave room.** It breaks `touch-target` on the most used trim, cutting the boring end of the last clip.
   - **What hiding costs:** with the last clip selected, adding at the end takes one more tap (deselect, then the tile, or the Add media tool). That's no dead end: the clip tool bar's back button and any tap on empty timeline bring the tile back.
   - **It matches the rule already there:** the tile steps aside whenever the end of the video is being worked on (trim, move, reorder).
   - The tile disappears at once while the handles fade in over 120 ms. Accepted: the eye is on the clip.
2. **The replace icon passes the grammar, with one fix (P4).**
   - Inside 3–21 on the 24 grid (padding 2), 2 px strokes with butt caps and mitred joins, one solid core (the clip, 1 px corners), one tint.
   - It's exactly 180° symmetric, so it reads as a cycle.
   - It can't be confused with `reorder` (one arc over two outlined clips; render 90 has them side by side) or with `undo`/`redo` (one hooked arrow).
   - Its solid arrowheads follow the set's convention (`undo`, `redo`, `reorder`, `move_here`). DESIGN_SYSTEM now says so: arrowheads are always solid and don't count as the core.
   - The only issue is the 0.7 px gap.
