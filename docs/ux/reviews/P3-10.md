# Design review · P3-10 Report a sound

Reviewed 12 Nov 2026 against `docs/ux/specs/P3-10-report-a-sound.md` (+ P3-03, P3-05). Evidence: the 16 desktop renders in `docs/ux/reviews/P3-10/` (no IME, no TalkBack, no device), the handoff, `SoundReportPane.kt`, `SoundReportController.kt`, `ic_flag.xml`, the 18 strings x5. Everything about TalkBack below is read from code and spec, not heard; QA must confirm it on the emulator.

## Verdict: Pass with polish

No must-fixes. The pane is faithful to the spec, tokens-only, and all six builder deviations are acceptable. Five polish items (P1-P5) should land before the phase-end QA; none blocks the ticket commit.

## The builder's six questions

1. **Back to the details after a report in the picker: confirmed (spec amended).** In the picker, people are auditioning sounds for a meme; closing the whole picker would throw away their list, search and place, and the details still carry "Use in a video meme". The toast and the Confirm haptic still fire, and "Reported. Thank you." replaces the Report row. Sounds tab keeps the spec (sheet closes, back to the list). Condition: see P2 (focus).
2. **"Sending…" at once: confirmed.** The 300 ms delay would leave a window where a second tap on a live-looking Send does nothing; the busy look (`surface-raised` + `text-secondary`, 5.7:1) is the DS rule for a started action. A fast success shows "Sending…" for a few frames and then the sheet closes; acceptable. Add the polite announcement (P1).
3. **Reason rows `surface-raised`, pressed `hairline`: confirmed.** The spec line 23 contradicted itself ("no fill" and "surface-raised"); the render is right: on `surface` the rows read as touch targets, and selection is the white radio, not the fill (DS: `surface-raised` never marks selection). Contrast: unselected ring `text-secondary` on `surface-raised` 5.7:1, on pressed `hairline` 4.7:1 (both >= 3:1); selected white on `surface-raised` 14:1; label `text` fine. Note: the spec's "5.7:1 on surface" was really the `surface-raised` figure (on `surface` it is 7.0:1); corrected in the spec.
4. **No "Couldn't send" label: confirmed.** `sound_report_failed` already begins "Couldn't send your report", and the offline line starts "You're offline". Words, not color, carry the meaning (SC 1.4.1). Spec amended; the label would only repeat itself.
5. **Report row is a private `text-secondary` row: confirmed.** Right call: the one blue action in the details is "Use in a video meme"; Report must be reachable (48 dp, 7.0:1 on `surface`) but not compete. Pressed turns `text`. The centered flag + label reads well in en and hi-200 (render `details-hi-200`).
6. **`flag` icon: approved.** `ic_flag.xml` is a 2 px butt-capped pole (x 4-6, y 3-21) with a solid 10 x 7 pennant (triangle, tip at 16, 6.5) joined at the pole's top: exactly the DESIGN_SYSTEM line 165 description, one solid core, one tint, 24 dp grid. It reads as a flag at 24 dp in `details-with-report`. No change.

## Checklist

**Tokens only: pass.** All colors, spacing, shapes, sizes, type are `MemixColors/Spacing/Shapes/Size/Stroke/Theme.type`. Only layout constants remain (`RADIO_DOT_FRACTION` 0.4 glyph math, `NOTE_MIN_LINES`, `COUNTER_FROM`). No v1 values, no outlines, no shadows. Radio ring uses `strokeSelection` (2 px), correct. No token changes.

**States (renders vs spec table): pass.**
- Default, chosen with 417/480 note, pick-reason line, offline, failed, sending, reported, removed sound (no Report row), toast: all present and correct. One blue button per pane. Counter shows from 400, `text-muted` 5.7:1 on `surface`.
- Sending: whole form disabled-looking; the note keeps its text.
- Observed only in code: a second tap on Send with no reason changes nothing (see P5).

**Copy and budgets: pass.** All 18 strings are in the five languages and inside their budgets (counted by hand; tightest: id `reason_offensive` 32/32, id `thanks` 43/44, es `back_a11y` 32/32, id `info` 58/72). Tone is calm and verb-first, "you/your", no blame. Notes: (a) es uses "reportar/reporte" (Mexico, the es launch market, uses it; Spain would say "denunciar"); keep. (b) pt "denúncia" fits Brazilian usage. (c) hi uses "साउंड" and Western digits in the counter, as specced. (d) id uses informal "kamu/-mu", consistent with the app. Machine drafts are allowed until P5; hi and id need a native read then.

**200% font: pass.** `report-hi-200` and `-tall`: title wraps to two lines with the arrow and close centered, reasons wrap ("आपत्तिजनक या नफ़रत भरा" gets two lines in a row that grows), Devanagari is not clipped, Send stays pinned and 48 dp+. With the keyboard open the scrolling region at 200% is small (1.5 rows in `report-hi-200`); that is the specced long-content behavior, but QA must confirm on a real IME that the note field scrolls into view above Send (the IME is not in any render).

**TalkBack (code read):**
- Reasons: `selectable(role = RadioButton)` inside `selectableGroup` gives "radio button, not selected / selected" and the group label is the prompt; the visible prompt Text is also focusable, so the prompt is read twice (once as text, once as group name). Harmless.
- Note field: `contentDescription` on a text field can replace the typed text in TalkBack on some Android versions. QA: type, swipe to the field, confirm the typed text is read; if not, follow the label pattern P1-10 uses (P4).
- Counter reads "417 slash 480"; wants a spoken form (P3).
- Messages: StatusLine is a polite live region and focus moves to the first reason (pick-reason) or Send (offline/failed): matches the spec. Risk: the focus announcement can cut off the live message; QA to listen once.
- Back: arrow `sound_report_back_a11y`, system back and Escape return to details (code: `onBack` handles `reportOpen`). Good.
- Focus on return: the Report row gets it (`ReportFocusReturn`). After a successful report in the picker the row no longer exists and the request silently fails (P2).

**Motion and haptics: pass.** Pane swap is a Crossfade of `durationSheet` 200 ms, `durationPress` 120 ms under reduce motion, in both sheets. Radio/button changes are not animated beyond the state swap, within the "nothing else" rule. One Confirm haptic with the toast (`ReportSentHaptic`), none on tap, none on failure. Matches the spec.

## Polish list (before phase-end QA)

- **P1. Announce "Sending…".** Spec Accessibility ("announced politely"). `Button` has no live region and a disabled-looking busy button drops focus. Request to the engineer: add `Modifier.semantics { liveRegion = LiveRegionMode.Polite }` to the Send button's modifier in `ReportPane` (or a `busy` live region in `Button`).
- **P2. Focus after a report in the picker.** Spec Accessibility ("focus returns to the row", Sheet README). With the Report row replaced by "Reported. Thank you.", put the `focus` requester on that line (make it focusable) so TalkBack lands on it and reads it. In `ReportEntry`, the `reported` branch ignores `focus` today.
- **P3. Spoken counter.** Counter visible text stays "417/480"; add a content description "417 of 480 characters" (new string `sound_report_count_a11y`, ~28 chars, 5 languages, `{n}` and `{max}` placeholders; budget 32). Not a live region (no per-keystroke chatter).
- **P4. Verify the note field label on TalkBack** (see above); fall back to P1-10's pattern if the typed text isn't read.
- **P5. Second tap on Send with no reason** changes nothing, so TalkBack hears nothing the second time. Re-announce (toggle the message off and on, or re-trigger the live region) so a repeated tap still answers. Low priority.
- **P6 (spec check, no code).** Spec says focus goes to the pane title on entering the pane. I could not find that in `ReportPane`; confirm with TalkBack that entering the pane reads "Report this sound" first, otherwise request focus on the sheet title.
