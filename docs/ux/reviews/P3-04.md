# Design review: P3-04 download states

Reviewed 11 Nov 2026 against `docs/ux/specs/P3-04-download-states.md`, with the download parts of P3-03 and P3-05. Evidence: the 19 desktop renders in `docs/ux/reviews/P3-04/` (looked at: row-downloading, row-failed, row-failed-hi-200, list-offline, toast-storage-full, row-looks-with-add-block, details-failed-hi-200, details-failed-storage, details-offline-notsaved), the handoff, and `SoundRow.kt`, `SoundsBlocks.kt`, `Toast.kt` and the five `strings.xml` sets. Nothing was seen on a device, so TalkBack and the real download timing are unverified.

## Verdict: Pass with polish

No must-fixes for P3-04. One follow-up ticket is recommended for the offline first launch (item 5), and it is not a blocker.

## The five deviations

1. **Live region on the meta line instead of two a11y strings: confirmed, and better than the spec.** The meta sits inside the merged name block, so a change is announced as "{name}, {meta}". That names the sound, which my two strings did. It announces only while Downloading or Failed, so a quick download and a return to normal say nothing (SC 4.1.3). I removed the two keys from the spec. Check on the device that the announcement fires once and not on every recomposition.
2. **Disabled disc reads its meta line: confirmed.** "Play {name}, disabled, No longer available" gives the reason in words. `sound_a11y_unavailable_hint` is dropped from the spec. The disc stays in the focus order.
3. **Status text on its own line under the player row: confirmed.** The waveform keeps full width (`details-failed-storage`, `details-offline-notsaved`), and at hi 200% the status wraps whole (`details-failed-hi-200`).
4. **Storage toast on the Sounds screen only, the sheet's status line when the sheet is open: confirmed.** The sheet is modal, so a toast behind it would be hidden and a second message would be noise. The sheet shows "Not enough space on your phone." in `danger` on `surface`. One condition: with the sheet open there is no "Free up space" action. This is acceptable because the toast stays until dismissed and appears when the sheet closes. Make sure it does show on close.
5. **Offline first launch: not a must-fix for P3-04, but my spec was wrong and the current result is a dead end.**
   - **My error.** Spec line 51 said the starter pack plays from the Favorites and My sounds tabs. Both are empty on a first launch (nothing favorited, nothing imported), so that could never have worked. The builder is right that it doesn't.
   - **What the Sounds screen should show.** The offline strip ("You're offline. Saved sounds still play."), then the bundled starter sounds as normal rows under a `label` heading "Starter sounds". No load-error block. The starter pack has its own names, lengths and credits (`SoundLibrary.starterSounds()` returns `CatalogSound`), so rows need no catalog row. They play, show the Add block and work with Use. The load-error block stays for an online failure, where Try again makes sense. This is the better reading of principle 5 (no dead ends) and principle 2 (sound first).
   - **Why not a must-fix.** TICKETS Done-when ("airplane mode plays the starter pack and every cached sound") is met through the editor's Meme sounds sheet (`airplane-starter.png`). The case is a first launch offline, with nothing cached, which is rare. The block does say what to do next.
   - **Follow-up.** A small ticket, to go before P3-15 or into it. Copy: `sounds_starter_heading` "Starter sounds", budget 20; en/id/es/pt/hi to be drafted by the engineer (suggested: Suara awal, Sonidos iniciales, Sons iniciais, शुरुआती साउंड). The spec is updated.

## Checks

- **Tokens only:** pass. The code uses `MemixColors`, `MemixSpacing`, `MemixShapes` and `MemixSize`. No raw values seen in the files I read. The look is v2: no outlines, no gradients, blue only on the disc, rail and action, `danger` only on failure words.
- **Every state (spec Row states):** pass. Seen: Downloading (blue × disc, "Downloading…", rail), Failed, Failed storage (disc enabled, Add block disabled), offline not saved (muted disc, muted meta, Add slot kept empty), removed (same look), toast with and without the action, offline strip, and the details variants. The Add block follows the table in every look (`row-looks-with-add-block`). Not rendered: the unreadable-file toast. Not verifiable in desktop renders: the under-300 ms path.
- **Contrast (calculated from tokens.json):**
  - `danger` `#F6574C` on `canvas` is about 5.7:1. The spec said 5.2; both are above 4.5.
  - `text-muted` `#949494` on `canvas` is about 6.2:1. On the dimmed disc the icon is well above 3:1.
  - "Free up space" in `primary` on `surface-raised` is about 5.9:1.
  - `danger` never lands on `surface-raised` in practice: a failed row can't be playing. I'd still guard it in code (see polish 3).
- **Copy and budgets in five languages:** pass. All strings are present in en, id, es, pt and hi, and the budgets hold (the longest is Spanish "No hay espacio suficiente en tu teléfono.", 41, under 52; `sound_not_saved_offline` es "No guardado para uso sin conexión", 34, over the budget of 32 by 2). Tone is verb first and "you". The wording is machine-draft quality, which is fine until P5.
- **200% font:** pass. The English failed meta wraps to 2 lines and the Hindi to 3 (`row-failed-hi-200`) with the row growing and nothing clipped. The disc stays centered. The toast wraps and its action keeps its own row.
- **TalkBack (by reading the code):** pass. The disc name changes with the state (Cancel download of, Try again: download), the name block is one stop, the toast is polite and its buttons are focusable. A screen reader hears the offline and removed reasons. Needs one device pass: announcement not repeated, and the disabled state read as "disabled" plus the reason.
- **Motion:** pass with one note. The rail is driven by a lambda read in the draw phase and the engine updates it every 100 ms, so it steps and never loops, which is also the reduce-motion behavior. The spec asked for a 120 ms linear glide to each value for normal motion; stepping at 10 per second is close enough that I accept it. The toast uses a 120 ms fade, the same with reduce motion (`FadingToast`).

## Polish (none blocks)

1. **Spanish length:** `sound_not_saved_offline` is 34 characters against 32. Shorten to "No guardado sin conexión" (24). Same check for pt "Não salvo para uso off-line" (27, fine).
2. **Stale line in the details sheet:** "On this phone: Saves when you play or add it" is shown while the download failed for storage and while offline. Better: for failed storage, "Not saved. Free up space, then try again."; for offline, "Not saved. Connect to save it." Copy needed in five languages. The row-level state is already clear, so this is polish.
3. **Guard:** do not draw the playing/paused band on a row whose look is not NORMAL (`SoundRow` applies the band on `isPlaying || isPaused` regardless of `look`), so `danger` text can never land on `surface-raised`.
4. **Hindi danda:** in the desktop render the danda "।" in the Hindi failure text sits with a gap before it ("सका । फिर"). The strings have no space, so this is the fallback font's side bearing. Check on the device; if it shows there too, ask the engineer to put the danda in the Devanagari font.
5. **Details status area while failed:** the empty rail beside a Retry disc (`details-failed-hi-200`) reads as a dead track. Acceptable; if it bothers on the device, hide the rail while Failed.
