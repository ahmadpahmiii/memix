# Design review · P1-14 Drafts

**Verdict: Changes requested, provisional, from code only** (27 Oct 2026). Three must-fixes, all small (a few lines each). The screen follows the spec closely: order, row layout, menu, rename sheet, delete with undo, copy sheets, motion, tokens and the five languages are right. The three problems are:
1. The type badge collides with the placeholder icon and is cramped.
2. Another toast can remove the Undo while a delete can still be undone.
3. A failed duplicate tells the user to "Update Memix, or delete it", and a failed rename says nothing.

Nothing was seen on a screen: this session has no emulator, so every width below is **computed**, not seen. The device screenshots (list at the end) are the final check, as for P1-12 and P1-13.

Reviewed commit 53b3c0c on `claude/phase-1-kickoff-cenfgz` against `docs/ux/specs/P1-14-drafts.md` and the tokens (Layout, Order, States, Interactions, Motion, Copy, Accessibility, Analytics, QA compares).

## Matches the spec
- **Order and Done when** (`DraftsViewModel`): the list is `ObserveProjectSummariesUseCase`'s newest-edit-first Flow. Opening, rename and undo never write a time. On return, a changed draft scrolls the list to the top and takes focus; an unchanged one keeps its scroll and takes focus. The 2 s `RETURN_WATCH` covers the editor's last save landing late.
- **Row:** thumbnail `listThumbSize` (56) at `radius-sm`, `space-4` from the edge, `space-3` before the text; name `bodyStrong` `text` with `maxLines = 2` and the design-system Text's default ellipsis; meta `label` `text-secondary` with no line limit (it wraps at large font); the thumbnail stays at the top of the text; the row is at least 56 + 2 × `space-2` (72) and grows. Name and meta stay in a column that is at least 56 tall and centered.
- **Pressed:** a `surface` fill, `radius-md`, inset `space-2` from both edges, behind the whole row, faded in from a see-through copy of the same gray over `duration-press`; no ripple, nothing moves. The More options icon ends up 16 dp from the screen edge (`space-1` + 12 dp inside its 48 dp target), on the `space-4` gutter.
- **Unnamed drafts** show the stand-in resource at draw time, so it follows a language change; the stand-in is never saved.
- **Menu:** Rename, Duplicate, Delete in the Menu component, labels in `text`, anchored to More options' center, the press point after a long-press (the LongPress haptic comes from `combinedClickable`), or the row's center for the Menu key and Shift+F10.
- **One screen-reader node:** `clearAndSetSemantics` gives "name, type, edit time" and the three actions as custom actions; More options is its own stop.
- **Rename sheet:** a single-line field in P1-10's look (`surface-raised`, `radius-md`, `space-3` inside, at least `touch-target` tall, `body` `text`), labelled "Name" for screen readers, the whole name selected on open, the stand-in as a `text-muted` hint on an unnamed draft, Done on the keyboard saves, the keyboard opens one frame after the sheet takes focus, 60-grapheme limit applied to pastes too, line breaks turned into spaces, the counter from 50 in `caption` `text-muted` and end-aligned, Save the one primary button full width. Close, scrim, drag and back send `CloseRename`, which changes nothing.
- **Copy sheets:** blocking "Copying your draft" with a determinate bar and Cancel (the percent is read only inside the sheet, so the list behind doesn't recompose); "Not enough space" with Free up space (hidden when the phone has no storage screen); both appear after 300 ms; coming back from the storage screen retries. Cancel deletes the half-made copy (the use case cleans up on cancellation).
- **Delete:** no confirmation, the row leaves at once, Undo toast for 8 s or the user's "Time to take action" time (`calculateRecommendedTimeoutMillis` with `containsControls`), a second delete replaces the toast, focus goes to the next row (the previous one at the end), Undo restores in place and focuses the row.
- **Motion:** removal fades out and rows slide over `duration-sheet` (200 ms), new and undone rows fade in the same way, all off with reduce motion; the thumbnail fades in over 120 ms and not at all when it was already cached.
- **Tokens only.** No `Color(0x`, no raw dp or sp, no v1 value in the feature code. No outline, hard shadow or gradient. Blue appears nowhere on the list (Create stays the blue); the rename sheet's Save is its one primary. Selection white is not used.
- **Copy, five languages.** All keys exist in all five languages, with placeholders intact and every string inside its budget. "Memix" is kept in `drafts_needs_update`. Duplicate and Delete match the editor's `tool_duplicate` and `tool_delete` in every language (Duplikat/Hapus, Duplicar/Eliminar, Duplicar/Excluir, डुप्लिकेट/हटाएं). Indonesian has only `other` (correct, no plural); Hindi `one` and `other` are filled; the Spanish percent uses a no-break space.
- **Analytics:** none fire, as specified.
- **Contrast** (recomputed from tokens): name `text` on `canvas` 16.9:1; meta and More icon `text-secondary` on `canvas` 7.8:1 (5.7:1 on `surface-raised`); the pressed row's `surface` 15.4:1 and 7.1:1; badge glyph `text` on `scrim` 7.5:1 or more over any image (worst case white, `#F2F2F2` on `#4D4D4D`).

## Must fix before end-of-phase QA

**M1. The type badge: hide it on the placeholder, and give it a proper chip.**
- **Where:** `DraftRow.kt` → `DraftThumbnail`.
- **The problem:**
  - The badge is drawn in every state. With no picture yet (every row for a moment, and permanently for a missing-media or pre-build draft) the thumbnail shows the centered 24 dp type icon and the corner badge together. At 56 dp the badge sits at x 4 to 20, y 36 to 52 and the centered icon at 16 to 40, so the two overlap by a 4 dp corner, and the same icon appears twice in a 56 dp square. Spec → Draft row, first sub-bullet: the placeholder is the centered icon and nothing else.
  - The badge is the 16 dp icon alone on the `scrim` (the `Icon` modifier is clipped and filled, then sized to 16). The drawing keeps only 1.3 dp of air inside its 16 dp box, and `radius-sm` (6) on a 16 dp square nearly makes a circle, so the glyph's corners come within about 0.1 dp of the curve. It will look crammed against the edge (Assumption from the geometry; the `badge-zoom` screenshot decides).
- **Fix:** I added the token `badge-size` 20 dp (`design/tokens.json`, `design/system/tokens.json`, DESIGN_SYSTEM → Sizes; changelog 27 Oct). Please add `MemixSize.badge = 20.dp` with the KDoc "`badge-size` in design/tokens.json" and change the badge to:
  ```
  if (shown != null) {
      Box(
          Modifier.align(Alignment.BottomStart).padding(MemixSpacing.space1).size(MemixSize.badge)
              .graphicsLayer { this.alpha = alpha.value }.clip(MemixShapes.radiusSm).background(MemixColors.scrim),
          contentAlignment = Alignment.Center,
      ) { Icon(typeIcon, null, tint = MemixColors.text, size = MemixSize.iconSmall) }
  }
  ```
  so the badge exists only over a picture and fades in with it. The placeholder branch stays as it is.
- **Spec line:** Layout → Draft row → Thumbnail (both sub-bullets; updated 27 Oct).

**M2. Another toast must not remove the Undo while the delete can still be undone.**
- **Where:** `DraftsViewModel.showToast` and `ToastTimedOut`.
- **The problem:** `showToast` replaces whatever toast is up. Delete a draft, then within 8 s duplicate another (or tap a "needs a newer Memix" row): "Draft duplicated." or "can't be opened" replaces the Undo toast, and `showUndoable` only clears a toast that is still `Deleted`. The delete stays pending but the Undo button is gone, so the draft is lost without the 8 s the spec promises. The "no dead ends, undo everywhere" principle.
- **Fix:** keep the latest `UndoableDelete?` in the ViewModel (set in `showUndoable`). On `ToastTimedOut`, after clearing the toast, if that field is non-null, show `DraftsToast.Deleted(undoable.draftId, newSerial())` again. The Undo then comes back for the rest of the window, and `showUndoable(null)` still clears it when the window ends or Undo is used. No change to the host.
- **Spec line:** Interactions → Delete (new sub-bullet, 27 Oct).

**M3. Failure copy: a failed duplicate must not say "Update Memix, or delete it", and a failed rename must not be silent.**
- **Where:** `DraftsViewModel.showDuplicateOutcome` (`Failed` → `CantOpen`), `saveName` (any failure other than `ProjectUnreadable` does nothing), `delete` (a failure does nothing); `DraftsToastHost`.
- **The problem:** `drafts_cant_open` tells the user to update or delete the draft. That is right for a damaged or newer-version draft, and wrong, and a risk to their work, for a copy that failed because a write to the phone failed. Silence after Save or Delete leaves the user unsure whether it worked (Nielsen: visibility of system status; errors say what to do next).
- **Fix:** add the three toast kinds, each shown for the 4 s explanation time (or longer by the "Time to take action" setting):
  - `saveName`: `ProjectUnreadable` keeps `CantOpen`; any other failure shows `RenameFailed`.
  - `showDuplicateOutcome`: `Failed(ProjectUnreadable)` keeps `CantOpen`; any other `Failed` shows `DuplicateFailed`.
  - `delete`: a failure other than not-found shows `DeleteFailed`; the row stays.
  - The rename sheet closes as now (the typed name is lost; it is a local database write that rarely fails). If Crashlytics ever shows these, the sheet can stay open instead.
  - The strings (budget 60; machine drafts until P5; apostrophes unescaped, the project's convention):

  | Key | en | id | es | pt | hi |
  | --- | --- | --- | --- | --- | --- |
  | `drafts_rename_failed` | Couldn't rename this draft. Try again. | Draf ini tidak bisa diganti namanya. Coba lagi. | No se pudo cambiar el nombre. Inténtalo otra vez. | Não foi possível renomear o rascunho. Tente de novo. | ड्राफ़्ट का नाम नहीं बदला जा सका। फिर कोशिश करें। |
  | `drafts_duplicate_failed` | Couldn't duplicate this draft. Try again. | Draf ini tidak bisa diduplikat. Coba lagi. | No se pudo duplicar el borrador. Inténtalo otra vez. | Não foi possível duplicar o rascunho. Tente de novo. | ड्राफ़्ट डुप्लिकेट नहीं हो सका। फिर कोशिश करें। |
  | `drafts_delete_failed` | Couldn't delete this draft. Try again. | Draf ini tidak bisa dihapus. Coba lagi. | No se pudo eliminar el borrador. Inténtalo otra vez. | Não foi possível excluir o rascunho. Tente de novo. | ड्राफ़्ट हटाया नहीं जा सका। फिर कोशिश करें। |

  Lengths: en 38 to 41, id 39 to 46, es 49 to 52, pt 51 to 52, hi about 45; all inside 60. The wording follows `drafts_cant_open` and `drafts_load_error` in each language ("Draf" in id, "Eliminar" in es, "Excluir" in pt, "हटाएं" family in hi).
- **Spec line:** States → the new "fails" row; Copy (added 27 Oct).

## Polish

**P1. Make the "Not enough space" body about the copy.**
- **Where:** `drafts_storage_body`, five languages. It is a drafts-only key, so nothing else changes.
- **Why:** on Android every duplicate now copies, so a 300 MB draft needs 300 MB more space, and "Your media needs 300 MB" doesn't tell the user why a duplicate costs space.
- **Fix:** en "Copying this draft needs %1$s, and your phone has %2$s free. Free up space, then come back to carry on." id "Menyalin draf ini butuh %1$s, dan HP kamu punya %2$s kosong. Kosongkan ruang, lalu kembali untuk melanjutkan." es "Copiar este borrador necesita %1$s y tu teléfono tiene %2$s libres. Libera espacio y vuelve para continuar." pt "Copiar este rascunho precisa de %1$s, e seu celular tem %2$s livres. Libere espaço e volte para continuar." hi "इस ड्राफ़्ट की कॉपी के लिए %1$s चाहिए, और आपके फ़ोन में %2$s खाली है। जगह खाली करें, फिर जारी रखने के लिए वापस आएं।" ("Come back to carry on" is true: coming back retries by itself.)

**P2. The keyboard focus ring is clipped at the screen edge and doesn't match the pressed fill.**
- **Where:** `DraftRow.kt`, the inner `Row`.
- **Why:** `focusRing` draws 3 dp outside the Row's bounds, and the Row starts at x = 0, so the ring's left side is cut by the list's clip. The pressed fill is inset `space-2`, the ring is not.
- **Fix:** put `.padding(start = MemixSpacing.space2)` before `.focusRequester` (so the focus target, ring, key handling and click area all start 8 dp in), and change the existing start padding from `space4` to `space2`. The thumbnail stays 16 dp from the edge, the pressed fill and the ring now share their left edge, and the ring is whole. Device check: Tab to a row (`focus-ring-keyboard`).

**P3. Keep the `more` icon as built; check its weight on the zoom screenshot.** See answer 4. No change unless the screenshot shows the dots lighter than the 2 px strokes beside them.

## Answers to the engineer's five points

**1. Hard links.** The spec's request 3 already had the fallback ("If links aren't possible, copy with P1-02's flow"), so nothing in the states breaks. I accept Android always copying and updated the spec:
- Request 3 now states that Android copies and iOS may link (P7-08).
- The "Duplicating takes over 300 ms" row says that on Android the sheet is the normal path for a draft with sizeable media; a draft with small clips finishes before 300 ms and never shows it.
- The "Not enough space" row names the copy and says coming back retries.
- The body copy changes (P1).
- Device check C already measures the route and time; add the copy time for the 500 MB draft to the QA notes. I won't claim a duration before that measurement (Assumption: a few seconds on current flash storage).

**2. Failed rename or failed duplicate.** The copy is in M3 (three strings, five languages). Behavior: an unreadable or newer-version draft keeps `drafts_cant_open`; any other failure gets a 4 s toast that says what happened and the next step (try again); nothing in the list changes; a failed delete leaves the row. Duplicate "can't be opened" for a write failure was wrong and is replaced.

**3. The type badge.** Not as built: the 16 dp icon alone is cramped, and it must not show on the placeholder. Token `badge-size` 20 dp is added (M1): a 20 dp `scrim` chip, `radius-sm`, `icon-small` centered (2 dp around it), `space-1` from the thumbnail's corner. It covers 20 of 56 dp at the corner, and `text` on `scrim` stays 7.5:1 or more over any picture.

**4. The `more` icon and `tint`.**
- **Icon:** approved. Three solid dots (r 1.5, centers x 5, 12, 19, y 12) sit inside the 20 dp live area (3.5 to 20.5) with a 4 px gap, all core, like play. Horizontal on purpose: it matches the editor's horizontal tool bar and iOS later, and the spoken label carries the meaning. I fixed the spec's stray "⋮" to "…". The dots are 3 px against the set's 2 px strokes: if `more-icon-zoom` shows them reading lighter than the nav icons, go to r 1.75 at the same centers and tell me.
- **`tint` on IconButton:** approved, used for a quiet icon in a list. Only `text-secondary` is allowed (7.8:1 on `canvas`); disabled still turns `text-muted`. I added this to the IconButton README. The default stays `text`, so the editor's buttons are unchanged.

**5. Focus to the empty state, and focus back to More options.** Later, not must-fix. Reasons:
- After the last delete the Undo toast is a live region (it is announced politely) and its Undo is focusable, so a TalkBack user is not stranded.
- Compose keeps the main window's focus while a Popup (the Menu) is open, so focus should return by itself when the menu closes (Assumption, not confirmed here).
- Both are recoverable with one swipe.
- **Rule:** QA does the TalkBack and keyboard pass (hand-check G). It becomes a must-fix only if (a) after the last delete TalkBack lands on the status bar or nowhere, or (b) after Escape on a menu a keyboard user has to Tab from the top of the list. If so, the fix is `requestFocus` on the empty state's "Make a meme" button, and on the same row's More options button.
