## Deviations judged

1. **Whole-button cross-fade at `duration-press`: accepted.** The change is blue to `surface-raised` plus a label change in 120 ms, which reads as one state change. One side effect, see polish 1.
2. **Title missing on arrival, so the spoken line has no name: accepted for a rare case; see polish 2** for the My sound case, which is not rare.
3. **`use_sound_missing_toast`: accepted.** It is the string the spec already defines (Copy table), not an addition.
4. **"Pick again" keeps the sound; Close and Cancel drop it: accepted.** It is exactly the spec's rule (Picker confirmed).

## Polish (none blocks the ticket)

1. **Focus can be dropped on the swap (Primary).** `Crossfade` replaces the Button, and the busy Button is not clickable, so a TalkBack or keyboard user who had focus on "Use in a video meme" may lose it when it turns into "Downloading...". The spec asks the disabled state to stay focusable. Request to the engineer: keep one Button instance and cross-fade only its label (a text-slot overload of `Button`, or `AnimatedContent` inside it), or give the busy Button `semantics { disabled() }` with focusability kept. Same check for the row's Use block while downloading (`enabled = false` on `AddSoundButton`). Confirm both with TalkBack at phase-end QA.
2. **My sounds arrive nameless.** `showStartingSound` looks the title up by `MediaOrigin.CatalogItem`. A My sound (P3-07) has no catalog id, so its arrival is always read as "  added at 0 seconds", with a stray leading space. Request: fall back to the clip's display name for a My sound, and if there is still no name, use a name-less sentence ("Sound added at 0 seconds", new key `a11y_sound_added_unnamed`: id "Suara ditambahkan di detik 0", es "Sonido añadido en el segundo 0", pt "Som adicionado em 0 segundos", hi "आवाज़ 0 सेकंड पर जोड़ी गई"; budget 40). I did not add the key to the spec's Copy table; do so with the fix.
3. **QA on device (not rendered):** (a) the bonk and Confirm haptic land after the 320 ms push, not during it (I could not find where `ArrivedWithSound` is dispatched in a `*Screen.kt`; check it waits for the push); (b) with reduce motion on, the fade-in plays and the haptic still fires once; (c) TalkBack hears the screen announcement first, then "{name} added at 0 seconds", with no focus move; (d) overhang case: wash plus toast, spoken in one message; (e) missing case: toast text and 4 s; (f) focus returns to the Use block or the sheet's Primary after the picker is cancelled.
4. **Screenshots still owed** for the spec's QA list: `arrive-overhang` and the editor arrival with the blue sound clip at 0:00 and the main tool bar. Add them to `docs/ux/reviews/P3-15/` at phase-end QA.
