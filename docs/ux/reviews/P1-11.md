# Design review · P1-11 Canvas

**Verdict: Changes requested, provisional, from code and desktop renders** (21 Oct 2026). There are three must-fixes, all small and all about what a screen reader hears: the ratio pill never says whether its panel is open, Fit and Fill lose their spoken "selected", and the captions on the preview can still be selected through TalkBack while the Canvas panel is open, which can stack the Style panel on top of it. Two of the three were gaps in my spec. Everything you can see works as intended: the pill and its open look, the six ratio tiles with their drawn shapes, the custom steppers, Fit and Fill for every clip, the Blur swatch and palette, the frame edge, the "Text moved…" toast and the four new icons. There are three polish items, and decisions on the engineer's three points. The final check uses the owner's device screenshots after Phase 1 (list at the end).

## Matches the spec

- **Ratio change** (render 185): one "Ratio" step; the top caption pulled in and shrunk, the off-frame caption kept; the toast "Text moved to stay inside the frame." The domain rule is covered by the engineer's 44 canvas checks in the domain harness.

## Must fix before end-of-phase QA
**M1. The ratio pill never says whether the panel is open.**
- **Where:** `:core:designsystem` `component/SettingPill.kt`, the `clearAndSetSemantics` block.
- **The problem:** it sets `expand { }` or `collapse { }`. Those are accessibility **actions**, not a state. TalkBack lists them in its actions menu but announces only "Canvas, 9:16, button", open or closed. The spec (Accessibility → The pill) and the SettingPill README ask for "expanded" or "collapsed". Without it, a TalkBack user who opens the panel and moves back to the pill can't tell that the panel below is open. It's the only cue a sighted user gets from the blue look. That's WCAG 2.2 SC 4.1.2 (state must be available to assistive technology).
- **Fix:** keep the actions, and add a state description:
  ```kotlin
  val state = stringResource(if (expanded) Res.string.setting_expanded else Res.string.setting_collapsed)
  // in clearAndSetSemantics:
  stateDescription = state
  ```
  New strings in `:core:designsystem` `composeResources` (machine draft OK until P5):

  | Key | en | id | es | pt | hi |
  | --- | --- | --- | --- | --- | --- |
  | `setting_expanded` | Expanded | Diperluas | Expandido | Expandido | खुला है |
  | `setting_collapsed` | Collapsed | Diciutkan | Contraído | Recolhido | बंद है |

  This is the pattern Material 3's exposed dropdown anchor uses.
- **Check:** TalkBack on the pill: "Canvas, 9:16, collapsed, button"; double-tap; swipe back to the pill: "…expanded…".
- **Spec line:** Accessibility → The pill; Copy (new keys); SettingPill README → Accessibility.

**M2. Fit and Fill don't say "selected".**
- **Where:** `component/OptionTile.kt` (`hint` → `stateDescription`) and `canvas/CanvasPanel.kt` → `FitTile`.
- **The problem:** OptionTile puts the hint ("Shows the whole clip") in the state description. On a selectable control the state description **replaces** the default state word: Compose speaks "selected" only when no state description is set. TalkBack reads "Fit, Shows the whole clip, radio button" whether or not Fit is the choice, so a screen-reader user can't tell Fit from Fill's state (SC 4.1.2). My spec and the OptionTile README asked for exactly this, so this one is my error.
- **Fix:**
  - `FitTile`: drop `hint`, pass `spokenName = stringResource(Res.string.canvas_ratio_a11y, stringResource(label), stringResource(hint))` → "Fit, Shows the whole clip". The name still starts with the visible label (SC 2.5.3). `canvas_ratio_a11y` is "%1$s, %2$s" in all five languages; its translator note now covers both uses, and its budget is 40.
  - `OptionTile`: remove the `hint` parameter (Fit and Fill are its only users) so no caller can hide "selected" again.
- **Check:** TalkBack on Fit while it's selected: "Fit, Shows the whole clip, selected, 1 of 2"; on Fill: no "selected".
- **Spec line:** Accessibility → Ratio tiles, Fit/Fill and swatches; Copy (`canvas_ratio_a11y`, `canvas_fit_a11y_hint`); OptionTile README → Accessibility.

**M3. With the Canvas panel open, TalkBack can still select captions and open their panels.**
- **Where:** `captions/CaptionLayer.kt` → `CaptionNodes` (the `onClick` and the Style and Position `customActions`).
- **The problem:** touch gestures are off while the panel is open (`gesturesOn`), but the caption nodes still take a double-tap. The first one selects the caption behind the panel. A second one goes to `CaptionControl.tap` → `editSelected()` and starts typing with the Canvas panel still open. The Style and Position actions run `SelectItem` + `OpenTextPanel`, which sets `textPanel` while `canvasPanel` is still set, so two panels stack. That breaks "panels never stack" (Entry and exit) and "no caption selection while the panel is open" (Interactions), and only screen-reader users can reach it.
- **Fix:** pass `interactive = state.canvasPanel == null` from `PreviewStage` through `CaptionLayer` to `CaptionNodes`. When it's false, keep `contentDescription` (and `selected`) so the captions can still be heard after a ratio change, but set no `onClick` and no `customActions`. The stage's own Play/Pause node is unchanged.
- **Check:** TalkBack, Canvas panel open: swipe to a caption; it reads "Text: …"; double-tap does nothing (or plays/pauses); the actions menu has no Style or Position; the panel stays the only panel.
- **Spec line:** Interactions → The preview while the panel is open; Accessibility → Captions on the preview while the panel is open (new).

## Polish
**P1. Keep the selected ratio tile in view.**
- **Where:** `canvas/CanvasPanel.kt` → `RatioRow` (or `ChoiceRow`, if the engineer prefers to do it for the Style rows too).
- **The problem:** when the panel opens with Custom selected, or undo brings Custom back, the white tile can be fully off screen: Hindi at 200% (render 196: the steppers show, the row ends at a cut "16"), and in es/pt the long "Personalizado" tile shows only "Perso" with no icon (render 197). The user sees steppers with no selected tile above them.
- **Fix:** give the selected tile a `BringIntoViewRequester` (`Modifier.bringIntoViewRequester`) and call `bringIntoView()` in a `LaunchedEffect(selected)` when it becomes selected or first composes selected. A tap on a tile that is already partly in view scrolls it fully in, which is fine.
- **Spec line:** Ratio row (new bullet); OptionTile README → Stacked.

**P2. One Portuguese toast is over budget.**
- **Where:** `values-pt/strings.xml`, `explain_canvas_reorder`.
- **Fix:** "Toque em Concluído para terminar de reordenar primeiro." (56 of 50) → "Toque em Concluído para terminar de reordenar." (46).
- **Spec line:** Copy (budget 50).

**P3. Let Fit and Fill wrap one under the other.**
- **Where:** `canvas/CanvasPanel.kt` → `ClipsRow`, the inner `Row` around the two tiles.
- **The problem:** measured from render 197 (the es tiles are 100 and 106 dp at 100%), at 200% the pair needs about 322 dp in pt ("Ajustar" + "Preencher") of the 328 dp a 360 dp screen leaves. It fits today with 6 dp to spare. Any wider font metrics, letter spacing or a longer final translation would squeeze the second tile inside a `Row`, and its one-word label would break mid-word.
- **Fix:** make the inner `Row` a `FlowRow` with `horizontalArrangement = Arrangement.spacedBy(MemixSpacing.space2)` and `verticalArrangement = Arrangement.spacedBy(MemixSpacing.space2)`, keeping `selectableGroup()` and its `contentDescription`.
- **Spec line:** Clips row; OptionTile README → Inline.

## Decisions on the engineer's points
1. **The preview renders at a 720 px shorter side while Blur is on: accepted.** The spec allows a reduced blur resolution in the preview, and the handoff's cost estimate (about 180M shader steps per frame at 1080 × 1920) makes it the right call. Two conditions, now in the spec as a build note: the sigma follows the preview's own output (3% of 720 ≈ 22 px), so the softness matches the 1080p export; and with a color background the preview keeps its normal size. QA's "same softness at 720p and 1080p" comparison and the 30 fps measurement on `preview-check` settle it on the phone.
2. **The four canvas icons: approved.** DESIGN_SYSTEM → Iconography now describes them as built and counts 41 icons (details below).
3. **Ratio and swatch rows aren't edge to edge yet: accepted,** because the P1-10 P1 fix lands in the shared `ChoiceRow` and both canvas rows use it. The Clips row doesn't scroll, so it isn't affected. QA confirms it on `panel-open` below.

## Icons
All four follow the grammar: 24 grid, shapes in the central 20, 2 px butt-capped strokes with mitred joins, 1 px rectangle corners, one tint, one solid core.
- **`fit`:** a stroked 12 × 20 frame with a solid 8 × 6 block across its middle, touching the inner sides. It reads as "the whole wide clip inside a tall frame" at 24 dp (render 180). Distinct from `fill`.
- **`fill`:** the same footprint filled solid, with four 2.5 px strokes 1.5 px clear of its sides (over the 1.4 px gap rule). At 24 dp the strokes read as small cut marks beside the block ("▮:"). That's acceptable: the label carries the meaning, and the solid-versus-outline contrast with `fit` is what matters.
- **`blur`:** a 7 px solid dot inside four 4 px strokes, 2.5 px clear. At `icon-small` in the swatch it reads more as a "focus" crosshair than a blur. I'm accepting it as built: the swatch's effect is instant and visible on the preview, and the spoken name is "Blur". I'll judge it again on the owner's screenshots; if it doesn't read, I'll redraw it in Phase 2 when P2-12 adds the image background next to it.
- **`ratio_custom`:** a stroked 20 × 16 rectangle with a solid 8 × 8 handle over its bottom-right corner, flush with the outer edge. Clearly different from the solid ratio shapes beside it (render 180).

## Notes (no change needed)
- **The Fill hint line is below the fold at 360 × 800** (render 191): the panel scrolls, as the spec's height budget predicted. It's next to the swatches it explains, so whoever looks for the background sees it.
- **The Blur swatch has no ring and no visible label,** like the colors. Its icon is the identifying graphic (5.7:1); the circle edge against `surface` is decorative.
- **A pulled-in caption can end up near another caption** (render 185: "PASSED" above "MIDDLE"). That's the minimal-move rule working; overlaps are the user's to fix, and one undo restores everything.
- **A stepper hold that commits and also hits a limit** shows the limit toast instead of the spoken ratio. Fine: the readout and the pill already show the result.
- **Explanation toasts at the top of the stage can cover the top caption** for a few seconds (render 192). Same as P1-10, accepted.
