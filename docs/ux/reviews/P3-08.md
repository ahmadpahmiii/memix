# Design review · P3-08 Voiceover

Reviewed 15 Nov 2026 against `docs/ux/specs/P3-08-voiceover.md`, the ToolBar and Timeline READMEs, `VoiceoverPanel.kt`, `VoiceoverControl.kt`, the five `strings.xml` files, and the 13 desktop renders in `docs/ux/reviews/P3-08/` (stand-in stage and transport row, so the saved time and the clip's start can't be compared). No TalkBack or device run: accessibility is judged from code and is for phase-end QA to confirm.

## Final verdict (fix-check, 15 Nov 2026): Pass with polish
All four must-fixes are closed. Checked on the re-renders and `VoiceoverPanel.kt`:
1. **Stop:** `recording-hi-200.png` shows Stop whole and first under the title row, with the status row visible under it. Pass.
2. **Quiet hint:** `recording-quiet.png` shows Stop, status row, then the two-line hint in the meter's place; the code makes it a polite live region. Pass.
3. **Ready:** `ready-no-headphones.png` and the new `ready-es-no-headphones.png` (three lines) show the whole note and Record with room to spare. One message above Record by code (saved, else note, else hint). Pass.
4. **Focus:** Record, Cancel and Stop are one `movableContentOf` button, so the node should survive the phase changes. Pass by code only; QA confirms with TalkBack at phase end, and also listens that the "Recording" live region and the quiet hint are spoken.
Polish also confirmed: the denied explanation takes focus. Cancel's 300 ms ignore is in the control, not rendered.
**The kept item:** a take of 0.5 s or more that leaves nothing after trimming to the picture and the video's end still says "too short". Accepted. Record is blocked within 0.5 s of the end, so this is a corner, and "too short" is true of the part that fits in the video. Real save failures use the save banner. No change.
Carried to QA, nothing new for the builder: focus and live-region speech with TalkBack, the clip start against the saved time on a device, the five-tool main bar at 200%, the blocked-control toasts, and the Hindi danda spacing.

## Earlier verdict (first pass): Fail (four small must-fixes, one re-render)

The design is right and the build follows it: nothing blue, `danger` with a word and an icon, no outlines, tokens only, all 24 keys in five languages matching the spec text. It fails on **fit**: three states the spec promised would not scroll do scroll, and each hides something the user needs. The root cause is **my spec's height budget**: it said 181 dp and left out the ToolPanel's own padding and gap (real budget 133 dp). The builder was right to flag it. I corrected the spec in this pass, so the fixes below are the corrected spec, not new design.

## Must-fixes

1. **Stop must never scroll out (the builder's flag 2).** `recording-hi-200.png`: Stop is clipped to about half its height under the fold, with a running recorder. Reaching it by scrolling or by Play/Pause works but is the wrong thing to ask of someone mid-sentence. **Fix (spec Recording, order changed):** Stop first under the title row, then the status row, then the meter. Also drop the status row's `touch-target` minimum height (it is not a control; spec "Status row"). Breaks spec: Accessibility → "200% font … Stop reachable"; QA compares item 4.
2. **The quiet hint is invisible (not flagged).** `recording-quiet.png` shows the empty meter and Stop and no hint: it sits under Stop, below the fold at 360 × 640 (Stop at the bottom edge, about 17 dp left). Nothing proves the state was ever seen. **Fix:** the hint takes the meter's place (a quiet take has an empty meter anyway), and it becomes a polite live region (`liveRegion = Polite`), because a blind user cannot see the meter and this is their only sign the microphone hears nothing. Breaks spec: Recording item 4; Accessibility → announcements (SC 4.1.3).
3. **Ready is 17 to 19 dp too tall, and in the common case (no headphones) the note is cut (the builder's flag 1).** `ready-no-headphones.png` and `ready-bluetooth.png` show the note's first line and then the edge. The note is the one thing a user must read ("your video plays silent"), and the spec says Ready states fit without scrolling. It also gets worse in es and id (three lines) and hi. **Fix (no copy change):** one message above Record, never two; priority saved line, else route note, else hint (spec Ready item 1). Heights at 100%: no headphones 94 dp (en) to 111 dp (es, id), headphones 104 dp, saved 104 dp, all inside 133 dp. Breaks spec: Layout intro; States → Ready rows.
4. **Focus after Record, by code reading.** Spec Accessibility → Focus: "focus stays on the same button, which now reads Cancel then Stop." `VoicePhase` switches between three separate `Button` calls, so the focused node leaves the tree and TalkBack focus falls back to the panel. Stop is the key control for a blind user, so this is a must-fix. **Fix:** after the countdown starts and again when recording starts, move accessibility focus to the new button (a `FocusRequester` per phase), or draw one `Button` composable whose label and action change. Engineer confirms with TalkBack at phase-end QA and says which way they did it.

## Answers to the builder's flags
1. **19 dp over:** my spec error, not yours. Budget corrected to 133 dp. No ToolPanel change, no new token. See must-fix 3.
2. **Hindi 200% Stop:** must-fix 1. Judged carefully: WCAG 1.4.4 and reflow are technically met (it scrolls), but Stop is a time-critical control with a live recorder, so "reachable by scrolling" is not enough. Stop-first makes it right at every font scale and costs nothing at 100%.
3. **`import_cancel` and the 12 dp dot:** both fine. The string reads Cancel, Batal, Cancelar, Cancelar, रद्द करें, correct for the countdown; polish: when someone next touches `:core:ui`, rename it to a generic `action_cancel`, so a recording screen doesn't depend on an import key. The dot uses `space-3`, a token, equal to the spec's 12 dp; no `status-dot` token for one use. If a second status dot appears (P3-09 or the layers panel), I add `size-status-dot` then. **No token changes.**
4. **Voiceover hidden in an empty project:** correct and as specced (spec Entry; ToolBar README line 11). One check for QA: with five tools the main bar scrolls or shrinks at 360 dp and 200% without clipping a label.

## Copy and budgets, five languages
Pass. All 24 keys are present in en, id, es, pt, hi and match the spec text; `{time}` and `{length}` map to `%1$s` and `%2$s`. Budget checks I made by eye: hint, saved and denied inside budget; the longest (`voiceover_muted_note` es about 101 of 110, `voiceover_denied` hi about 80 of 100) wrap to three lines in es and id, which the corrected layout absorbs. "Stop" a11y names contain the visible label in all five (WCAG 2.5.3). Hindi: the danda sits detached on a wrapped line in `ready-hi-200.png`, the same fallback-font spacing seen in P3-07; check on a device. No copy changes requested.

## 200% font
Ready hi-200 scrolls with the hint first and Record peeking; fine, because scrolling is the designed fallback and nothing is cut mid-glyph. Recording hi-200: must-fix 1. Title and Done wrap correctly; Devanagari line height holds with no clipped matras.

## TalkBack (from code)
- **Good:** Record, Cancel, Done and Open settings are plain buttons; Stop's name "Stop recording" contains "Stop"; the dot, meter and timecode are hidden; the countdown is one polite live region with a fixed description, so the digits don't talk over each other; "Recording" is a polite live region; the panel title is a heading and a pane title.
- **To fix or confirm at QA:** focus continuity (must-fix 4); the quiet hint is not a live region (must-fix 2); `Recording` as a live region on first composition may not be spoken by every TalkBack version, so QA listens for it.
- **Polish:** a real double tap on Record can land on Cancel, because Cancel takes Record's place a frame later; the spec says a quick second tap is ignored. Ignore Cancel for the first 300 ms of the countdown.

## Motion and reduce motion
Pass. Only the ToolPanel's slide (200 ms, fade 120 ms with reduce motion) moves; the digits change instantly, the dot is static, the meter is a reading. No loop anywhere.

## The green Audio track for the take
Pass. `track-audio` (`#3DAE79`) with the label `#111111` and white selection; it reads as audio, not as a meme sound (no blue). The take is selected after Done, as specced.
