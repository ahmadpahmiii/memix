## Matches the spec
- **Swatch order:** video Blur · Image · colors (`20-video-*`); photo Image · colors (`10-bg-*`). Image sits right after Blur.
- **Three looks** (`20-video-canvas-panel-no-picture-yet`, `-picture-set`, `-missing`): the `photo` icon on `surface-raised` and unselected; the picture center-cropped into the circle with the white ring (the "BG" grid reads clearly at 32 dp); the icon in `text-muted` with the ring. With Blur or a color selected the Image swatch goes back to the no-picture look.
- **Image row:** "Image" label in `text-secondary` at the start, Replace and Remove at the end, `space-2` apart, 48 dp tall; absent with no picture; Hindi at 200% fits on one line (`20-video-hindi-200`), Spanish at 200% wraps without cutting (`10-bg-spanish-200`).
- **Missing line** under the row, `caption` in `text-secondary`, wraps; the canvas is black behind the layers and the frame edge shows (`10-bg-canvas-panel-missing`). Toast text matches the spec and names the pill ("Tap 1:1 at the top").
- **Hint line** for an image behind a full-bleed photo and behind Fill clips (`10-bg-...-hint-under-full-bleed-photo`, `20-video-...-picture-hint`): same line, same place as for a color.
- **Draw rules in the reference frames:** `photo-background-only-9x16-1080` is a centered cover crop of the 3000 × 2000 picture (37.5% of the width kept, so "BG" is cut on both sides, as a cover must); `expected-video-9x16-fit-16x9-clip` puts a 1080 × 608 clip at y 656 to 1264 of 1920, which is the right Fit geometry. Full brightness, no scrim, no tint.
- **Layer stack:** the scene draws black, the picture, then the layers (`10-bg-scene`); the translucent layer shows the picture through it.
- **Strings:** all 11 keys exist in en, id, es, pt and hi, with the spec's wording and the `%1$s` placeholder; hard-coded values none.
- **Semantics (code):** the swatch speaks "Image" (or "Image, file missing"), keeps `selected` as its state, adds the click label "Pick an image" only while empty; Replace and Remove carry names that start with the visible label in en, id, es and pt.
- **Analytics:** `canvas_background` with `value` `image` on a pick or Replace, `color` on Remove and on a color, `blur` for Blur (`CanvasPanelControl.kt`, `PhotoEditorViewModel.kt`).
- **Swatch README and DESIGN_SYSTEM:** the Swatch README already had the Image variant (added with the spec); I added the "unreadable counts as missing" and loading notes there, and the Image variant line in `docs/DESIGN_SYSTEM.md` → Compose notes (the Swatch sentence). Logged in `docs/ux/CHANGELOG.md`.

## Polish (not blocking)

**P1. Swatch thumbnail fade (the 120 ms; builder's deviation 1).** Accepted for the commit. While the thumbnail loads, the swatch is the ringed icon in `text-secondary`, so a first open shows "icon, then picture pops in". It is almost the same as the missing look (the icon tint differs 5.7:1 vs 4.6:1), so a slow decode could read as a failure for a moment. Fix when `Swatch.kt` is next touched: animate the picture's draw alpha 0 to 1 over `MemixMotion.durationPress` when `picture` goes from null to non-null (an `animateFloatAsState` read inside the `drawBehind`, so no recomposition). On Android reduce-motion makes it instant anyway (Compose ends animations at animator scale 0), so no extra reduce-motion branch is needed. Spec line: Motion, "Swatch thumbnail appears".

**P2. The missing line and the missing swatch use two different tests.**
- **Where:** `BackgroundRows.kt` → `BackgroundGroup` (line `if (image?.missing == true)`) and `ImageSwatch` (`val missing = image != null && (image.missing || ... thumbnails.failed(...))`).
- **The problem:** the swatch goes to the "missing" look when the thumbnail fails even if the editor hasn't set `image.missing`. In the photo editor `image.missing` comes only from the scene decode, so a file whose 128 px thumbnail fails but whose scene decode works (rare) shows the missing swatch with no line and no toast.
- **Fix:** compute `missing` once in `BackgroundGroup` (`image != null && (image.missing || thumbnails.failed(image.path))`), pass it to `ImageSwatch`, and use the same value for the line. Spec line: States, "Picture's file missing".

**P3. Photo panel: the image row sits partly or wholly below the fold, and my spec's height was wrong.**
- **Evidence:** in `10-bg-canvas-panel-picture-set` (360 × 800, a 1:1 canvas) the panel is at its 40% cap (320 dp) and Replace and Remove are cut about 12 dp (36 of 48 dp showing); measured content is about 335 dp, about 360 dp with a hint. The spec said 300 dp. At 360 × 640 the cap is 256 dp and the whole image row is under the fold. The user just picked the picture, so the controls for it are not in view.
- **Decision:** keep the 40% cap. Raising it while a picture is set would resize the stage when the picture lands (a visible jump on the user's meme). I corrected the number in the spec.
- **Fix (optional, small):** when a pick lands in the photo editor, scroll the panel so the image row is fully in view (once, instant, not on every open). If you skip it, QA item 3 decides.

**P4. Portuguese toast is one character over budget.** `canvas_image_missing_toast` pt is 91 characters with "9:16" in it (budget 90), and "no alto" is less natural than "no topo". Replace with: `Imagem de fundo não encontrada. Toque em %1$s no topo para substituí-la ou removê-la.` (85 characters). The other four languages fit (en 80, es 71, id about 76, hi short).

**P5. Hindi names don't start with the visible label.** `canvas_image_replace_a11y` "तस्वीर बदलें" and `canvas_image_remove_a11y` "तस्वीर हटाएँ" contain the visible "बदलें" and "हटाएँ" but put the object first, as Hindi word order wants. SC 2.5.3 needs the label contained in the name, which holds, so accepted as is. Recheck on the device with Voice Access ("tap बदलें").

## Judgment on the builder's deviations
1. **Swatch thumbnail fade not built: accepted** as P1. Polish, not a spec-breaking state.
2. **Focus return not built: accepted**, the same rule as P2-01's P4. For the picker the Canvas panel stays open, so Android usually restores TalkBack focus when the picker activity closes; the import sheet is the risk, since it is in-app and its Cancel or finish can leave focus on nothing. It becomes a must-fix only if QA's TalkBack pass lands on nothing or the status bar after the picker or the sheet closes. One shared helper later, for every editor.
3. **An undecodable file counts as missing: accepted.** It is honest to the user: the file can't be used and the way out (Replace or Remove) is the same. I wrote it into the spec's States and the Swatch README. Two guards for QA: (a) the editor decides from the thumbnail, the export from the bars' decode, so confirm they agree on a damaged file and on a very large one (12000 × 8000: thumbnail fine, cover-size decode could fail, and then the export would draw black bars with no word in the panel); (b) after Replace or Undo the swatch and line must clear (the watch is keyed on the path, so it should).
4. **Exporting screen's mock frame draws no picture: accepted.** The frame is a decoration beside the progress, it already draws black for Blur, and the export decodes the picture at the output size, which this screen shouldn't also do while the encoder runs. Say nothing; revisit only if testers think the export lost the picture (record in the P2 test notes). No change to P1-12.
5. **Question 2 (cache the decoded bars across rebuilds):** only if the device numbers ask for it, as the builder proposed: the preview rebuild with a picture set more than 100 ms slower than without.
