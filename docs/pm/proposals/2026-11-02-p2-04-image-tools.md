# P2-04 image tools: the Done when, where the 20 filters come from, and which filter was used

**Date:** 2 Nov 2026 · **Author:** PM (P2-04 ready check) · **Status:** **Approved by delegation (owner, 2 Nov): recommendation applied, owner reviews after Phase 2** (all three questions: 1A, 2A, 3A)

## 1. The Done when reads backwards

**Problem:** P2-04's Done when is "Filter ids and looks match the video filters". The video filters are P4-07, built months later, and P4-07's own Done when says "same ids and looks as the photo filters". P2-04 is the one that defines them, so the sentence cannot be checked when P2-04 is built: there is nothing to match yet.

**Considerations and options:**
- **A. Reword it so P2-04 defines and P4-07 matches (recommended).** New Done when: the 20 filters, 6 adjustments and deep-fry each have a stable id and a reference render; applied to an image layer, the editor and the render hook at 1080 and 2160 show the same look; crop, rotate, flip and straighten keep the layer editable and give the same picture in the editor and the render; the ids and LUT data are the ones P4-07 reuses. Cost: none; it is checkable by hand now and keeps the promise to video.
- **B. Leave the sentence and check it at P4-07.** P2-04 could then never reach a final verdict until Phase 4 (about 2 months), and a mismatch found then would reopen a closed ticket.
- **C. Pull the video filters (P4-07) forward.** About 2 to 3 more days now, a Media3 GL pipeline for filters built before the video-effects work, and a Phase 4 ticket moved; not worth it for a look comparison.

**Recommendation: A.** Applied: `docs/TICKETS.md` P2-04 Done when reworded.

## 2. Where do the 20 LUT filters come from?

**Problem:** the PRD says "about 20 filters", and the ticket says LUT filters. The content policy says nothing enters the app without a recorded license, and free LUT packs found online often forbid redistribution inside an app. The repo is public.

**Considerations and options:**
- **A. Make them ourselves with a script (recommended).** A script generates 20 color grades (curves, tints, fades) as small LUT images; the script and a README saying "original work" go in the repo. License: none to track. Size: about 20 files of 100 to 300 KB (well inside the 50 MB budget). The same data is read by photo now and video later, so looks match.
- **B. Buy or license a pack.** Money and a license review before the lawyer step; still needs the owner's approval of each file.
- **C. Use free packs.** Fast but the one rule that can't be fixed later (a takedown after launch).

**Recommendation: A.** Cost: about half a day of design time to choose the 20 looks, inside P2-04 (the backend engineer can own the script, as for content). Reverse: replace the files and keep the ids (a look changes, no schema change).

## 3. Which filter did people use?

**Problem:** with 20 filters, analytics should say which earn their place. `tool_use` has no way to send a filter id: the owner approved `font` only for text, and `value` only for canvas tools.

**Considerations and options:**
- **A. Add an optional `filter` parameter to `tool_use`, sent only when `tool` is `filter` (recommended), in both editors.** The same reason as `font` (9 Oct): which of the 20 looks matter for the catalog, presets and the video filters. Cost: one custom dimension in Firebase at P5; no personal data; off until consent.
- **B. One id per filter** (20 ids): no new parameter, but 20 `EditorTool` values and a long list in the analytics tool.
- **C. Send nothing**: P4-07 and any later pack are chosen blind.

**Recommendation: A.** Reverse: stop sending it (no migration).

## Impact

No launch date moves (Android ≈ 7 Mar 2027, iOS ≈ 2 May 2027). Phase 2 stays planned for 16 Nov–6 Dec. Quality improves: the filters are original, checkable and reusable for video.
