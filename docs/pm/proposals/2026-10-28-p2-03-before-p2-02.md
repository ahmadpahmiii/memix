# Build text (P2-03) before meme formats (P2-02)

**Date:** 28 Oct 2026 · **Author:** PM (P2-02 ready check) · **Status:** **Approved: A** (owner, 28 Oct 2026, relayed by the main session). P2-03 now comes before P2-02 in `docs/TICKETS.md`; `decision-log.md`, 28 Oct

**Problem:** four of the five meme formats are made of words. Classic is a top and a bottom caption, Caption bar is a white bar with a caption in it, Demotivational is a frame with a title and a line under it, and Speech bubbles are shapes with text inside. Panels (cells with photos) is the only one that works without text. Today the photo editor cannot draw text at all: `drawPhotoScene` skips every text layer until P2-03 (it says so in the code), and no tool in the editor adds one. In the ticket table P2-02 comes before P2-03 and needs only P2-01. Built in that order, P2-02 would produce frames, bars and bubble outlines with nothing to put in them, and its Done when ("each format exports correctly") could not be checked for four formats until a later ticket.

**Considerations and suggested fixes:**
- **A. Build P2-03 first, then P2-02 (recommended).** New order: P2-01, P2-12, P2-13, **P2-03**, **P2-02**, P2-11, P2-04 and on. P2-02 then needs P2-01, P2-03 and P2-12. P2-03 needs only P2-01 and P1-10, both built, so nothing blocks it. P2-11 (shadow and box) already follows P2-03 and stays right after P2-02.
  - Time: none. Same tickets, same sizes, only the order changes. Phase 2 started 20 days early.
  - Money: none.
  - Risk: low. The text drawing in the photo scene (the part P2-02 depends on) is built once, by the ticket that owns it. P2-03's open question about sticker content (nothing exists until the catalog and sticker packs, P3 and P4) comes up a few days sooner, and the Blank row on the Create sheet goes live sooner, which is good.
  - User impact: none yet; nobody outside the team has a build before the closed test (about 25 Jan 2027).
- **B. Keep the order; P2-02 builds the frames, bars, cells and bubble shapes with empty slots, and P2-03 fills them.**
  - Time: none now, but P2-02's check is split in two: the shapes at P2-02, the words at P2-03.
  - Money: none.
  - Risk: medium. The Done when for four formats can only be met after P2-03, so a P2-02 verdict means "shapes only" and the real check lands in another ticket. Layout decisions (how much room a caption bar needs, how a title wraps in a frame) are made without ever seeing text.
  - User impact: none yet.
- **C. Move the text drawing for the photo scene into P2-02.**
  - Time: P2-02 is already at the top of L, so it would very likely overflow. P2-03 shrinks, but the total is the same and the work is split across two tickets that depend on each other.
  - Money: none.
  - Risk: high. Text drawing is the shared text engine P2-03 is meant to own, and P2-11 builds on it.
  - User impact: none yet.

**Recommendation: A.** It costs nothing, and each ticket's Done when can then be checked on its own.

**Impact:** no launch date moves (Android ≈ 7 Mar 2027, iOS ≈ 2 May 2027); Phase 2 stays planned for 16 Nov–6 Dec. The 5,000 DAU goal is not touched: formats are what makes a photo meme fast to make, and they arrive in the same phase either way. Quality improves because every format is checked with real text.

**If approved (A):** the PM reorders the P2 rows in `docs/TICKETS.md` (P2-03 and P2-11's Needs are unchanged; P2-02's Needs become P2-01, P2-03, P2-12), adds a Phase 2 note, updates the board and logs it in `decision-log.md`. The designer keeps writing the P2-02 spec now: nothing in a spec depends on the build order, and the spec can name P2-03's text as a given. The P2-03 spec is needed next, before P2-02's.

**Needed by:** before P2-12 and P2-13 are finished, because the next builder pick after P2-13 depends on it.
