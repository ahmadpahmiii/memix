# P1-02 follow-ups: "Add media" and "Replace a clip" ticket, `project_create.source`

Raised by the P1-02 spec (`docs/ux/specs/P1-02-gallery-picker.md` → Proposals and questions for the PM, ca3ce51). Two separate decisions, each approved on its own.

## A. No ticket for "add more at any time" and "replace a clip"

**Status: Proposed**

**Problem.** PRD → Video editor → Media promises "add more at any time, replace a clip". No ticket in any phase builds either. The P1-02 spec already defines how "Add media" behaves: it lands after the clip under the playhead, never splits a clip, and is one undo step. P1-05 places the button. Without a ticket, the first internal build forces a user who forgot a clip to start over, which breaks "fast path with deep tools".

**Options**
1. **New ticket P1-16, size S, after P1-06** (recommended). "Add media and replace a clip from the video editor: same picker and import sheet as P1-02; replace keeps the clip's place and length." Done when: *Media added from the editor lands after the clip under the playhead as one undo step, and a replaced clip keeps its start and length so sounds and text stay in sync.* Needs P1-02, P1-06, P1-07. The designer adds "Replace" (and what happens when the new media is shorter) to the P1-05/06 spec. *(8 Oct: done in a30ae8e. The P1-06 spec → Replace holds the recommended behavior: a shorter video is refused with a message rather than shrinking the clip. The P1-05 spec places the Add media tile after the end of the video. Both stay hidden until this is approved.)*

**Scope note (8 Oct, PM):** P1-16 covers video and photo clips only, as the PRD's "replace a clip" sits under Media. Swapping a meme sound (keep its start, change the sound) is not part of it; in P1 that is Delete plus add at the playhead. If wanted, it is raised with the P3-05 sound picker spec as a separate P3 proposal. This doesn't change the size (S) or the impact below.
2. **Fold both into P1-06.** P1-06 is already L (4–5 days) and its Done when is about preview latency, so it would grow past L and need a split anyway.
3. **Move to Phase 4** (pro video tools). That keeps P1 smaller, but P4 is the heaviest phase and includes the holidays, and the first internal build would have no way to add a clip after the start.

**Recommendation:** option 1.

**Impact.** Up to 1 day added to P1. P1 started 7 Oct, 12 days ahead of the planned 19 Oct, so launch dates (Android ≈ 7 Mar 2027, iOS ≈ 2 May 2027) don't move. It supports exports per DAU and day-1 retention: a user fixes a project instead of abandoning it. Analytics: `tool_use {editor: "video", tool: "add_media" | "replace_clip"}`, per the spec.

## B. `project_create.source` has no value for a gallery start

**Status: Proposed**

**Problem.** The PRD lists `source` values `blank` and `template` only. Every video project that doesn't start from a template starts from the gallery. In P2, a photo project starts from the gallery or from a blank layout (PRD → App structure), so with `blank` covering both we can't tell those two starts apart.

**Options**
1. **Add `gallery`** (recommended): values become `blank`, `template` and `gallery`. Video gallery starts send `gallery`. `blank` means only the photo editor's blank layout.
2. **Keep the PRD as written:** gallery starts send `blank` and the two photo starts stay merged.

**Recommendation:** option 1. It costs one value, and the funnel from start to export (exports per DAU is a supporting target) needs to know where projects come from.

**Impact.** No date or scope impact. Analytics collection stays off until consent (P5-01), so no live data is affected. Until the owner decides, P1-02 sends `blank`, per the PRD as written; switching later is a one-line change.
