Shared Kotlin code holds the UI, the domain and the data layer; only the video engine, background removal and platform services are written per platform.

Features and data never talk to each other directly: both go through domain interfaces, which also lets iOS swap in its own engines without touching shared code.

## Modules and layers

The code is one Gradle multi-module Kotlin Multiplatform project using clean architecture: presentation and data both depend on domain, and platform engines sit behind interfaces defined in domain.

| Module | Layer | Holds | Depends on |
| --- | --- | --- | --- |
| `:androidApp` | App | Android `Application`, `MainActivity`, manifest (AGP 9 keeps the Android app out of KMP modules) | `:composeApp` |
| `:composeApp` | App | Shared root: `App()`, navigation host, Koin graph, iOS entry point (`MainViewController`); builds the `ComposeApp` framework that `iosApp/` (Xcode) embeds | All feature modules |
| `:core:model` | Domain | Project, Track, Clip, Layer, Effect, Sound and Template entities; serialization | Nothing |
| `:core:domain` | Domain | Use cases; repository interfaces; engine interfaces (`VideoEngine`, `PhotoRenderer`, `Segmenter`, `MediaFiles`, `MediaInspector`, `LocalCalendar`, `Sharer`, `Ads`, `Analytics`) | `:core:model` |
| `:core:data` | Data | Repositories; remote source (supabase-kt on Ktor); local source (SQLDelight); file cache; settings | `:core:domain` |
| `:core:designsystem` | Presentation | Memix tokens, theme, base components | Nothing |
| `:core:ui` | Presentation | Shared composables and the strings both editors use: time formatting; layer gestures, selection frame, handle, guides and bubble (`layers/`); the Position and Canvas panel rows and the stepping logic (`panels/`); the save banner, unsaved sheet, frame edge and canvas frame (`editor/`); the one photo-scene drawing function and the picture-decoder interface (`scene/`); `Res` is public here so features reach the shared strings (the video timeline lives in `:feature:video-editor`, its only user) | `:core:designsystem`, `:core:model` |
| `:engine:video` | Platform | `VideoEngine`: Media3 in `androidMain`, AVFoundation in `iosMain`; the preview surface composable (`VideoPreviewSurface`) the composition root hands to the editor | `:core:domain` |
| `:engine:photo` | Platform | The scene's picture decoder (`SceneImageSource`: `ImageDecoder` on Android, a stub on iOS until P7-09); P2-08 adds the platform encoders (PNG, JPG, GIF, WebP) and draws the scene offscreen | `:core:domain`, `:core:ui` |
| `:engine:segmentation` | Platform | `Segmenter`: ML Kit and MediaPipe on Android, Vision on iOS | `:core:domain` |
| `:platform:services` | Platform | AdMob and UMP, Firebase, share intents; the gallery picker, storage-screen launcher and editor portrait lock (Compose hooks for the composition root) media copies and checks (`MediaFiles`, `MediaInspector`) and the phone's calendar and date format (`LocalCalendar`, P1-14) | `:core:domain` |
| `:feature:onboarding`, `:feature:home`, `:feature:templates`, `:feature:sounds`, `:feature:drafts`, `:feature:video-editor`, `:feature:photo-editor`, `:feature:export` | Presentation | Screens and ViewModels | `:core:domain`, `:core:ui` |
| `:feature:media-import` (P2-12) | Presentation | The import flow every pick goes through: `MediaImportFlow`, the sheet and its state, `ProjectPickImport` (a pick for an open project, by destination), the import strings | `:core:domain`, `:core:ui` |

- **Domain stays pure:** `:core:model` and `:core:domain` live in `commonMain` with no Android or iOS imports.
- **Features call use cases only:** never repositories or engines directly.
- **Platform code** lives only in the `androidMain` and `iosMain` source sets of engine and platform modules, plus the composition root (`:androidApp`, `:composeApp`) for app entry and wiring, such as the SQLDelight driver and debug hand-check hooks (owner, 8 Oct 2026).
- **iOS compiles from day one:** CI builds the iOS framework on every push to a phase branch and every pull request, even before iOS work starts, so Android-only APIs never leak into shared code.
- **State:** each ViewModel exposes one `StateFlow<UiState>` and takes `Intent` events (MVVM with one-way data flow). Editors keep an undo stack of immutable project snapshots in a `ProjectEditSession` (see Project data model → Editing, undo and auto-save).

## Project data model

One serializable `Project` describes both editors, so drafts, templates, undo and export all work from the same data. The code lives in `:core:model` (`app.memix.core.model.project`); this is its shape as built in P1-01. Fields for later features (speed, keyframes, filters, masks, transitions, audio effects, layer lock/opacity, meme formats) are added by the ticket that needs them, with a schema bump.

```kotlin
@Serializable
data class Project(
    val id: String,
    val type: ProjectType,                 // VIDEO or PHOTO
    val name: String,
    val canvas: Canvas,                    // ratio chip, widthPx, heightPx, background (Solid color or Blur)
    val video: VideoTimeline? = null,      // set when type == VIDEO
    val photo: PhotoScene? = null,         // set when type == PHOTO
    val createdAtEpochUs: Long,            // wall clock, µs since 1970 UTC
    val updatedAtEpochUs: Long,            // set on every save; the drafts list sorts by it
    val schemaVersion: Int = CURRENT_SCHEMA_VERSION,
)

data class VideoTimeline(val tracks: List<Track>)   // always exactly one MAIN_VIDEO track

data class Track(
    val id: String,
    val kind: TrackKind,              // MAIN_VIDEO, OVERLAY, TEXT, STICKER, MEME_SOUND, AUDIO, EFFECT
    val items: List<TimelineItem>,    // placed by startUs, never by list index
    val muted: Boolean = false,
    val locked: Boolean = false,
)

sealed interface TimelineItem { val id: String; val startUs: Long; val durationUs: Long }
// MediaClip(source: MediaRef, trimInUs, trimOutUs, volume, audioDetached, fit: FIT|FILL)   MAIN_VIDEO, OVERLAY
// AudioClip(source: MediaRef, trimInUs, trimOutUs, volume)                                  MEME_SOUND, AUDIO
// TextItem(durationUs, text, style: CaptionStyle(fontId, color, outlineColor?), transform)  TEXT
// StickerItem(durationUs, source: MediaRef, transform)                                      STICKER
// EffectItem(durationUs, effect: EffectSpec(id, params: Map<String, Float>))                EFFECT
// MediaClip and AudioClip derive durationUs from trimOutUs - trimInUs; it isn't saved.

data class MediaRef(
    val origin: MediaOrigin, val kind: MediaKind, val cachedCopyPath: String? = null,
    // Measured at import (P1-02, schema 2); null for media added before schema 2:
    val durationUs: Long? = null,      // the whole source file; null for photos
    val pixelSize: PixelSize? = null,  // as shown, rotation and EXIF orientation applied
    val hasAudio: Boolean? = null,     // a sound track this phone can decode; false for photos
)
// MediaOrigin: GalleryUri(uri) on Android, PhotoAsset(localIdentifier) on iOS, CatalogItem(itemId) for meme sounds and stickers

data class PhotoScene(val layers: List<Layer>)   // bottom to top
// Layer(id, transform): ImageLayer(source), TextLayer(text, style), StickerLayer(source)
// Transform: centerX/centerY as fractions of the canvas, scale, rotationDegrees (clockwise)
```

- **Time** is in microseconds (`Long`), matching Media3 and AVFoundation. Wall-clock timestamps are microseconds too, with an `EpochUs` suffix.
- **Media references** hold where the file came from (gallery URI, PHAsset id or catalog id) plus the app's own copy, so a draft survives the original file moving. `cachedCopyPath` and the thumbnail path are relative to the app's files directory, because iOS moves the app container on every update. The source's duration, shown size and whether it has sound are measured once at import (see Media import), so the editor never probes files to open a draft; a draft from before schema 2 has them null, and the editor reads them from the copy when it opens it.
- **Effects, filters and transitions** are declarative specs (an id plus parameters). Each engine renders the same spec, which keeps Android and iOS output alike.
- **JSON:** kotlinx.serialization with a stable `@SerialName` on every polymorphic subtype and enum entry (never rename one). Every field is written (`encodeDefaults`), and unknown keys fail the load instead of being dropped.
- **Storage:** `:core:data` keeps one row per project in the SQLDelight `project` table (`Project.sq`): `project_json` is the whole project and the source of truth; `name`, `type`, `schema_version`, `created_at_epoch_us` and `updated_at_epoch_us` are copied out of it on every save so the drafts list can sort and show rows without decoding projects (`updated_at_epoch_us` descending, then `created_at_epoch_us` descending for ties, P1-14); `thumbnail_path` is nullable and written only by `updateThumbnailPath` (P1-14). A save is one `INSERT OR REPLACE` that keeps the thumbnail, so a killed process leaves either the old row or the new one. The repository never changes a project's times: only `SaveProjectUseCase` (the editors' saves, the first import) stamps `updatedAtEpochUs`; rename, duplicate and an undone delete write through the repository with the times they want (P1-14).
- **Project JSON migrations:** each load parses the JSON, runs it through `ProjectJsonMigrator` (one `ProjectMigration` step per version, listed in `ProjectMigrations.kt`), then decodes it. A shape change bumps `Project.CURRENT_SCHEMA_VERSION` and adds the step that turns version N into N + 1; then open a draft saved before the change. JSON saved by a newer app, or damaged, loads as `AppError.ProjectUnreadable` and stays untouched in the database.
- **Database migrations:** the table itself evolves through SQLDelight: edit `Project.sq` and add `migrations/<version>.sqm` (the first is `1.sqm`). `databases/1.db` is the version-1 schema; `./gradlew :core:data:verifySqlDelightMigration` (run in CI) fails if `1.db` plus the `.sqm` files doesn't equal the `.sq` files. Regenerate a schema file with `./gradlew :core:data:generateCommonMainMemixDatabaseSchema`, in its own Gradle run.
- **Drivers:** the composition root opens the database (`:composeApp` `databaseDriverModule`: `AndroidSqliteDriver` in androidMain, `NativeSqliteDriver` in iosMain, file `memix.db`); `:core:data` stays commonMain only. The iOS framework is static, so `iosApp` links `-lsqlite3`.
- **Editing, undo and auto-save (P1-07):** both editors edit through a `ProjectEditSession` (`:core:domain`, started with `StartEditSessionUseCase`). The ViewModel copies `session.state` (`project`, `canUndo`, `canRedo`, `undoTool`, `redoTool`, `saveFailure`) into its own UiState, sends `commit(tool) { edit }` (returns whether a step was recorded), `undo()`, `redo()` from the main thread, calls `saveNow()` on ON_STOP and registers the session with `addCloseable`, so closing the editor saves too.
  - **Undo:** `ProjectHistory` keeps the current project plus up to 100 earlier and later versions (`MAX_UNDO_STEPS`), in memory only, each with the `EditorTool` whose edit made it. One `commit` is one step; a drag, trim or pinch keeps its in-between positions in UI state and commits once on release. An edit equal to the current project adds no step; a new edit clears redo. The editor turns the tool into words for its "Undo: Split" toast. A recorded `commit` logs `tool_use {editor, tool}` once, and `undo()` and `redo()` log `undo` and `redo`, each only when it changes the project (P1-06).
  - **Leaving a draft with no clips:** `close()` deletes a video draft whose main video track has no clip left (`Project.hasNoClips()`) instead of saving it (owner, 8 Oct 2026). The delete runs under the same write lock as saves, after any write in progress, and nothing is written after close, so a waiting save can't bring the draft back (P1-07 review R4). `DeleteProjectUseCase` deletes its media folder right after the row (P1-14); if that fails, the next start's `LeftoverMediaCleaner` does.
  - **Auto-save:** the newest version is written 500 ms after the last change (`AUTOSAVE_DELAY`; each change restarts the wait), at once on `saveNow()` and `close()`, and not at all if it is already the last version written. Writes run one at a time in the app-owned `appScope` (Koin, `Dispatchers.Default`; the repository encodes and writes on IO), so the newest version always lands last and a closing editor's save still finishes. A failed save keeps the version pending and shows as `saveFailure` (`StorageFull` or `Unexpected`); the next change, `saveNow()` or `close()` tries again.
  - **Process death:** only changes from the last 500 ms, plus the write in progress, are lost; SQLite rolls a half-done write back on the next open, so the previous save reopens intact.
- **Debug hand checks** (debug builds only, logcat tag `MemixProjectCheck`, started from `androidApp/.../ProjectChecks.kt`; the drafts list's `--ez memix.draftsCheck true` is under Drafts list):
  - Round trip (`ProjectRoundTripCheck`): `adb shell am start -S -n app.memix/.android.MainActivity --es memix.projectCheck save`, then `adb shell am force-stop app.memix`, then the same start command with `verify`, logs `identical` or the first difference.
  - Auto-save (`AutosaveCheck`): `--es memix.projectCheck autosave` drives a real `ProjectEditSession` through 110 edits, undo to the limit, 3 redos and one drag, logging every save. Add `--ei memix.killAfterMs <ms>` to end the process with SIGKILL that long after the last change, or `--ez memix.background true` to move the app to the background and end it right after the save that ON_STOP starts. A new start with `autosave-verify` logs which version reopened and whether it is identical.
  - Editor (P1-04, debug **and benchmark** builds: the `memix_hand_checks` resource is true in `src/debug` and `src/benchmark`): `--es memix.openEditor <name>` saves one of `EditorCheckProjects` as a draft and opens it in the video editor (logcat tag `MemixEditorCheck`): `export-check` (P1-03's project), `preview-check` (30 s of 1080 × 1920 at 30 fps on six tracks, the frame-rate check), `preview-error` (overlapping main clips: "The preview stopped"), `missing-media` (a clip whose file is gone), `empty` (no clips; leaving deletes it), and for P1-05 `timeline-check` (20 main clips, 80 s, plus caption, meme-sound and detached "Original audio" lanes; one sound runs 2 s past the end), `timeline-tracks` (the preview check's six tracks plus an overlay and a second meme-sound lane past the end) and `hour-long` (the 1080p clip's first 30 s, 120 times), and for P1-11 `canvas-check` (a 16:9 video, a 9:16 video and a 4:3 photo, Fit on black, four captions: large at the top, turned near the right edge, half off the left edge, in the middle). In the editor, a long-press on the timecode runs `DebugEdits.shortenLastClip` (1 s off the last clip, or removes a clip of 1 s or less), a real undo step named `trim`, for the undo, redo, toast and save-banner checks until P1-06. `--ez memix.failImportSave true` makes the next import's first save fail once with `StorageFull` (`ImportSaveFailure`, wrapped around the import's `SaveGalleryProjectUseCase` only), for the P1-02 N2 check. Every editor save logs the values that changed since the stored draft under `MemixEditorCheck` (`EditorSaveDiffLog`, wrapped around the edit session's save; items named by id, `updatedAtEpochUs` left out), for P1-16's "only the clip's source and trim changed" check. Media and commands: `docs/qa/phase-1/engineer-hand-checks.md` → P1-04.

## Media import

How picked videos and photos get into a project (P1-02; the editor's Add media and Replace reuse it, P1-16). Screens and copy: `docs/ux/specs/P1-02-gallery-picker.md`, `P1-06-clip-edits-and-audio.md` → Add media, Replace.

- **Picker (Android):** androidx.activity's `PickMultipleVisualMedia` (images and videos, ordered selection, at most `MAX_ITEMS_PER_PICK` = 35 or `MediaStore.getPickImagesMaxLimit()` if lower); Replace's one item uses `PickVisualMedia`, because `PickMultipleVisualMedia` requires a maximum above 1 (androidx.activity 1.13). androidx.activity picks the system photo picker, else the Play services backport (installed through the `ModuleDependencies` entry in `androidApp`'s manifest; Android 10 and phones without Google system updates), else `ACTION_OPEN_DOCUMENT`, which ignores the limit, so the import keeps the first 35. No accent color, no default tab, no HDR transcoding (the engine tone-maps), and no persistable URI permission: the project uses Memix's copy, never the original.
- **No permissions:** the merged manifest declares no media or storage permission; `androidApp`'s manifest removes `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_AUDIO` and `READ_MEDIA_VISUAL_USER_SELECTED` with `tools:node="remove"` in case a library adds one.
- **Where the code lives:** the picker and the storage screen are Compose hooks (`rememberMediaPickerLauncher`, `rememberFreeUpSpaceLauncher`, expect/actual in `:platform:services`), registered once at the app root (`:composeApp` `MemeImport`, one instance for Video meme and one for Photo meme), so a result that arrives after Android restarted the app still reaches them. The root hands the result to `MediaImportViewModel` (`:feature:video-editor`) as an intent. The copying, the sheet's timing, the space wait and the results are `MediaImportFlow` (`:feature:media-import`; it lived in `:feature:video-editor` `importmedia/` until P2-12 moved it, because the photo editor needs it too), shared with the editors' imports: it calls `ImportMediaUseCase` (prepare → space check → copy and check), then hands the copies to an `ImportLanding`, which says `Landed`, `Declined` (the copies are deleted) or `Failed`. For Create → Video meme, landing is `SaveGalleryProjectUseCase`, which places the media and makes the first save; `ImportUiState.Done` then opens the editor. Disk and checks sit behind `MediaFiles` and `MediaInspector` (`:core:domain`, Android implementations in `:platform:services`).
- **Copies:** `files/media/<project id>/<random id>.<extension>` (`MediaPaths`); one folder per project. The extension comes from the MIME type, else the file name, else the kind's default (`mp4`, `jpg`), and must be 1–8 letters or digits, because Media3 recognizes photos by it. Bytes go to `<name>.part`, are synced to disk and renamed when complete, so a file under its real name is always whole. Copying runs on IO in 256 KB reads and checks for cancel between reads.
- **Cleanup:** Cancel, Close or a failed check deletes that pick's copies at once (including a copy that finished just as Cancel landed). At every app start, `LeftoverMediaCleaner` (a Koin single created at start, running in `appScope`) deletes every `.part` file and the folder of every project that isn't a saved draft (Android stopped the app mid-import, or a draft was deleted); imports, duplicates, deletes from the drafts list and thumbnail writes wait for it. If the drafts can't be read, it deletes nothing. It logs how long it took (`Cleanup checked N drafts in M ms`, tag `MediaImport`; P1-14 bar: under 300 ms with 25 drafts).
- **When copies are deleted (P1-16):** a replaced or deleted clip's copy stays while the editor is open, because undo lives in memory and can bring it back. At the next app start, the cleaner also deletes the files in a saved draft's folder that the draft no longer uses (`Project.mediaCopyPaths()`: every clip, sound and sticker; split and duplicated clips share one copy; plus the draft's thumbnail). A draft saved since this start is skipped, since an editor of this run may have it open; a draft that can't be read keeps everything. So the owner's check is: replace, close, `adb shell am force-stop app.memix`, start again, and the old copy is gone.
- **Space:** before copying, `StorageManager.getAllocatableBytes` must cover the known sizes of what's left plus `HEADROOM_BYTES` (100 MB); then `allocateBytes` asks the system to clear other apps' caches for it. Unknown sizes count as zero, so a copy can still run out: a failed write that reports `ENOSPC`, or any failed write with less than 256 KB free, stops the import with what's done kept for the retry. "Free up space" opens `ACTION_MANAGE_STORAGE` with `EXTRA_REQUESTED_BYTES` (else the internal storage settings; else the button goes away); the space is checked again whenever the app returns to the foreground.
- **Checks and facts:** each copy is checked before it counts. A video needs a video track this phone has a decoder for (`MediaExtractor` + `MediaCodecList`; Dolby Vision may fall back to its HEVC or AVC base layer) and a duration over zero; a photo must decode (`ImageDecoder`, at about 512 px). The check records the source's duration (longest track), its shown size (rotation and EXIF orientation applied) and whether it has a sound track this phone can decode. A failed check deletes the copy and the item shows as "won't play"; a source that can't be opened or read to the end shows as "can't be read".
- **Placement:** in pick order on the main video track, back to back from 0 µs: videos at full length with their own sound, photos for `PHOTO_CLIP_DURATION_US` (3.0 s). A new project is created in memory with an empty name and saved once, when at least one item went in, which also logs `project_create` (`editor: video`, `source: gallery`). Nothing is saved for a pick that was backed out of, cancelled or where nothing went in.
- **First save fails for space** (P1-04, owner 8 Oct): when the copies are done but the new project's first save reports `StorageFull`, the import keeps the copies and shows "Not enough space" asking for the headroom (`ImportMediaUseCase.spaceToSaveAgain`). Back in the foreground with room, it saves again without copying (no Copying state), then opens the editor or "Some didn't go in"; Close deletes the copies. Any other save failure still shows "Couldn't add your media" with no rows.
- **Into the editor:** a sheet that was up stays, unchanged, while the editor's 320 ms push covers it (`ImportUiState.Done.sheetShown`; `ImportIntent.Finish` follows the push), and the tabs, bottom nav, scrim and sheets live in one `MainRoute` destination under the editor, so the push slides over them.
- **Progress:** by bytes when every size is known, else an equal share per item; at most 10 sheet updates a second (`CopyProgressTracker`); time left from the average speed over the last 2 s, shown after 2 s and only above 10 s. The import sheet appears only when copying takes longer than 300 ms and then stays at least 500 ms.
- **Backups:** `files/media` is excluded from the cloud backup (`data_extraction_rules.xml` on Android 12+, `backup_rules.xml` on 10 and 11), because one video exceeds Android's 25 MB backup quota, and over the quota Android backs up nothing at all. Drafts (the database) are still backed up; a draft restored on a new phone has no media copies and opens as the editor's "missing media" case (P1-04, P1-14). Device-to-device transfers on Android 12+ carry everything.
- **Process death:** copying carries on while the app is in the background. If Android stops the app mid-import, the picker's access ends with it; the next start deletes the unfinished files, and a first import leaves no project.
- **iOS (P7-08):** `PHPickerViewController` and copies into the same folder layout; until then iOS shows "Can't open your gallery", and its `MediaFiles` and `MediaInspector` are stand-ins.
- **Media copies are never changed in place (P1-14).** A duplicated draft may share its files with the original through hard links (iOS, P7-08), so writing into an existing copy would change both drafts. Every later feature that produces media (P2's masks, P4's crop and rotate, anything else) writes a new file under a new name and points the project at it; the cleaner deletes the old one when nothing uses it.
- **From the editor (P1-16):** the Add media tool (main tool bar) and the Add media tile (after the end of the video) pick up to 35 items; Replace (main clips) picks one. The editor asks for a picker through `VideoEditorUiState.mediaPicker` (`MediaPickRequest.Add(MediaPlace)` or `Replace(itemId)`); the root's `EditorMediaPickers` opens it and keeps the request in `rememberSaveable` while it's open, so a result after Android restarted the app comes back with what it was for (`MediaPicked(request, items)`), and the landing waits until the draft has opened. `EditorMediaImport` (`:feature:video-editor`) runs a `MediaImportFlow` into the draft's own folder and lands through the edit session: `insertMedia(media, clipIds, place)` (`project/MediaEdits.kt`: the tool lands after the main clip under the playhead, exactly on a boundary at that boundary, at or past the end appended, never splitting; the tile always appends; an empty project from 0:00; later main clips move right by the added length and other lanes keep their times) as one "Add media" step, or `replaceClipMedia(itemId, media)` as one "Replace" step when `replaceFit` says it fits (a photo, or a video at least as long as the clip, used from 0; the clip keeps its id, start, length, place and volume; a clip whose sound was detached gets its new sound attached at 0%, and its detached audio clip stays). A shorter video is `Declined`: its copy is deleted and "That video is shorter than this clip" names the clip's length. The import sheet draws over the editor with its own scrim and reads the import's state itself (`EditorMediaImportUi`), so only it redraws while copying. After the sheet has gone, the playhead moves to the first new clip and the new clips bonk together (`LandedItems`), or the replaced clip bonks; focus returns to the opener. `tool_use` `add_media` (once per pick) and `replace_clip`; no `project_create`.

## Drafts list (P1-14)

The Drafts tab: every saved draft, last edited first, with open, rename, duplicate and delete with undo. Screen and copy: `docs/ux/specs/P1-14-drafts.md`.

- **Where the code lives:** `:feature:drafts` (`DraftsViewModel`, `DraftsScreen`, `DraftRow`, `DraftsSheets`, `DraftsToastHost`, `DraftThumbnailImages`); use cases in `:core:domain` `drafts/`. The ViewModel is created by the app's main destination (`MainShell`, scoped to `MainRoute`), so the rename and copy sheets and the toast sit over the bottom navigation and the list is still there when an editor closes; the list is read from the first time the tab shows. The tab reports `Shown`/`Hidden` with its lifecycle.
- **Order:** `ObserveProjectSummariesUseCase` (`updated_at_epoch_us` descending, `created_at_epoch_us` descending for ties; the list never decodes a project). Opening a draft writes nothing (P1-07 saves only changes); `RenameDraftUseCase` writes the cleaned name (line breaks to spaces, trimmed, 60 user-perceived characters by `Graphemes.kt`; empty = unnamed, shown as "Untitled video meme" in the user's language) with `ProjectRepository.save`, keeping the edit time. `ProjectSummary` carries `createdAtEpochUs` and `schemaVersion`; a draft above `Project.CURRENT_SCHEMA_VERSION` shows "Needs a newer version of Memix" and only Delete works (by id, no decode).
- **Back from the editor:** the ViewModel remembers the opened draft's edit time; if the row's time changed (within 2 s of coming back, since the editor's last save lands after its screen has gone) the list scrolls to the top and focuses it, otherwise focus returns to its row. An editor that can't open a draft (damaged, from a newer app, or deleted meanwhile, such as P1-12's "Open draft" toast after a delete) closes with `couldntOpen`, and the app shows "This draft can't be opened" through the drafts toast, on whichever tab is showing.
- **Duplicate** (`DuplicateDraftUseCase`): a new id, `createdAtEpochUs` now, `updatedAtEpochUs` the original's + 1 µs (so it sits directly above its original until edited; a second copy ties and goes first by its newer creation time), "{name} (copy)" then "(copy 2)" and on, the original's part shortened to keep 60 characters, a copy of an unnamed draft unnamed; no `project_create`. Every file in the original's own folder (`Project.mediaCopyPaths()` plus the thumbnail) goes to `media/<copy id>/` under the same name, and every path in the copy is rewritten into that folder (`withMediaCopyPaths`); shared files outside it (bundled sounds, `debug-media/`) stay shared. Each file is first offered to `MediaFiles.link` (a hard link), else copied with `copyFile` (`.part` + rename, progress); only copied files need space (their sizes plus the 100 MB headroom, `reserveBytes`). A missing source file is skipped and its clip keeps its path in the new folder, so the copy opens in the same missing-media state. The row is saved (`saveWithThumbnail`) only after every file is in place; cancel, a full disk or a failed save deletes the new folder, and a kill leaves it to the next start's cleaner. The copying sheet shows only after 300 ms; "Not enough space" retries when the app comes back to the foreground. Each file's route is logged (`Duplicate: <file> linked | needs a copy | copied`, tag `Drafts`).
- **Hard links on Android:** AOSP's SELinux policy forbids them to apps (`neverallow all_untrusted_apps file_type:file link`, in `app_neverallows.te` since 2015), so `Os.link` fails with `EACCES` on every phone and duplicates copy; `AndroidMediaFiles` stops trying after the first refusal in a run. iOS's `FileManager.linkItem(at:to:)` does make hard links inside the app's container (P7-08). See "Media copies are never changed in place" under Media import.
- **Delete with undo** (`DeleteDraftUseCase`, a Koin single in `appScope`): `ProjectRepository.remove` deletes the row and returns it whole (`RemovedDraft`: the summary and the stored JSON, no decode), held in memory with the media folder on disk for the undo window: 8 s, or the user's "Time to take action" setting (`calculateRecommendedTimeoutMillis` with controls), passed in by the screen. Undo `putBack`s the row byte for byte (same id, times, name, thumbnail), so it returns to its place. When the window ends the folder is deleted; a second delete ends the first one's window at once. The window runs in the app's scope, so leaving the tab or rotating can't strand a folder; if the app dies first, the next start's cleaner deletes the folder of a draft that's no longer saved. The toast follows `undoable`; the ViewModel keeps the latest one, so when another toast (Duplicated, CantOpen, a failure) times out while the delete can still be undone, the Deleted toast with Undo comes back. A failed rename, duplicate or delete shows its own 4 s toast (`RenameFailed`, `DuplicateFailed`, `DeleteFailed`); only `ProjectUnreadable` shows "This draft can't be opened".
- **Thumbnails** (`UpdateDraftThumbnailUseCase`, a Koin single in `appScope`, one draft at a time): the cover is a video's first main clip at its trim-in, or a photo's lowest image layer (`Project.cover()`); a 192 px square JPEG from the engine's `ThumbnailReader` is written to `media/<id>/thumb-<cover file name>-<trim-in µs>.jpg` and `thumbnail_path` updated with `setThumbnailPath` (the edit time is untouched), then the old file is deleted. Because the name encodes the cover, a draft whose saved path already matches is skipped after one indexed query: nothing is decoded unless the first clip or its trim-in changed. It runs after the first save (`SaveGalleryProjectUseCase`), when the editor goes to the background and when it closes; a draft saved before P1-14 gets its thumbnail the first time an editor leaves it. The list reads the file through `ReadDraftThumbnailUseCase` and decodes it once off the main thread (`DraftThumbnailImages`, an in-memory cache of up to 60 by path); the image fades in over 120 ms.
- **Edit times** (`DescribeEditTimeUseCase` over `LocalCalendar`, `:platform:services`): under a minute "just now", minutes, hours under 24 h, the previous calendar day "yesterday", 2 to 6 calendar days, then a short date in the user's language (`DateFormat.getBestDateTimePattern` "dMMM", with the year when it isn't this year). One tick for every row: on `Shown` and once a minute while shown. iOS has a UTC stand-in until P7-08.
- **Opening time:** the app logs `Draft opened from the drafts list` under `MemixPreview` at the tap; the engine's `Preview opened in N ms` follows under the same tag, so logcat's timestamps give tap → first frame (PRD: under 1 s).
- **No analytics events** (spec → Analytics): rename, duplicate and delete log nothing, and a duplicate never reaches `project_create`.
- **No schema or table change:** the list query and `ProjectSummary` changed and four queries were added (`selectRowById`, `selectThumbnailPathById`, `updateThumbnailPath`, `insertWithThumbnail`); the table and the project JSON are as before, so no `.sqm` and no `schemaVersion` bump.
- **Debug hand check** (debug and benchmark builds): `adb shell am start -n app.memix/.android.MainActivity --ez memix.draftsCheck true` saves 25 drafts (`DraftsCheck`, logcat tag `MemixDraftsCheck`) with spread-out edit times covering every wording, one unnamed, one with a 60-character name, one with a schema version above this app's and one whose media folder is missing; the others each get their own copy of the pushed `debug-media/clip-a.mp4` and a thumbnail. Steps: `docs/qa/phase-1/engineer-hand-checks.md` → P1-14.

## Meme sounds (P1-08)

The starter pack and the editor's sound tools. Screens and copy: `docs/ux/specs/P1-06-clip-edits-and-audio.md` → Meme sounds sheet, Meme sounds, Move, Volume panel; `P1-05-timeline.md` → "Add a meme sound" row.

- **Starter pack:** the 10 CC0 sounds and `manifest.json` from `content/starter-sounds/` are copied into `:platform:services` Compose resources (`composeResources/files/starter-sounds/`), so Android and iOS read them the same way (`Res.readBytes`). `content/starter-sounds/` stays the source: a re-encoded sound is copied there and here together, and the manifest's `sha256Output` tells if they differ. The license proofs (`licenses/`) and the README are not bundled. About 443 KB of the APK (453,633 bytes stored; the m4a files aren't compressed again).
- **`SoundLibrary`** (`:core:domain`, `BundledSoundLibrary` in `:platform:services`): `starterSounds()` reads the manifest once per run into `CatalogSound`s (permanent catalog id, title in every app language as `LocalizedText`, length, credit = the license's attribution or else its type, "CC0"); `fileOf(sound)` writes the sound to `files/sounds/<catalog id>.m4a` the first time it's needed in a run (`MediaFiles.write`: temporary name, synced, renamed) and returns a `MediaRef` with `CatalogItem(id)` as its origin. That file is shared by every project, sits outside `media/` so the leftover cleanup never touches it, and is left out of backups (`sounds` in both backup rule files): the app writes it again from itself. `PrepareSoundUseCase` checks it with `MediaInspector` and uses the measured length, so trims and the end rule match the file that plays; a sound that doesn't decode is "That sound won't play".
- **Titles on the timeline:** a project keeps only the catalog id; the editor labels each sound with the pack's title by id, in the app's language (`ItemLabel.SoundTitle`, resolved with `LocalLocale` where it's drawn and spoken). No schema change, and a later catalog fix reaches old drafts.
- **Sheet previews:** `VideoEngine.openSoundPlayer()` → `SoundPlayer` (Android: one ExoPlayer, media audio focus, stops on noisy and on focus loss instead of resuming), opened on the first play and closed with the editor. One sound at a time; the editor stays paused.
- **Edits** (`:core:domain` → `project/SoundEdits.kt`, `MoveEdits.kt`): `addSound` lands the whole file at 100% at the playhead, or, with the playhead within one frame of the end, so it ends at the end (`startAtPlayhead`); on the first meme-sound lane free for its whole length, else a new lane right after the last one. `moveItem(itemId, startUs, LaneTarget, newTrackId)` moves any item but a main clip: never before 0:00, on the lane it's dropped on (`LaneTarget.Lane`; a lane of another kind counts as its own) or a new one (`NewLane`, the add row); if it would overlap there it goes to the next free lane of its kind, else a new one; a lane it empties goes in the same step; a drop where it was changes nothing. `moveItemToPlayhead` is Move here (same end rule). `setVolume` holds 0–200% (`MAX_VOLUME`).
- **Analytics:** `sound_add {sound_id, tab: "starter", editor: "video"}` once per landing and `sound_preview {sound_id, tab: "starter"}` per play (`LogSoundEventsUseCase`). The landing is an undo step ("Add sound", `EditorTool.ADD_SOUND`) with no `tool_use`, because `sound_add` counts it (the PM's `tool_use` ids have no add-sound value); Move and Volume log `tool_use` `move` and `volume`.
- **Volume heard live:** while the Volume slider moves, `PreviewSession.previewVolume(itemId, volume)` changes a `LiveGainProcessor` that every preview composition puts on each sound (a volatile gain the audio thread reads; clamps at full scale like Media3's `ChannelMixingAudioProcessor`), so the change is heard at once without a rebuild. The release commits one Volume step, which rebuilds as any edit does; export never has the live gain. Since P1-09 main clips playing their own sound get one too, and preview compositions keep items at 0% (`CompositionPlanner.plan(keepSilentItems = true)`) with no fixed volume step and the live gain at 0, so raising one from 0% is heard while the slider moves; export plans still leave them out.
- **Sync measure (P1-08 Done when):** in builds with hand checks (Koin property `memix.handChecks`), every preview composition carries `SoundOnsetLog`, a pass-through audio processor on the whole mix. Media3 1.11.1 flushes composition audio processors with the seek position (`AudioGraph.flush` → `StreamMetadata.positionOffsetUs`, read in the tagged source), so each sample's timeline time is that position plus the samples since; after at least 50 ms of silence, the first sample over −40 dBFS logs `Sound onset: heard at T, placed at S, off by D` under `MemixPreview`, against the nearest sound start in the plan. It measures where the sound sits in the mixed audio, which Media3 then shows video frames against; the phone's own output delay is the owner's ear check. The export is measured from the file (`--ez memix.exportLatestDraft true` exports the draft edited last and logs where each sound starts; then `ffmpeg`/`ffprobe` on a computer). Steps: `docs/qa/phase-1/engineer-hand-checks.md` → P1-08.
- **iOS (P7):** `SoundPlayer` plays nothing and `MediaFiles.write` fails, so a sound "won't play"; the bundled files already reach the iOS framework through Compose resources.

## Original audio (P1-09)

The sound recorded in the user's own videos. Screens and copy: `docs/ux/specs/P1-06-clip-edits-and-audio.md` → Original audio, Clip tool bar, Volume panel; `P1-05-timeline.md` → Leading area.

- **Model:** no new fields and no schema change. "Mute every clip" is `Track.muted` on the main track; a clip's level is `MediaClip.volume`; a detached clip has `audioDetached = true` and its sound is an `AudioClip` on an `AUDIO` lane pointing at the same file.
- **Edits** (`:core:domain` → `project/OriginalAudioEdits.kt`): `setOriginalMuted(muted)`; `originalSoundOf(itemId)` says whether a main clip's own sound `PLAYS`, is `NONE` (a photo, or a video with `hasAudio == false`) or is `DETACHED`; `hasOriginalAudio()` is true while any main clip's sound plays when unmuted (the toggle shows only then); `detachAudio(itemId, audioClipId, newTrackId)` adds an `AudioClip` with the clip's source, trims and volume at the clip's start (0% while every clip is muted, so nothing gets louder) on the first Audio lane free for that span, else a new lane, and sets `audioDetached`. Each is one undo step ("Mute original audio", "Unmute original audio", "Detach audio"); there's no re-attach but Undo.
- **Editor:** `OriginalAudioControl` (behind `EditorHost`) flips the mute without pausing playback and runs Detach audio: the new clip is selected and bonks (no haptic: that's for meme sounds) and is announced, or, detached while muted, the stage explains it starts at 0%. Volume and Detach audio on a video with no sound or an already detached clip explain instead; photos have neither tool. Detach audio on a clip whose file is missing shows the missing-file toast and changes nothing (the screen passes `fileMissing` from the thumbnails' missing sources; a detached clip of a missing file would play nothing and outlive the Replace that fixes it, P1-09 review M2). Duplicating a detached clip gives the copy its own sound back at 0% (`audioDetached` false, volume 0, the Replace rule; Split keeps both pieces detached, P1-09 review P1). `VolumePanelControl` opens "This clip" for a video clip with the "Mute original audio of every clip" toggle row under the slider.
- **Toggle:** `OriginalAudioToggle`, a real composable in the timeline's leading area: a `track-height-video` square, its right edge `space-2` before 0:00 in the main row, inside a 48 dp target, placed from the playhead time and zoom at placement (moves without recomposing) and clipped below the ruler. A screen-reader switch "Original audio", read right after the playhead (`traversalIndex`). Hidden in reorder mode, while a trim or move is held, when `hasOriginalAudio()` is false, and while the selected main clip starts less than `touch-target` after 0:00, because that clip's start handle target reaches over it (P1-09 review, M1; zoom read in `derivedStateOf`, as for the Add media tile).
- **Engine:** unchanged mapping (a muted track or a detached clip plays no clip sound; the detached `AudioClip` plays the same file span once), so detaching never doubles or shifts the sound. Clip volume is heard live through the clip's `LiveGainProcessor` (Meme sounds → Volume heard live).
- **Analytics:** `tool_use` `mute_original` and `unmute_original` per flip (toggle or panel row), `detach_audio` per detach, `volume` per release; nothing for an explanation.

## Captions (P1-10)

- **Content in one place:** `CaptionCatalog` (`:core:model`): the five fonts (ids `anton`, `poppins`, `baloo2`, `kalam`, `rozha`, saved in drafts and never renamed; Classic draws Devanagari in Teko Bold), the ten-color palette, the default style (Classic, white, black outline) and the geometry (font size 8% of the canvas's shorter side, wrap at 90%, outline = size ÷ 12 with round joins under the fill, scale 25–500%, 250 characters). - **Live editing:** typing, gestures and held Position arrows change only the stand-in, never the project; each commit (Done, release, a panel tap) is one undo step and one `PreviewSession.update`. While a caption is edited, `PreviewSession.hideCaption(itemId)` leaves it out of the paused frame without a rebuild (a seek to the same position redraws the frame through the overlay; each composition has its own hide switch, and `update` starts the next one with nothing hidden). After a commit the editor keeps drawing the stand-in until the preview has caught up (`VideoEditorUiState.captionStandIn`, cleared once `isCatchingUp` has come and gone, or after 2 s), so nothing jumps or flashes.

Style and Position panels (`captions/TextPanels.kt`, ToolPanels behind `coveredByModal`); text tools Edit text · Style · Position · Delete · Split · Move here · Duplicate. The stage (`captions/CaptionLayer.kt`, `CaptionGestures.kt`) draws the two-tone frame, the handle, snap guides and the value bubble, and handles tap, drag, pinch and the handle inside the stage's own tap (touches off captions still play or pause). - **Analytics:** `tool_use` `add_text` and `text_font` with `font` (the font id), `edit_text`, `text_color`, `text_outline`, `position_text`, `transform_text`, and P1-06's ids on text; a caption cleared to blank logs `delete`.

## Canvas (P1-11)

The meme's shape and what fills the space a clip doesn't cover. Screens and copy: `docs/ux/specs/P1-11-canvas.md`; the fixed rules: its Ratio change and Rendering rules sections and `design/tokens.json` → `canvas`.

- **Rules in one place:** `CanvasCatalog` (`:core:model`, next to `CaptionCatalog`): the preset sizes (shorter side 1080 px: 9:16 1080 × 1920, 1:1, 4:5 1080 × 1350, 3:4 1080 × 1440, 16:9 1920 × 1080), the custom rule (`customSize`: w:h in lowest terms, `w·k × h·k` with k the even number nearest 1080 ÷ min(w, h), so both sides are even and the ratio exact; terms 1–99, long side at most 2.39 × the short), the blur sigma (3% of the output's shorter side), the layer margin (2%) and the same-shape tolerance (1%). `RatioTerms` reduces and prints ratios ("5:8"); ratios are never translated. No new model fields and no schema bump: `Canvas.ratio`, `widthPx`, `heightPx`, `background` (`Solid` or `Blur`) and `MediaClip.fit` already hold everything.
- **Edits** (`:core:domain` → `project/CanvasEdits.kt`): `setCanvasRatio(ratio, customTerms, measure)` returns a `CanvasRatioChange(project, movedLayers)`: the new size and, in the same step, every caption that was fully inside the old frame kept fully inside the new one (its laid-out block from the caption renderer, outline included, scaled and turned; crossing an edge it shrinks first if it's bigger than the frame less two margins, never below 25%, then moves straight in to the 2% margin; still too big at 25% it's centered on that axis). A caption the user hung off the edge keeps its place. `setClipsFit(fit)` sets every main clip; `setCanvasBackground`; `sharedClipsFit()` (null when mixed); `backgroundShows()` (false when every main clip is Fill or has the canvas's shape within 1%). Add media gives new clips the shared fit (Fit when mixed); Replace, Split and Duplicate keep a clip's own fit. Opening a draft now also measures photos and videos saved without a picture size (`OpenVideoDraftUseCase`), so older drafts get their background too.
- **In the engine** (`CanvasFraming`, androidMain; arithmetic in commonMain `CanvasGeometry.kt`): every main clip is drawn into one frame size, the canvas's shape (`frameSizeOf`: the canvas, or a lower resolution with both sides even). Fill: `Presentation` `LAYOUT_SCALE_TO_FIT_WITH_CROP`. Fit: `LAYOUT_SCALE_TO_FIT`, or `LAYOUT_STRETCH_TO_FIT` for a clip within 1% of the canvas's shape (no hairline bars). Color background: two `BitmapOverlay`s of a 1 × 1 bitmap scaled to the bars' size, anchored on the frame's edges (Presentation leaves alpha 0 there, which shows as black for a black background, so black needs none). Blur: `Presentation` to the fitted size → `GaussianBlurWithFrameOverlaid(sigma · s, s, s)` with s = fit scale ÷ fill scale → `Presentation` `FIT_WITH_CROP` at the frame size. Media3 stretches the input over the whole output and blurs it, then draws the input sharp at scale s; a uniform s makes the stretched copy exactly the Fill copy once cropped, and a sigma in input pixels comes out at 3% of the frame's short side. Gaps and missing clips are gaps: black whatever the background. A clip of unknown size is fitted with nothing around it. The preview draws at a 720 shorter side while Blur is on (the blur costs per drawn pixel; the stage shows the frame smaller than that on a phone); exports draw at the chosen resolution.
- **Preview frame:** `PreviewPlayback.shownCanvasSize` is the canvas size of the picture on screen. After a ratio change the stage frame changes shape at once and shows the background color (black for Blur) until the first frame at the new size (`VideoEditorUiState.pictureOutOfShape`), never a stretched picture; other edits keep the last frame (P1-06). Every canvas choice is a rebuild (R1).
- **Editor:** the ratio pill (`SettingPill`, top bar center) opens the Canvas panel (`canvas/CanvasPanel.kt`, a ToolPanel behind `coveredByModal`, run by `CanvasPanelControl` behind `EditorHost`): six `OptionTile`s (presets drawn as their own shape with `RatioShape`, then Custom), Width and Height steppers for Custom (`RepeatingButton`, shared with the Position panel: the readout and pill follow a held stepper, one "Ratio" step on release; the numbers stay as stepped for the visit), Fit and Fill, and the Blur plus palette swatches. Choices don't pause playback. The frame edge (`text-muted` hairline just outside the frame) shows while the panel is open or a caption gesture runs; with the panel open, stage taps play or pause, even over a caption. In reorder mode the pill explains.
- **Analytics:** `tool_use` `canvas_ratio` (`value` `9:16` … `16:9` or `custom`), `canvas_fit` (`fit` or `fill`) and `canvas_background` (`blur` or `color`), once per committed step (owner, 21 Oct: the optional `value`). `EditorTool.CANVAS_FILL` logs as `canvas_fit`, so undo can say "Fill".

## Export (P1-12)

Screens, copy and states: `docs/ux/specs/P1-12-export.md`. The encoder, foreground-service, gallery and notification facts it builds on, checked against Media3 1.11.1 source and the Android docs: `docs/research/P1-12-encoder-facts.md`.

- **Use cases** (`:core:domain` → `video/`): `GetExportCapabilitiesUseCase`, `ExportSheetFactsUseCase` (remembered choice, learned speed, free bytes), `ExportVideoUseCase`, `ExportNotificationPermissionUseCase`, `RecoverUnfinishedExportUseCase`, `OpenResultPlayerUseCase`, and `share/ShareVideoUseCase`. Features call only these.
- **One export at a time:** `ExportVideoUseCase` is a Koin single in the app's scope. It outlives every screen: the Exporting screen, the editor (the "Export stopped." toast after a cancel) and the notification all read its `state` (`Idle | Running | Done | Failed | Cancelled`). The draft is copied into the job at the tap, so the file matches what the user saw. Progress reaches the screen about ten times a second and the notification, the saved percent and the learned speed once a second.
- **Capabilities** (`ExportCapabilityScanner`, androidMain): for each resolution (480p to 4K, the canvas's shorter side) and frame rate, the first of H.264 on hardware, HEVC on hardware, H.264 on any encoder (an emulator has only that) whose encoder takes the size aligned to its width and height alignment, checked with the long side as width (Transformer encodes portrait turned) through `EncoderUtil.isSizeSupported` and `areSizeAndRateSupported`; the bitrate is clamped to the encoder's range. The same scan at 1920 × 1080 tells "the phone can't" from "this shape can't". The answer is cached per canvas size; the first scan runs off the main thread and the editor warms it when it opens. Export runs with format fallback off, so a refused size fails with 4003 instead of exporting smaller.
- **Bitrates and estimate:** VBR (`VideoEncoderSettings.setBitrate`, `BITRATE_MODE_VBR`) at the spec's table (`requestedVideoBitrateBps`); the size shown is an upper bound, (video + 128 kbps audio) × length × 1.05. The time is length × a first-run factor until this phone has exported once, then its measured seconds per megapixel-second for the resolution group (`SpeedGroup`), saved after each export. Each export logs the estimate, the requested and the encoder's average bitrate and the file size (logcat tag `MemixVideoEngine`).
- **Gallery write** (`GalleryVideoFile`, androidMain): a MediaStore item in `Movies/Memix`, inserted with `IS_PENDING = 1`, named `Memix_<yyyyMMdd_HHmmss>.mp4`, written straight through its file descriptor by a custom `Muxer.Factory` (Transformer takes only a path). The muxer is `Mp4Muxer` plus the two things `InAppMp4Muxer` does and whose constructor is private: `Mp4OrientationData(format.rotationDegrees)` on the video track (without it every portrait export plays sideways) and only supported metadata. Checked against the 1.11.1 `InAppMp4Muxer` source on 22 Oct. `GalleryVideoFile.WRITES_STRAIGHT_TO_GALLERY` is the one switch: false writes a temporary file and copies it in, and the sheet then asks for 2 × the estimate + 100 MB instead of 1 ×. Not verified on a device: that the descriptor seeks on Android 10 (no FUSE) and 11+; engineer hand checks → P1-12 F. Finished: `IS_PENDING = 0`; failed, cancelled or stopped: the item is deleted.
- **Foreground service** (`:platform:services` androidMain, `AndroidExportForeground` + `ExportForegroundService`): started from the Export video tap while the app is visible; type `mediaProcessing` on Android 15+ through `Service.startForeground` (androidx `ServiceCompat` 1.19.1 masks it out), `dataSync` on 10 to 14. The notification (channel "Exports", low importance) carries progress and a Cancel action, which also makes Android 12+ show it at once. The notification for how it ended (saved, failed, stopped) is left only when Memix isn't in front, because the screen already says it. `onTimeout` ends the export as `system_stopped`. A refused start shows "Android stopped the export". The service does no work itself; the export runs on the engine's thread.
- **Stopped mid-export:** while an export runs, the project id and whole percent are saved (`ExportPreferences.unfinishedExport`, multiplatform-settings, once a second). At the next start `RecoverUnfinishedExportUseCase` deletes the pending gallery item, logs `export_cancel` with that percent when `AppExitReasons` says the user stopped Memix (`ApplicationExitInfo.REASON_USER_REQUESTED`, API 30+) and `export_fail` `process_death` otherwise, and the first screen shows the "last export didn't finish" toast with Open draft. Android 10 has no exit records, so there it counts as `process_death`.
- **Settings:** `ExportPreferences` in `:core:data` (`SettingsExportPreferences` over multiplatform-settings; the composition root creates `Settings`: SharedPreferences on Android, NSUserDefaults on iOS): last resolution and frame rate (app-wide), "notification permission asked", learned speeds, the unfinished record. Watermark-free is never stored (P1-13).
- **Editor side:** `ExportSheetControl` behind `EditorHost` keeps the sheet's `ExportSheetUi` (choice, codec, estimate, notices); the tap rules (the tapped option wins, the other steps down, with a toast) are pure functions in `ExportOptions.kt` (`tapResolution`, `tapFrameRate`). Export video starts the export and sets `openExportScreen`; the composition root pushes `ExportRoute` and tells the editor.
- **Exporting and Exported screens** (`:feature:export`): `ExportViewModel` follows the use case's state; the frame is the first main clip's first frame from the thumbnail reader, placed as it sits on the canvas. Back while exporting opens "Stop exporting?". The Exported screen's player is a `ResultPlayer` (`openResultPlayer`, ExoPlayer prepared paused; plays once, back to the start at the end) drawn by `VideoResultSurface` (Media3 `PlayerSurface` on a TextureView, so its corners round and it fades with the screen). Share: `ShareVideoUseCase` → `Sharer` (`ACTION_SEND`, `video/mp4`, the content URI, `ClipData` for the read grant, in a chooser). The interstitial hook (P5-03) is `ExportViewModel.showResult`, the one place between Exporting and Exported.
- **Large font and Free up space (design review):** the three screens share `PictureScreen`, a custom `Layout` whose picture takes what the title and the rest leave but never less than 30% (Exporting, failure) or 40% (Exported) of the screen's height, inside one `verticalScroll`, so no button is cut at 200%. Free up space passes `StorageManager.EXTRA_REQUESTED_BYTES` the **total** the export needs free (`ExportSheetUi.spaceNeededBytes`; `ExportPhase.Failed.spaceNeededBytes` after a full disk), never the missing amount, which Android would find already available. The editor's top bar is a custom `Layout` that keeps the ratio pill centered and clear of Close and Export.
- **Notification permission:** `POST_NOTIFICATIONS` is asked once, on Android 13+, right after the first Exporting screen appears (`rememberNotificationPermissionRequest`); the export never waits for the answer, and the flag is saved whatever it is.
- **Reopening:** when Memix is opened while an export runs or ended while it was away, `ReopenRunningExport` (composition root) pushes the editor and the Exporting screen back.
- **Analytics:** `export_start`, `export_complete`, `export_fail` (`ExportError.eventValue`), `export_cancel` and `share_target` (`more`) as in the spec; `ExportError` is mapped from Media3's code groups in `exportErrorOf` (2xxx input I/O, 3xxx decoding, 4xxx and 7xxx encoding and muxing, ENOSPC anywhere in the cause chain).
- **iOS:** compiles with stubs: `exportCapabilities` is empty (the sheet says so), `ExportForeground.start` refuses, `Sharer` and `ResultPlayer` do nothing (`TODO(P7-05)`, `TODO(P7-09)`).
- **Watermark (P1-13):** the constants are `WatermarkCatalog` (`:core:model`, next to `CaptionCatalog` and `CanvasCatalog`; mirrors `design/tokens.json` → `watermark`): "Memix" in Anton, font size 4% of the output's shorter side, ink box 3% from the left and from the top (two separate constants, so the owner's phase-end TikTok test moves the top with one value), white at 80%, black 50% shadow with no offset and a blur of 15% of the font size. `WatermarkOverlay` (androidMain) is a `CanvasOverlay` drawn with the caption renderer's Anton (`AndroidCaptionRenderer.typefaceOf`), measured with `Paint.getTextBounds` so the margins reach the glyphs' ink, and drawn once per frame size. It goes last in the same `OverlayEffect` as the captions (Media3: the last overlay in the list is on top). Only `ExportSettings.watermark` (default true) adds it to an export; previews never do, and nothing is saved in a draft or remembered, so a value change needs no schema bump. The debug hook's `--ez memix.exportWatermarkFree true` turns it off for one export. The sheet's row is information only (P5-02 adds Remove).
- **Play Console (P1-15):** the manifest declares `FOREGROUND_SERVICE_DATA_SYNC` and `FOREGROUND_SERVICE_MEDIA_PROCESSING`, so Play asks for a declaration for each type (description, what happens to the user if the task is interrupted, a link to a screen video of Export) before a release that contains the service. The owner fills it once, step 4 of `/play-release`; the Console form itself wasn't readable from a cloud session (support.google.com is blocked), so the step was written from secondary sources and the owner reads the form.

## Video engine

One shared interface renders a `Project`; each platform implements it with its native framework, so decoding, effects and encoding run on the phone's video hardware.

```kotlin

interface VideoEngine {

    fun openSoundPlayer(): SoundPlayer                           // P1-08: the sounds sheet's previews; the caller closes it

    // suspend fun waveform(source: AudioRef, buckets: Int): FloatArray                     P3-09
}
```

**Android (v1): Media3.** The engine maps a project to a Media3 `Composition`. The main video track becomes one `EditedMediaItemSequence`; overlays, meme sounds, audio and voiceover become further sequences that overlap in time, which Media3 supports for layering ([Media3 Composition](https://developer.android.com/media/media3/transformer/composition)). `CompositionPlayer` drives the preview and `Transformer` exports ([multi-asset editing](https://developer.android.com/media/media3/transformer/multi-asset)).

**Project to composition (P1-03).** `CompositionPlanner` (`:engine:video` commonMain) turns a `Project` into a `CompositionPlan`: plain data in µs that both platforms build from, so the mapping rules live in one place. `Media3CompositionBuilder` (androidMain) translates the plan; P7 adds the AVFoundation translation.

- **Main video sequence:** the `MediaClip`s of the `MAIN_VIDEO` track in start-time order, with a gap (black, silent) for empty time. A clip that starts before 0 or before the previous clip ends makes the project unplayable (export fails with `Unexpected`; the editor never produces it). The export is as long as the main track.
- **Background picture (P2-12):** `CanvasBackground.Image(source)` (schema 4, `ProjectMigration(fromVersion = 3)` version-only; `Project.mediaCopyPaths()` and `withMediaCopyPaths()` include it, so the cleaner keeps the file and a duplicate gets its own). The plan carries `PlanBackground.Image`; `CanvasFraming` draws the picture only where a Fit clip leaves bars: `BackgroundBars` decodes the picture once per build with `ImageDecoder` (EXIF applied, target size = `coveredImageSize` of the frame, `setCrop` to the centered frame rectangle, software allocator for the GL upload), cuts out each bar's rectangle, and each bar is a `BitmapOverlay` anchored on the frame's edge at the bar's exact thickness (the same arithmetic as the color bars). A missing or undecodable file leaves the bars black, as a gap is. The builder runs off the main thread in the preview (`prepare`) and in the export (`withContext(io)`). The preview size is unchanged (a still, no per-pixel blur). 4K memory: the covered picture plus its bar copies, about two frames' worth (about 66 MB at 2160 × 3840); not measured on a device.
- **Clips:** trims in µs (`ClippingConfiguration`); photos show for their duration (Media3 takes whole milliseconds) at the export frame rate; `FIT` and `FILL` and the background around fitted clips follow the canvas rules (Canvas section above, `CanvasFraming`).
- **Clip audio:** plays unless the clip is a photo, its audio is detached, the main track is muted or its volume is 0 (a preview keeps a 0% clip in, silenced by its live gain, P1-09). Volume is a `ChannelMixingAudioProcessor`, which clamps instead of wrapping when the volume is above 1.
- **Audio sequences:** each unmuted `MEME_SOUND` and `AUDIO` track becomes an audio-only sequence starting at 0, with gaps before and between sounds. Sounds that overlap on one track spill into an extra sequence so both play. Sounds are cut at the main video's end, because Media3 ends a composition with its longest sequence. A detached clip's audio is an `AudioClip` on an audio track pointing at the video file (its picture isn't decoded). Volume-0 sounds are left out of exports (a preview keeps them, silenced by their live gain, P1-09).
- **Captions:** composition-level `CaptionOverlay` (Captions section above).
- **Not rendered yet:** overlay (P4-01), sticker (P4-12) and effect (P4-06) tracks are skipped with one log line each (logcat tag `MemixVideoEngine`).
- **Export:** Transformer on its own `HandlerThread` per export; H.264 video and AAC audio in MP4; HDR sources are tone-mapped to SDR with OpenGL; a portrait canvas is encoded landscape with a rotation flag (Media3's default, the widest encoder support). The user's exports go to the gallery (Export section below); only the debug export hook still writes `cache/exports/`. A failed or cancelled export deletes its file. Progress is polled every 100 ms.
- **Media files:** the app's copy (`cachedCopyPath`, relative to the files directory) first; a gallery URI only when there's no copy. A missing copy, an iOS `PhotoAsset` or a catalog item that isn't downloaded fails with `NotFound`.
- **Clip sound:** a video whose `MediaRef.hasAudio` is `false` (measured at import: no sound this phone can decode) is left silent, in export and preview alike. Media saved before schema 2 (`null`) still plays its sound; Media3 fills a missing sound track with silence.
- **Source lengths:** `Media3CompositionBuilder` sets each video and sound item's `EditedMediaItem.setDurationUs` from `MediaRef.durationUs`, at least the trim end (Media3 checks the trim lies inside it). `CompositionPlayer` needs it; Transformer reads the file when it's missing.

**Preview (P1-04).** `Media3PreviewSession` (androidMain) plays the project with Media3's `CompositionPlayer`, from the same plan and the same builder as the export, so the editor shows what will export.

- **Threads:** planning, the file checks and building the `Composition` run on IO; the player lives on the main thread (Media3 requires one thread). A newer `update` cancels a build still running, so quick edits render only the last project.
- **Player lifetime:** created when the first composition is ready (in Media3 1.11.1 a player released before it ever got a composition keeps its playback thread running), released by `close()`. `seekTo` before the first composition only moves the start position.
- **Edits:** `update(project)` calls `setComposition(new, position)`, which in Media3 1.11.1 rebuilds every sequence player (no incremental update yet), keeping the position (clamped to the new length) and play or pause. How long that takes on the owner's phone is P1-04 review R1, measured at phase-end QA. Version check (13 Oct 2026, Google Maven): 1.11.1 is the newest androidx.media3 release, with no 1.12 alpha or beta, so no newer stable offers a cheaper update and the rebuild-per-edit risk stands until a later release.
- **No black or gray frame after an edit (P1-06):** the stage keeps its last frame until the edited project's first frame replaces it. From Media3 1.11.1's source: once prepared, `CompositionPlayer.prepareCompositionPlayerInternal()` only replaces the audio graph, so the `PlaybackVideoGraphWrapper` that draws into the `SurfaceView` survives; the old sequence players' video renderers detach from that graph in `onDisabled()` before they're released (video prewarming, on by default), so releasing them never releases it; `maybeSetVideoOutput()` re-sets the same surface, which `PlaybackVideoGraphWrapper.setOutputSurfaceInfo` ignores (same surface and size). Nothing draws to the surface until the new first frame, and a `SurfaceView` keeps its last buffer meanwhile. The new stream's seek resets the release control, so `onRenderedFirstFrame` fires again: `PreviewPlayback.isCatchingUp` is true from the `update` until that frame (or a failure, or 5 s without a report). The editor's stage cover depends only on the first frame ever shown, so it never covers an edit. The editor shows "Updating the preview" when catching up passes 1 s.
- **Trim frames (P1-06):** while a trim handle of a video or photo clip is dragged, `showTrimFrame(clip, sourceTimeUs)` sets a one-clip composition of that clip's whole source (from 0:00, silent, framed like the project) once per drag, with scrubbing mode on; every later drag frame is a seek in it. `positionUs` keeps the project's time, and a seek or Play meant for the project waits for its composition. `endTrimFrames()` brings the project back at `positionUs`; the editor commits the trim just before it (P8), and both land in one build (`combine` + `collectLatest`), so a trim costs one rebuild at the drag's start and one at its release, never one per frame. Sounds and captions don't change the preview while trimmed.
- **Missing media:** a clip whose file is missing, or whose length isn't known (a copy that can't be read), becomes a gap: black and silent on the main sequence, silent in its lane, and lanes left silent are dropped (`CompositionPlan.withGapsFor`, shared). `missingMedia` tells the editor to say so once. A project the planner refuses (overlapping main clips) ends in `FAILED`.
- **Playback rules:** audio focus with `USAGE_MEDIA` (Media3 pauses for calls and other apps; a transient loss pauses for good instead of resuming by itself); `ACTION_AUDIO_BECOMING_NOISY` (headphones unplugged) pauses, registered only while playing; the end stops on the last frame with the time at the full length. Play from the end (within one frame) restarts at 0 (the editor's rule). The position is published every display frame from a `Choreographer` callback while playing.
- **Surface:** `VideoPreviewSurface(session, modifier)` in `:engine:video` (Compose; media3-ui-compose 1.11.1 `PlayerSurface`, a `SurfaceView`, which `CompositionPlayer` requires; it includes Media3's Android 14 resize fix). Features can't depend on the engine, so the composition root passes it to `VideoEditorScreen` as a slot. The editor draws its covers (empty frame, error) over it.
- **Measuring:** each stretch of playback logs one line under `MemixPreview`: video time played, wall time, frames the decoder put on screen and frames dropped (Media3's `DecoderCounters`). Media3's own `EventLogger` lines (`CompositionPlayer…`) also report `droppedFrames`. The P1-04 frame-rate check reads these on a `benchmark` build. `ShowTimingLog` adds one line per new composition: `Preview opened in N ms (build B ms, first frame F ms)` from `createPreview`, and `Edit shown in N ms (rebuild R ms, first frame F ms)` from each `update(project)` that changes the project, to the player's next rendered first frame (or a "no first frame reported" line after 5 s). It times P1-04 review R1 (every edit rebuilds the players) against P1-06's 100 ms.
- **Scrubbing (P1-05):** while the timeline is dragged or flung, the editor pauses, calls `setScrubbing(true)` and seeks on every frame; Media3's scrubbing mode (`CompositionPlayer.setScrubbingModeEnabled`, 1.11.1) keeps the decoders warm and may show the nearest fast frame. When the timeline stops, `setScrubbing(false)` and one exact `seekTo`. `seekTo` clamps to the newest project's length even before its composition is ready.
- **Opening a draft:** `OpenVideoDraftUseCase` loads it and, for media saved before schema 2, reads the missing length and has-sound from the app's copy (`MediaInspector`, which also measures sound files since P1-04). The draft isn't saved for this; the facts go in with the next edit.
- **iOS:** `createPreview` returns a session that reports `FAILED` until P7-03, and the surface draws nothing. `openThumbnails` returns a reader whose every picture fails (tiles stay `track-video`) until P7-03.

**Thumbnails (P1-05).** `MediaThumbnailReader` (androidMain) reads the app's copy of each file: video frames with `MediaMetadataRetriever.getScaledFrameAtTime(OPTION_CLOSEST, RGB_565)` (the platform's hardware decoders, the frame's rotation applied, scaled so its short side is the tile), photos with `ImageDecoder` at a power-of-two sample size (EXIF orientation applied); each is center-cropped to a square and encoded as JPEG (quality 85, a few KB). One worker (`ioDispatcher.limitedParallelism(1)`) does everything, one picture at a time, so the preview's decoders plus this one stay inside every phone's codec limit; the two most recently used videos stay open. A missing file is `NotFound`, a damaged one `Unexpected`. Media3's `FrameExtractor` was not used: in 1.11.1 it moved to the separate `media3-inspector-frame` artifact, is `@UnstableApi`, and defaults to software decoders and a GL pipeline.

**Clip edits (P1-06).** `:core:domain` → `project/TimelineEdits.kt`: `splitItem`, `trimItem` (+ `trimRange` for the drag), `deleteItem`, `duplicateItem`, `reorderMainClips` and `moveMainClip`, with `canSplit` and `canDelete` for the explanations. Each returns a new `Project`; one that can't apply returns the same project, which the edit session records as no step. Rules: nothing is shorter than 0.1 s (`MIN_ITEM_DURATION_US`); the main video track is re-packed gap-free from 0:00 after every main-track edit, in its clips' order from before the edit; other tracks keep absolute times (owner, 8 Oct 2026) and an emptied one is removed in the same step; videos and sounds stop at their source's start and end (a source of unknown length can only get shorter), photos have no limit and keep a 0-based trim; on other tracks a neighbor is a hard stop and nothing starts before 0:00; a duplicate goes right after the original, on its own track if that time is free, else the first free track of its kind, else a new one.

**Timeline (P1-05).** `:feature:video-editor` → `timeline/`. The editor's ViewModel turns each project into a `TimelineUi` (tracks in the spec's order, items sorted by start) and keeps the selection; the timeline keeps its own playhead time and zoom (`TimelineState`), which only draw blocks, placement and gesture code read, so a scroll, pinch or playback frame redraws without recomposing the screen.
- **Drawing:** `TimelinePainter` draws the ruler, lanes, items, thumbnail strips, the selection and the playhead in three draw blocks, finding the items on screen by binary search on start time (`forEachItemBetween`). Text is measured once and cached (labels per item, re-measured in `space-2` steps only while a label is cut by the screen edge; ruler labels per time).
- **Gestures:** one Initial-pass detector sees every touch first (touch-down pauses; a two-finger pinch past the touch slop zooms around the playhead and consumes the gesture); a horizontal `scrollable` without overscroll moves time (and its fling); the lanes `verticalScroll`; taps and the ruler's long-press (zoom menu, opened with a `LongPress` haptic) are hit-tested from the same geometry the painter uses. The playhead follows the preview's `positionUs` except while the timeline itself moves time.
- **Thumbnails:** `TimelineThumbnails` (owned and closed by the ViewModel) asks the `ThumbnailReader` for the tiles of the screen plus one screen each side, nearest the playhead first (`TileWindow`, which only changes when the playhead crosses a tile or the zoom changes), drops a read that leaves the window, decodes JPEGs into `ImageBitmap`s on `Dispatchers.Default`, and keeps 16 MB of them (least recently wanted out first). Tile source times are rounded to power-of-two frame buckets, so a pinch mostly asks for frames already in memory; until a tile arrives the nearest one in memory stands in, and the exact one fades in over 120 ms.
- **Clip edits and tools (P1-06, P1-08, P1-16):** the tool bar (`ToolBar` in `:core:designsystem`) shows Edit, Meme sounds (blue) and Add media with nothing selected (only Add media in an empty project), else the selected item's tools (video clips: Split, Volume, Delete, Duplicate, Detach audio, Reorder, Replace; photo clips: Split, Delete, Duplicate, Reorder, Replace; Replace comes first when the clip's file is missing, known from the thumbnails' `missingSources`; meme sounds and detached audio: Volume, Split, Delete, Move here, Duplicate; captions: Delete, Split, Move here, Duplicate; other items: Split, Delete, Move here, Duplicate), cross-fading in 120 ms. The Volume panel (`ToolPanel`) covers exactly the timeline and tool bar (`VideoEditorScreen`'s `EditorLayout` measures it into that region), and the Meme sounds sheet opens at half the window and grows when dragged up (`Sheet(opensAtHalfHeight)`). Each tool pauses playback, commits one step through `VideoEditorViewModel.commit`, which shows the edited timeline at once (the preview catches up), and announces it ("Delete: clip 2", spoken only). Tool areas with their own state live in helpers that reach the editor through one `EditorHost` port: `EditorSoundTools` (the sheet, previews, landing), `VolumePanelControl`, `MoveControl`, `OriginalAudioControl` (P1-09: the mute toggle and Detach audio), and `EditorMediaImport` (Add media and Replace). A tool that can't act explains with a toast. The edits are pure functions in `:core:domain` (`TimelineEdits.kt`, below).
- **Trim:** the selected item's handles take a touch before the scroll does (an Initial-pass detector, `detectTrimDrag`); the dragged edge is a `TrimDrag` in `TimelineState`, read only in draw and gesture code, clamped to the domain's `trimRange` (passed in as `TrimRanges`), snapping within `space-2` to the playhead, 0:00, the end, main clip boundaries and other items' edges (one `SegmentTick` per snap or limit), with edge auto-scroll near the sides and a value bubble (no shadow, kept inside the timeline on both axes). Only the moving edge moves until the release commits one Trim step. The handles have screen-reader nodes ("Start of clip 3": one frame per step, Trim to playhead).
- **Reorder mode:** the Reorder tool, or a long-press on a main clip that goes on as a drag (`detectReorderGestures`), turns the main clips into first-frame tiles (`ReorderStrip`); the ViewModel owns the order (`ReorderUi`) until Done or the drop commits one Reorder step; back cancels. Only the strip's row takes touches; elsewhere a touch is taken and does nothing. Without a finger on it, the strip scrolls with each move so the moving tile stays at least `touch-target` from both sides. The playhead fades out with the wash. Tiles slide 200 ms when the order changes; entering and leaving morph between time and tiles in 200 ms (120 ms with reduce motion).
- **Edit motion:** after an edit moves main clips (trim, delete, duplicate, undo), they slide from their old places in 200 ms (`EditMotion`, read only in draw; no slide with reduce motion); items that land (a duplicate, P1-08 sounds, P1-16 added or replaced media) bonk together (`VideoEditorUiState.landed`, `LandedItems`): the height scales 1 → 1.12 → 1 over 240 ms and the width grows by the same pixels, at most by the same scale, so a long clip swells a few dp at each end rather than 12% of its width over its neighbors (P1-16 review, P5); with reduce motion they fade in over 120 ms.
- **Past the end while trimming (P1-06 review, P8):** while a handle is held, edge auto-scroll may go past the end of the video as far as that handle's own limit (`TimelineState.scrollBy(endUs)` with `max(length, range.maxUs)`), so extending the last clip, or a photo, isn't capped by the screen; reaching the limit ticks. On release or cancel, a playhead past the video's length after the trim (the main track's length plus the dragged clip's change) slides back to it in 200 ms (`settleInside`), and the editor commits before it seeks the preview, so a playhead inside a newly extended end isn't clamped to the old one.
- **Known limits (P1-06 review follow-ups):** with reduce motion, Android shows the ripple, reorder morph and slides as instant changes (Compose scales animations by the system's animator duration scale); iOS's Reduce Motion doesn't shorten animations, so before P7 they must become the spec's 120 ms cross-fades (P9).
- **Accessibility:** the container has the zoom actions, the playhead is an adjustable node (one frame per step, plus ±1 s, start and end), the original-audio toggle is a switch read right after it (P1-09), and each track row is a screen-reader scroll container with a node per item on screen (the lazy-list pattern: Compose leaves off-screen nodes out of the tree), so every item is reachable at any scroll position. While a ToolPanel (the Volume panel) is open, the timeline and tool bar it covers are out of the accessibility tree and keyboard focus, and while any sheet is open the whole editor behind it is (`Modifier.coveredByModal` in `:core:designsystem`: `clearAndSetSemantics`, a `focusProperties` that refuses entry, a focus group). ## Photo rendering and background removal

The photo editor renders in shared Compose code, so it needs very little extra work on iOS. Export draws the same layer scene into a full-resolution offscreen bitmap, then a small platform encoder writes PNG, JPG, GIF or WebP.

## Backend

Supabase serves small JSON catalog lists and Cloudflare R2 serves every audio, image and video file. The live schema is the migrations in `supabase/migrations/` (project `memix`, ref `drnhpnixnewqjfmrchrr`, Singapore); the sketch below is the summary. There is no custom server code: the app reads tables through Supabase's auto-generated API with supabase-kt ([supabase-kt](https://github.com/supabase-community/supabase-kt)).

```sql
create extension if not exists pg_trgm;

create table categories (
  id text primary key,
  kind text not null check (kind in ('sound','sticker','template')),
  name jsonb not null,                 -- {"en": "Reactions", "id": "Reaksi", ...}
  sort int not null default 0,
  is_active boolean not null default true
);

-- Columns shared by every catalog item (sounds, templates, sticker_packs)
--   title jsonb, category_id text references categories(id),
--   regions text[] default '{global}', tags text[] default '{}',
--   source_url text not null, license_type text not null
--     check (license_type in ('CC0','CC-BY','royalty-free','own','licensed')),
--   license_proof text not null, credit text,
--   is_active boolean default true, added_by text,
--   created_at timestamptz default now(), updated_at timestamptz default now()

create table sounds (
  id uuid primary key default gen_random_uuid(),
  file_path text not null,             -- R2 key: sounds/<yyyy>/<mm>/<id>.m4a
  duration_ms int not null,
  waveform_path text
  -- + shared catalog columns
);

create table templates (
  id uuid primary key default gen_random_uuid(),
  kind text not null check (kind in ('video_overlay','video_cutout','video_preset','photo_format','photo_template')),
  preview_path text not null,
  asset_paths text[] not null,
  preset jsonb not null                -- slots, timings, sound cues, effects, text styles
  -- + shared catalog columns
);

create table sticker_packs (id uuid primary key default gen_random_uuid(), cover_path text not null /* + shared */);
create table stickers (id uuid primary key default gen_random_uuid(), pack_id uuid references sticker_packs(id),
  file_path text not null, animated boolean default false, sort int default 0);

create table trending (
  month date not null, region text not null,          -- ISO country code or 'global'
  kind text not null check (kind in ('sound','template')),
  item_id uuid not null, rank int not null,
  primary key (month, region, kind, rank)
);

create table reports (
  id uuid primary key default gen_random_uuid(),
  item_kind text not null, item_id uuid not null, reason text,
  status text not null default 'open', created_at timestamptz default now()
);

create index sounds_title_trgm on sounds using gin ((title::text) gin_trgm_ops);
create index sounds_tags on sounds using gin (tags);
-- search_sounds(q text, region text, lim int, off int): trigram match on title and tags, active rows only
```

- **Access rules (RLS):** the app's publishable key can read rows where `is_active = true` (stickers follow their pack; trending ranks are readable) and can insert into `reports` with `status = 'open'` and a reason of at most 500 characters. No reads of reports, no updates or deletes. A CC-BY item can't be saved without its credit (check constraint). All other writes happen in the Supabase dashboard; the service key never ships in the app.
- **Files:** one public R2 bucket behind a custom domain (`media.<domain>`). Keys are immutable: a changed file gets a new key, so files can be cached forever. The app joins `media_base_url` from Remote Config with each row's `file_path`.
- **On the phone:** SQLDelight caches catalog rows; downloaded files live in the cache directory with a 500 MB least-recently-used limit.

| Sounds page | `sounds?category_id=eq.X&regions=ov.{ID,global}&order=created_at.desc&limit=30&offset=N` | 6 h |

## CMS workflow

Until phase 4, the Supabase dashboard is the CMS and a desktop script does the file work. A small admin web page (bulk upload, waveform generation, trending editor) comes in phase 4, hosted separately from the app.

**Adding a sound**

1. Find a candidate: Freesound with the CC0 filter, Pixabay, or record your own recreation.
2. Save the license proof: the license page URL plus a screenshot.
3. Run the intake script: trims silence, normalizes to −16 LUFS with −1 dBTP peaks, encodes AAC 128 kbps `.m4a`, and writes a waveform JSON. Desktop tools such as ffmpeg are fine here because they never ship inside the app.
4. Upload the files to R2 under `sounds/<yyyy>/<mm>/<id>.m4a`.
5. Add the row in the Supabase table editor with every license field filled.
6. Check it in the app after the next catalog refresh.

Templates and sticker packs follow the same steps with their own folders (`templates/`, `stickers/`, `previews/`).

**Monthly trending:** on the 1st of each month, add `trending` rows per launch region and for `global`: 10 to 20 sounds and 5 to 10 templates each.

**Takedowns:** a report or email arrives, set the item's `is_active` to false, record the outcome on the `reports` row, and reply within 72 hours.

- **Release build (P1-15):** `release` is the variant the owner signs in Android Studio (Build → Generate Signed App Bundle) and uploads to Play (runbook: the `play-release` skill). What it contains and why:
  - **R8:** `isMinifyEnabled` and `isShrinkResources` on `release` with `getDefaultProguardFile("proguard-android-optimize.txt")` and `androidApp/proguard-rules.pro` (AGP 9.4's legacy DSL, which Google still supports; the new `optimization { enable = true }` block with `src/main/keepRules/*.keep` is the 9.3+ alternative). Library consumer rules do most of the work: kotlinx.serialization 1.11.0 keeps `Companion` and `serializer()` for the Project JSON and the type-safe routes, Media3 keeps what DefaultRenderersFactory and PlaybackVideoGraphWrapper create by reflection. The project file holds only `-keepattributes SourceFile,LineNumberTable` (readable Crashlytics traces) and its policy: a rule is added only after a failing release run shows the class, with the library or class named above it; no blanket `-keep class app.memix.**`, no blanket `-dontwarn`. The CI release step is the place to see a missing class or a missing rule.
  - **`benchmark` is minified** (it copies `release`), so QA's and the owner's phase-end speed numbers and device checks run on R8 code. It still has the hand-check hooks (`memix_hand_checks` is true in `src/benchmark`) and the debug key. The export hooks (`memix.exportCheck`, `exportLatestDraft`), `projectCheck` and the shared checks gated by `isDebugBuild` need a debuggable build and do nothing on `benchmark`; export on `benchmark` runs through the Export button. In `release` every hook is off: `memix_hand_checks` is false in `src/main`, and the hooks live in shared code that R8 can't remove, so that flag is the only gate.
  - **Version code:** `release` gets whole minutes since 1 Jan 2026 UTC (about 430,000 in Oct 2026; Play's limit is 2,100,000,000, reached in about 4,000 years), set in `androidComponents.onVariants` from a `ValueSource` so each release build asks the clock again and the configuration cache can't reuse an old number. Debug and benchmark keep `versionCode = 1` and keep Gradle's configuration cache. It is not the git commit count: the owner merges each phase PR, and a squash merge would make `main`'s count lower than the phase branch's, which Play would refuse. Two release builds in the same minute get the same number (the second upload is refused; build again); a wrong clock on the owner's Mac can lower it. `versionName` is bumped by hand in `androidApp/build.gradle.kts` at each phase end, by the engineer who prepares the build (`/play-release` preflight).
  - **Crashlytics mapping:** the Crashlytics Gradle plugin (3.0.8) uploads the R8 mapping after `minify<Variant>WithR8` for minified variants, and fails the build if the upload fails. `-Pmemix.mappingUpload=<release|all|none>` picks the variants: `release` (default; needs the Mac online and the real `google-services.json`), `all` (adds `benchmark`, for the one-time deobfuscation check), `none` (CI). `assembleDebug` never uploads: debug isn't minified. Play Console gets its own mapping from the bundle (`BUNDLE-METADATA`), nothing to upload by hand. To see deobfuscation work: `installBenchmark -Pmemix.mappingUpload=all`, start the app with `--ez memix.testCrash true` (it throws `MemixTestCrash`, a class R8 renames), start the app again so the report is sent; the console must read `app.memix.debug.MemixTestCrash`, not a one- or two-letter name.
  - **Signing:** no `signingConfigs` for `release`, no keystore path, no `keystore.properties` reader. The bundle that CI builds is unsigned and is never uploaded. The release build needs the same local `androidApp/google-services.json` as debug (gitignored; CI copies the placeholder).
  - **Language splits:** `bundle.language.enableSplit = false`, so Play delivers all five languages' Android resources (the export notification's strings in `:platform:services`) and not only the phone's system languages; people can pick another language for Memix alone (Android 13+). The cost is the translated strings of the libraries; the Compose Resources strings are in `assets/` and never split.

## Security and privacy

Memix keeps no user data on its servers: projects, imports and favorites stay on the phone.

- The app ships only the Supabase public (anon) key. Access rules limit it to reading active catalog rows and inserting reports.
