- 2026-10-08 · P1-04 · Media3 1.11.1 CompositionPlayer (read at the tag): `release()` before any `setComposition` returns early and never quits its playback HandlerThread -> create the player only when the first composition is ready. `seekTo` before `setComposition` NPEs. `setComposition(c, posMs)` rebuilds every sequence ExoPlayer (b/412585856) -> each edit is a re-prepare (P1-06 100 ms risk). After the first `prepare()` later compositions prepare themselves unless an error/stop left it IDLE. `EditedMediaItem` needs `setDurationUs` >= clip end (checkArgument). Transient focus loss = suppression that auto-resumes; pause on `PLAYBACK_SUPPRESSION_REASON_TRANSIENT_AUDIO_FOCUS_LOSS` to stay paused. No BECOMING_NOISY handling: own receiver, plain registerReceiver (protected broadcast). `onDroppedVideoFrames`/`onVideoEnabled(DecoderCounters)` are forwarded to `addAnalyticsListener`.

- 2026-10-08 · P1-03 · Media3 1.11.1 (read at the tag, not memory): `EditedMediaItemSequence.Builder(Set<trackType>)` is the API (vararg/List builders and `experimentalSetForce*Track` are deprecated). - 2026-10-08 · P1-01 · SQLDelight 2.4.1: no explicit transaction around a save. On SQLITE_FULL, SQLite rolls back by itself, SQLDelight's ROLLBACK in `finally` then throws "cannot rollback - no transaction is active", and that hides the disk-full error (seen with sqlite-jdbc; Android reports the same). Use one statement (`INSERT OR REPLACE` + subquery to keep columns). Android 10 = SQLite 3.22, so no UPSERT; keep the default 3.18 dialect.
