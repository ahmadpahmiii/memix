# Add a media effect

1. **Spec.** In `:core:model`, a serializable spec: stable `id` (e.g. `effect.zoom_punch`), typed params with defaults and ranges, a name string key. Data only.
2. **Registry.** Register it in the effect catalog (category, icon, default duration, intensity range) so UI lists come from data.
3. **Android.** Map the spec to Media3 effects in `:engine:video` androidMain (and `:engine:photo` if it applies to photos): built-in effects where they exist, otherwise a GLSL program; matrix transforms for motion (zoom punch, shake). Animate params over the item's time range in µs. Check current Media3 effect APIs first.
4. **Photo parity.** Filters share ids and LUTs/params between photo and video so looks match.
5. **iOS.** iosMain mapping (Core Image / Metal) or a clearly marked `TODO(P7-04)` stub that reports `UnsupportedEffect`, never a silent no-op.
6. **Audio effects** (fades, pitch, speed, echo, bass boost, voice presets): fields of `AudioEffects` in `:core:model` (added once, in the P3-09a schema bump), a stage in `AudioChain.effects` (`:engine:video` androidMain, in `AudioEffectsCatalog.CHAIN_ORDER`) that both preview and export build through `Media3CompositionBuilder`, `AVAudioMix` + processing on iOS (`TODO(P7-03)`). The reference render is a generated test tone through the chain, saved as WAV and plot under `docs/qa/references/<ticket>-audio-effects/` with measured pitch and length; the null test (preview chain against export chain, under -40 dB) and the harness that runs both on a JVM are described in the android-media-engine skill.
   P3-09b: voices are `VoiceRecipe`s (`VoiceRecipes.kt`), Bass/Distortion/Echo map through `AudioEffectsCatalog`; the limiter is the last stage (`LIMITER`) before the volume; reference renders in `docs/qa/references/P3-09b-audio-effects/` from the harness.
7. **Reference render.** Render the fixed sample project with the effect and save a frame (or short strip) to `docs/qa/references/<effect-id>.png`. QA and the iOS port compare against it by eye.
8. **Performance.** Preview still ≥ 30 fps at 1080p with 6 tracks on the reference phone; put the number in the PR.
9. **UI.** Listed in its tool with a thumbnail and an intensity slider; on the timeline it's an `EFFECT` item in `track-effect` violet.
- Masks (P4-03b) are specs on the clip (`ClipMask`) with a CPU twin (`MaskMath`) and references in `docs/qa/references/P4-03-masks/`; the shader mirrors the twin line by line.
- Video filters (P4-07) reuse the photo editor's specs and data (`FilterRef`, `ImageAdjust`, the 20 `.lut` files) through `ClipLook`; the GPU passes mirror `VideoLookMath` (CPU twin), which a harness compares with `ImagePipeline` (the photo path) for parity; references in `docs/qa/references/P4-07-video-filters/` show photo and video side by side.
- Video effects (P4-06): all 30 ids are in `EffectCatalog` (`:core:model`) from 06a, with `isBuilt` per effect, so a new effect is a shader in `EffectShaders` + its branch in `EffectsProgram.drawEffect`, its numbers and CPU twin branch in `EffectMath`, `isBuilt = true`, its name and description strings (`fx_name_<id>`, `fx_desc_<id>`) in five languages and a line in `EffectNames`, a reference render from the harness in `docs/qa/references/P4-06-effects/`, and **no schema bump**. `EffectMath` owns every number the shader reads; envelopes are `effectStrength`. Check each effect against the WCAG 2.3.1 luminance plot.
- Video effects, random or sampled (P4-06b): numbers and twins live in `GlitchMath`, `BlurMath`, `RetroMath` (`:core:domain` `image/`; `EffectMath.apply` dispatches), shaders in `GlitchShaders`, `BlurShaders`, `RetroShaders` (`:engine:video`), draw methods in `EffectsProgram`. **Randomness is `EffectNoise` only**: the hash of the frame's time rounded to 1/30 s (`frameIndex`) and a per-effect seed; GLSL ES 1.00 can't hash, so the shaders read the 256 x 256 noise texture (`EffectNoise.cell`) at a CPU-computed shift, never a float `sin` hash. A blur is the Glow recipe (quarter-size copy, 4 passes, `BlurMath.reach`), never a full-size wide kernel. Write the generated shader sources out and check by script that every uniform is used, every float literal has a point and loops have constant bounds, since there is no validator; add a luminance plot (100% and stacked three) for anything that can flicker.
