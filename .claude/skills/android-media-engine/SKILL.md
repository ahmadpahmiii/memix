# Android media engine (Media3)

Read `docs/TECHNICAL_DESIGN.md` → "Video engine" first. Before coding, check the current official docs and the latest stable Media3 version:
- https://developer.android.com/media/media3/transformer/composition
- https://developer.android.com/media/media3/transformer/multi-asset
Never guess class names or signatures from memory. If an API you expected doesn't exist, say so and adapt.

## Mapping

- Captions (P1-10): `AndroidCaptionRenderer` is the one caption renderer (layout once in canvas pixels; bundled TTFs with `Typeface.CustomFallbackBuilder`, Classic → Teko → system). `CaptionOverlay` is a composition-level `CanvasOverlay` (composition time in both player and Transformer in 1.11.1) that redraws only when the shown set changes; a lower export resolution draws every clip at that frame size and the overlay scales to it. `hideCaption` uses a per-composition switch plus a seek to the same position (no rebuild; `experimentalRedrawLastFrame` needs the replayable cache).
- Photo text (P2-03): `AndroidSceneCaptions` (`:engine:video` androidMain) implements `SceneCaptions` from `:core:ui` on top of `AndroidCaptionRenderer`, so the photo editor and later the photo export draw text like the video; layouts are cached (64) by words, style and canvas, opacity under 1 draws into a `saveLayerAlpha` group. `:engine:video` therefore depends on `:core:ui`; iOS binds `NoSceneCaptions` until P7-04.
- Canvas (P1-11): `CanvasFraming` draws each main clip into the frame size by the canvas rules: Fill and Fit are `Presentation` layouts (stretch within 1% of the shape), a color background is two scaled 1 × 1 `BitmapOverlay` bars, Blur is `Presentation`(fitted) → `GaussianBlurWithFrameOverlaid(sigma·s, s, s)` → `Presentation`(crop) with s = fit ÷ fill (stock effects; checked in the 1.11.1 source), a picture background (P2-12) is the same two bars cut from one `ImageDecoder` decode at the frame size (`BackgroundBars`, cover rule `coveredImageSize`; the builder decodes it, so call `build()` off the main thread). Gaps stay black. The preview draws at a 720 short side under Blur; `PreviewPlayback.shownCanvasSize` lets the editor cover a picture of the old shape.
- Mapping rules (order, gaps, trims, mute, detach, overlap lanes, cut at the main track's end) live in the shared `CompositionPlanner` → `CompositionPlan` (`:engine:video` commonMain). Change them there, never only in the Media3 builder, so iOS keeps matching.
- One `Project` → one Media3 `Composition` (`Media3CompositionBuilder`).
- Main video track → one `EditedMediaItemSequence` (clips in order, trims, speed, per-clip effects).
- Overlays, meme sounds, imported audio and voiceover → further sequences that overlap in time.
- Text and stickers → bitmaps rendered once per change and composited as overlay effects.
- Overlay layers (P4-01a, TECHNICAL_DESIGN → Overlays): several video sequences are composited by `VideoCompositorSettings` (`inputId` = sequence index). Media3 1.11.1 draws the primary input LAST (on top) and paces output by it; the primary is the first input *registered* (not necessarily index 0; the stage must register first, unverified on a device), and a video gap is opaque black, so the order is stage (hidden gap-only sequence), overlay layers top first, main video, audio lanes; every layer is padded to full length and its gaps are alpha 0. `CompositionPlayer` needs `MultipleInputVideoGraph.Factory()` set at build (the session swaps the player when overlays appear or vanish). Overlay math is `OverlayPlacement` in commonMain; video overlays are admitted against `VideoDecoderBudget` by `OverlayAdmission` (whole items, top layer first, same in preview and export). Read the Media3 source for compositor behaviour (the docs say little): raw.githubusercontent.com/androidx/media/<version>/libraries/effect. P4-01b: an overlay video's own sound plays (layer sequence with audio track types, `AudioChain.volume`, live gain; audio decoders are software and not in the video decoder budget); `PreviewSession.hideOverlay` (alpha 0 per frame through `OverlayVisibility`, the stand-in follows a finger) and `previewOpacity` (live alpha, no rebuild) read per frame in `OverlayCompositorSettings.LayerTimeline.settingsAt`; `ThumbnailReader.frame` reads the whole picture (PNG with transparency) for the stand-in; `OverlayPlacement` uses `fittedImageSize` (the 1% cover rule) so the editor's frame and the render agree.
- Effects/filters/transitions come from their declarative specs (`media-effect` skill); time params in µs.

## Preview (built in P1-04: `Media3PreviewSession`, TECHNICAL_DESIGN → Preview)

- `CompositionPlayer` plays the same `Composition` as export (same plan, same builder, same HDR mode). It needs every video and sound item's source length (`EditedMediaItem.setDurationUs`, at least the trim end); items without one, and missing files, become gaps and set `missingMedia`.
- Create the player only once the first composition is ready: in Media3 1.11.1, releasing a player that never got a composition leaves its playback thread running. `seekTo` before `setComposition` crashes.
- `PreviewSession.update(project)` calls `setComposition(new, positionMs)`, which rebuilds every sequence player in 1.11.1 (no incremental update yet). Measure it before promising an edit-to-preview time. The last frame stays on screen meanwhile: from the second composition on, CompositionPlayer keeps its video graph and surface (TECHNICAL_DESIGN → Preview → No black or gray frame); keep it that way (never clear or re-attach the surface on an edit) and keep `isCatchingUp` honest.
- Trim frames (P1-06): one composition of the clip's whole source per drag, then scrubbing seeks; never a rebuild per drag frame, and never publish the trim's time as `positionUs`.
- Show it with `VideoPreviewSurface(session, modifier)` (media3-ui-compose `PlayerSurface`, a SurfaceView; CompositionPlayer refuses TextureView). The composition root hands it to the editor screen as a slot, because features can't depend on the engine.
- Changes heard while a control moves (P1-08 Volume) go through a `LiveGainProcessor` per item with sound (each sound, and since P1-09 each main clip playing its own sound) that every preview composition carries (`previewVolume`), never a rebuild per frame; the release commits and rebuilds. Preview plans keep 0% items (`keepSilentItems`) with the live gain at 0 and no fixed volume step, so a raise from 0% is heard; export plans leave them out. Hand-check builds also put `SoundOnsetLog` on the whole mix (composition-level audio processors are flushed with the seek position as `StreamMetadata.positionOffsetUs` in 1.11.1), logging where each sound is heard (`MemixPreview`). Single sounds outside a project (the sheet) play on their own ExoPlayer (`Media3SoundPlayer`).
- Position: a `StateFlow<Long>` ticked by `Choreographer` while playing; the UI reads it only where it's drawn.
- `CompositionPlayer` and `media3-ui-compose` are `@UnstableApi`, `CompositionPlayer` also `@ExperimentalApi`: opt in to both with `androidx.annotation.OptIn` (lint).

## Audio effects and waveforms (P3-09a, TECHNICAL_DESIGN → Audio effects and timeline waveforms)

- Green screen (P4-04): `ChromaKeyEffect` (a `BaseGlShaderProgram`, straight alpha: Media3's compositor blends with `SRC_ALPHA`) goes first in a clip's effects; a keyed main clip adds `BackdropEffect` last (`CanvasFraming.keyedEffects`); `LiveChromaKey` carries the preview's slider values.
- Keyframes (P4-02a, TECHNICAL_DESIGN → Keyframes): the plan's `OverlayClip`, `VisualClip`, `SoundClip` and `CaptionClip` carry `keyframes`; the compositor's per-frame `settingsAt` calls `OverlayPlacement.of(clip, frame, clip.lookAt(time))`, `CaptionOverlay` redraws when a caption's `transformAt` changes, and keyed volume is `KeyframedGainProcessor` (per sample, `FramesProcessor`; Media3's `GainProcessor` is 0 to 1 only) via `AudioChain.volume(volume, keyframes, liveGain, tailUs)`.
- One function turns a clip's `AudioEffects` into processors: `AudioChain.forSound(clip, liveGain)` (androidMain), called only by `Media3CompositionBuilder.soundItem`; the preview and the export both build through the builder, so there is one chain. Order: `AudioEffectsCatalog.CHAIN_ORDER` (Sonic for speed and pitch, gain ramps for fades, P3-09b's voice, bass, echo and limiter in their places), then volume, then the preview's live gain. Add a stage in `AudioChain.effects`, never a second path.
- Media3 1.11.1 facts that matter (checked in the library, not from memory): `SonicAudioProcessor.setSpeed/setPitch` are independent and `getDurationAfterProcessorApplied` gives the sped-up length that `EditedMediaItem` uses for the item's duration; `GainProcessor(GainProvider)` is in media3-common, and its position is reset on a seek (`AudioGraphInputAudioSink` flushes with the position inside the item, `AudioProcessingPipeline.flush` maps it through each processor's duration change), so a fade processor placed after Sonic needs no seek code of its own. A processor that changes the length must say so through `getDurationAfterProcessorApplied`, or the sequence's later items drift.
- A clip's timeline length is `AudioEffects.timelineLengthOf(span)`; cuts in timeline time become source time with `sourceSpanOf` (rounded down). Never use `trimOut - trimIn` as a clip's length in new code: use `durationUs`.
- Everything in `AudioChain`, `FadeGains`, `PeakAccumulator`, `CompositionPlanner` runs on a desktop JVM against media3-common (plus a stub `android.util.SparseArray`, which `ChannelMixingAudioProcessor` needs): compile the files with `kotlinc`, drive an `AudioProcessingPipeline` with chunked PCM and compare renders. The null test of a new stage is that harness with the preview's and the export's chain; it proves the chains and chunking agree, not the phone's decoder, AudioTrack or encoder (on-device check).
- P3-09b: the maths lives in pure Kotlin kernels in `:engine:video` commonMain `audio/` (`BiquadFilter`, `SoftClip`, `RingModulator`, `EchoLine`, `PeakLimiter`), wrapped by `androidMain/audio/` processors on `FramesProcessor`. A processor with sound at the end of the stream (`TailProcessor`, `PeakLimiterProcessor`) extends `EndOfStreamProcessor`: Media3 repeats `queueEndOfStream` and reuses output buffers, so build the final sound once in its own buffer. Media3 maps the flush position through `getDurationAfterProcessorApplied`, so a processor that lengthens the stream shifts positions after it (`FadeGains(tailUs)` compensates). The echo tail is `SoundClip.tailUs`, capped at the video end by the planner. Live values (Bass, Distortion) use a `LiveBass` holder like `LiveFades`.
- Waveform peaks: `VideoEngine.waveform(source)` → `AudioPeaksReader` (MediaExtractor + MediaCodec decode, `PeakAccumulator`, `cache/waveforms/`); never decode on the main thread, never in a draw block.

## Voiceover recording (P3-08, TECHNICAL_DESIGN → Voiceover recording)

- `AndroidVoiceRecorder` / `VoiceCapture` / `AacM4aWriter` in `:engine:video` androidMain: `AudioRecord` (`MIC`, mono, 48 kHz then 44.1 kHz) read on its own thread in 20 ms chunks into MediaCodec AAC-LC and MediaMuxer (`<name>.part`, renamed when done). No foreground service: it runs while the editor is on screen. A Bluetooth output pins the built-in microphone with `setPreferredDevice`; never use SCO.
- Timing is the point of the ticket: `AudioRecord.getTimestamp(TIMEBASE_MONOTONIC)` gives (frame count, `System.nanoTime()`) at the capture pipeline's earliest point, so first-sample time = nanoTime minus frames/rate. Clock samples of the player (`PreviewSession.sampleClock()`) use `System.nanoTime()` too. Never mix `SystemClock.elapsedRealtimeNanos` in.
- The player is silenced for a no-headphones take with `setSilent` (`player.volume = 0`), engine only. It is re-applied in `newPlayer()`; a composition rebuild does not need it because edits are blocked during a take (check on a phone that `setComposition` keeps the volume).
- The check is the clap test (docs/qa/phase-3/engineer-hand-checks.md → P3-08); `VoiceoverTuning.extraOffsetUs` is the one correction and `MemixVoiceover` log lines are the readout.

## Export

- `Transformer` export (`TransformerExport`) under a foreground service with a progress notification and Cancel (`:platform:services`, `AndroidExportForeground`): `mediaProcessing` on Android 15+ through `Service.startForeground` (not `ServiceCompat`, which drops it), `dataSync` on 10 to 14.
- Before export: `exportCapabilities(canvasSize)` (per resolution and frame rate: H.264 hardware, else HEVC, else software H.264; sizes aligned to the encoder, long side as width) and free space; show the estimate. Export with `setEnableFormatFallback(false)` and a VBR bitrate clamped to the encoder's range.
- Encode straight into a MediaStore pending item in `Movies/Memix` (`GalleryVideoFile`, a custom `Muxer.Factory` with `Mp4OrientationData`); return location, duration and size. `WRITES_STRAIGHT_TO_GALLERY` switches back to a temporary file plus copy.
- Watermark (P1-13): `WatermarkOverlay`, a `CanvasOverlay` last in the composition `OverlayEffect` (after the captions), Anton from the caption renderer, constants in `WatermarkCatalog` (4% of the shorter side, ink box 3% from the left and the top, separate constants); exports only (`ExportSettings.watermark`, default on), never the preview.

## Rules

- No FFmpeg, no GPL code. Hardware codecs only.
- Release every player, codec and GL resource on dispose.
- Hit the budgets in `mobile-performance`; measure on the reference phone and put the numbers in the PR.
- For each new effect, save a reference render to `docs/qa/references/<effect-id>.png` (frame from the fixed sample project) so QA and the iOS port can compare by eye.
- Shape masks (P4-03b): `MaskEffect` (a `BaseGlShaderProgram`, straight alpha, `GL_BLEND` off, uniforms only on change) with `LiveMask`; overlays run key, scale, mask, main clips key, `Presentation`, mask, `BackdropEffect` (`CanvasFraming.layeredEffects`); `PreviewSession.previewMask`; CPU twin `MaskMath`; references `docs/qa/references/P4-03-masks/` (TECHNICAL_DESIGN → Shape masks).
- Video look (P4-07): `LookColorEffect` (adjustments + the filter's table, per pixel) and `LookDetailEffect` (sharpen as one merged-tap separable kernel written into the shader source, then vignette), `LiveLook`, `LutTables` (the photo editor's `.lut` files as N x N^2 textures); main clips key, look, `Presentation`, mask; overlays key, scale, look, mask; `PreviewSession.previewLook` (a look the composition wasn't built with rebuilds once); CPU twin `VideoLookMath`; references `docs/qa/references/P4-07-video-filters/` (TECHNICAL_DESIGN → Video filters and adjustments).
- Video effects (P4-06a): composition-level `EffectsEffect` between the caption overlay and the watermark (`Media3CompositionBuilder.compositionVideoEffects`), so effects hit captions and never the mark, in preview and export; one program reads `LiveEffects.spans` per frame from the presentation time and draws one pass per active item (max 3) with its own ping-pong targets (`EffectShaders`, GPU twin of `EffectMath`); `CompositionPlan.effects`/`hasEffects` (the pass is built only when an effect exists, and `Media3PreviewSession.sameComposition` keeps every other effect edit off the rebuild path); `PreviewSession.previewEffectIntensity` (TECHNICAL_DESIGN → Video effects).
- Video effects, second batch (P4-06b): the same one program, now 30 effects: `drawSecondBatch` in `EffectsProgram` (Glitch, RGB split and Tear share the `SHIFT` program; Static and Film grain the `NOISE` program and the noise texture made once per program; Blur, Tilt blur and Soft focus are four passes through the quarter-size targets, programs keyed by reach and compiled when the size is set; Radial blur and Smear 16 taps; VHS, Old screen, Fisheye, Mirror one pass). `frameTimeUs` (the presentation time) feeds `EffectNoise.frameIndex` for the random looks. Shaders in `GlitchShaders`, `BlurShaders`, `RetroShaders`; passes and taps per effect in TECHNICAL_DESIGN → Video effects, second batch.
