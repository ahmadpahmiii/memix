## Rules

1. Domain (`:core:model`, `:core:domain`) is pure `commonMain`.
2. Features call use cases only.
3. Platform code only in engine/platform modules, behind domain interfaces, plus the composition root (`:androidApp`, `:composeApp`) for entry and wiring only (driver creation, Koin start-up, debug hooks).
4. The iOS framework must compile on every PR.
5. No automated tests in this project; keep interfaces small anyway so behavior is easy to check by hand.

## Project model essentials

- `Project(id, type: VIDEO|PHOTO, name, canvas, video: VideoTimeline?, photo: PhotoScene?, createdAtEpochUs, updatedAtEpochUs, schemaVersion)` in `app.memix.core.model.project`.
- Overlays (P4-01a, schema 14): a `MediaClip` on an `OVERLAY` track with `transform`, `opacity` and `edit` (P4-16, inert); each overlay track is one layer, a later track draws over an earlier one; edits in `:core:domain` `OverlayEdits.kt`; engine: `OverlayPlacement`, `OverlayAdmission` (decoder budget), `OverlaySequences` (TECHNICAL_DESIGN → Overlays). P4-01b (`:feature:video-editor`): `OverlayUi` (a `GestureTarget`: caption gestures, edge snap, handle kept whole), `OverlayControl` (gestures, Position/Opacity/Layer order panels, stand-in), `OverlayFrames` (stand-in pictures from `ThumbnailReader.frame`), `OverlayLayer` and `OverlayPanels` in `overlays/`, `MissingMediaNotice` and `SkippedOverlayNotice`; domain adds `reorderOverlay`, `overlayLayerOf`, `overlayStackAt`, the ratio rule in `setCanvasRatio`, the duplicate offset and overlay Detach audio; ids `add_overlay`, `transform_overlay`, `position_overlay`, `overlay_opacity`, `overlay_order`; the photo editor's opacity and layer-order strings live in `:core:ui`.
- `Track(kind: MAIN_VIDEO|OVERLAY|TEXT|STICKER|MEME_SOUND|AUDIO|EFFECT, items, muted, locked)`; `TimelineItem(id, startUs, durationUs)` sealed: MediaClip, AudioClip, TextItem, StickerItem, EffectItem. Clip `durationUs` is derived from `trimOutUs - trimInUs`.
- Time = microseconds (`Long`), wall-clock timestamps included. Immutable; each edit → new Project. Editors edit through `ProjectEditSession` (`StartEditSessionUseCase`): `commit(tool) { }`/`undo`/`redo` (the `EditorTool` names the step, shown as "Undo: Split"; a recorded step logs `tool_use` itself and `commit` returns whether it recorded one); clip edits are pure functions in `:core:domain` `TimelineEdits.kt` (split, trim + `trimRange`, delete, duplicate, reorder; main track re-packed, other tracks keep their times), `SoundEdits.kt` (`addSound`, `setVolume`), `MoveEdits.kt` (`moveItem` with a `LaneTarget`, `moveItemToPlayhead`), `OriginalAudioEdits.kt` (P1-09: `setOriginalMuted`, `originalSoundOf`, `detachAudio`; no schema change), `TextEdits.kt` (P1-10; P2-11 adds shadow and box to `CaptionStyle`, schema 6, drawn by the same renderer: `addText` with its landing slot and lane, `editText`, `setCaptionStyle`, `setTextTransform`, Position panel steps; caption content in `CaptionCatalog`, `:core:model`; 250 characters counted by `text/Graphemes.kt`), `CanvasEdits.kt` (P1-11: `setCanvasRatio` keeps fully-inside captions inside, measured with the caption renderer through `CaptionBlockMeasure`; `setClipsFit`, `setCanvasBackground`, `sharedClipsFit`, `backgroundShows`; P2-12 adds `CanvasBackground.Image` (schema 4) with `setBackgroundImage` and `removeBackgroundImage`, and `mediaCopyPaths()` includes the background picture; sizes and rules in `CanvasCatalog`, `:core:model`) and `MediaEdits.kt` (P1-16: `insertMedia` at a `MediaPlace` with the shared fit, `replaceFit` + `replaceClipMedia`), 100 undo steps, auto-save 500 ms after the last change, `saveNow()` on ON_STOP, closed with `addCloseable` (a video draft left with no clip is deleted then); the video editor opens drafts with `OpenVideoDraftUseCase` (measures media saved before schema 2, and pictures with no size); stored as JSON in the SQLDelight `project` table (`:core:data`) + a thumbnail file. The composition root (`:composeApp` `databaseDriverModule`) creates the `SqlDriver`; `:core:data` stays commonMain.
- Media refs = `MediaRef(origin: GalleryUri | PhotoAsset | CatalogItem, kind, cachedCopyPath, durationUs, pixelSize, hasAudio)`; paths are relative to the app's files directory (gallery copies in `media/<project id>/`). Duration, shown size and has-sound are measured at import (schema 2) and null in older drafts. Importing goes through `ImportMediaUseCase` (copy, check, measure) driven by `MediaImportFlow` (`:feature:media-import`, sheet timing, space wait, results; `ProjectPickImport<R>` is the pick into an open project: the video editor's Add media, Replace and canvas background, the photo editor's background and, P2-13, Add photo), which hands the copies to an `ImportLanding`: `SaveGalleryProjectUseCase` for Create → Video meme, the edit session for the editor's Add media and Replace (`EditorMediaImport`, P1-16); the pickers are Compose hooks in `:platform:services` used only by the composition root (TECHNICAL_DESIGN → Media import). Unused copies of a saved draft go at the next app start (`LeftoverMediaCleaner`, P1-16). Media copies are never changed in place: a duplicated draft may share them (P1-14), so new media is always a new file. The drafts list (P1-14, `:feature:drafts`, use cases in `:core:domain` `drafts/`): rename, duplicate and an undone delete write through `ProjectRepository` with the times they want, never `SaveProjectUseCase` (which stamps the edit time); duplicates get their own `media/<id>/` folder with every path rewritten; delete keeps the `RemovedDraft` row in memory for the undo window (`DeleteDraftUseCase`, app scope); thumbnails are `media/<id>/thumb-<cover file>-<trim-in>.jpg` written by `UpdateDraftThumbnailUseCase` (TECHNICAL_DESIGN → Drafts list). Meme sounds come from `SoundLibrary` (P1-08: the bundled starter pack in `:platform:services` Compose resources, written once per run to the shared `sounds/<catalog id>.m4a`, origin `CatalogItem(id)`; titles looked up by id, TECHNICAL_DESIGN → Meme sounds). Library sounds downloaded in P3-04 live in the same `sounds/<id>.<ext>` place as the cache for previews only: a sound that lands on a timeline (P3-05) is copied into the project's own `media/<project id>/` folder by `PlaceSoundInProjectUseCase`, so the cleanup of the cache never touches a draft (only pins protect a playing or landing sound; `SoundsOnPhone` is the screens' one entry; TECHNICAL_DESIGN → Download manager, Sound picker in the video editor). The bundled starter pack stays the one shared file. P3-15: the Sounds tab's Use carries one library sound to the next new video meme in `PendingMemeSound` (owned and dropped by `MediaImportViewModel`, pinned), `SaveGalleryProjectUseCase` copies it into the new project's folder and adds it at 0:00 in the first save, and `VideoEditorRoute(startingSound)` tells the editor to bonk it (no selection, Undo empty).
- Keyframes (P4-02a, schema 15): `keyframes: List<Keyframe>` on `MediaClip`, `AudioClip`, `TextItem` and `StickerItem` (`Keyframe(timeUs relative to the item's start, look: ItemLook, easing: Easing)`, `:core:model` `Keyframe.kt`, `KeyframedItems.kt`, constants in `KeyframeCatalog`); the one evaluation is `interpolatedLook`/`lookAt` in `:core:domain` `KeyframeLook.kt` (preview, export and the stage all call it); edits in `KeyframeEdits.kt` (`addKeyframe`, `removeKeyframe`, `moveKeyframe`, `setKeyframeEasing`, `clearKeyframes`, `setLookAt` = auto-keying, project-time arguments); split, trim and ratio change handle keyframes in `TimelineEdits.kt`/`CanvasEdits.kt`/`OverlayEdits.kt`; engine: `OverlayPlacement.of(clip, frame, look)`, `KeyframedGainProcessor` (TECHNICAL_DESIGN → Keyframes). Editor half (P4-02b, `:feature:video-editor`): `KeyframeControl` + `KeyframeBarUi` (`keyframeBar` in the UiState), the `keyframes/` package (`KeyframeBar`, `EasingPanel`, `KeyframeNote`), marker row = a taller `LaneRow` (`markerHeightPx`) drawn by `TimelinePainter.drawKeyframeMarkers`, drag in `KeyframeDrag`; **every edit of a keyed item (or with its bar open) goes through `EditorHost.commitLook` = `setLookAt`, never the static setters** (`routesThroughKeyframes`); domain `KeyframeView.kt` (`keyframedItem`, `hasKeyframes`) and `setLookAtAddsKeyframe`; `GestureTarget.centerRange`; ids `keyframe_add`, `keyframe_remove`, `keyframe_move`, `keyframe_easing`, `keyframe_clear`.
- Green screen (P4-04, schema 16): `MediaClip.chromaKey: ChromaKey?`, `ChromaKeyCatalog` (`:core:model`); edits `ChromaKeyEdits.kt`, CPU twin `ChromaKeyMath`, `ChromaKeyPick.kt` (`picturePointAt`); engine `ChromaKeyEffect`, `BackdropEffect`, `LiveChromaKey`, `PreviewSession.previewChromaKey`; editor `GreenScreenControl`, `greenscreen/` (`GreenScreenPanel`, `PickLayer`); ids `green_screen`, `green_screen_off` (TECHNICAL_DESIGN → Green screen).
- Audio effects (P3-09a): `AudioClip.effects: AudioEffects` (`:core:model`, every field of P3-09a and P3-09b, schema 13), `AudioClip.durationUs` = trimmed span / speed; edits in `:core:domain` `AudioEffectEdits.kt` (`setFadeIn/Out`, `setPitch`, `setSpeed` with the lane rule, `resetAudioEffects`) and speed-aware split, trim and duplicate in `TimelineEdits.kt`; the engine builds one chain, `AudioChain.forSound`, for preview and export; `VideoEngine.waveform(source)` returns `AudioPeaks` (100 a second, cached) read by `ReadWaveformUseCase` into the timeline's `TimelineWaveforms`; panel: `AudioEffectsControl` and `AudioEffectsPanel` in `:feature:video-editor` (TECHNICAL_DESIGN → Audio effects and timeline waveforms).
- Audio effects (P3-09b): no schema change; `VoiceRecipes`, `BiquadSpec`, `EchoSpec` in `:core:model`; DSP kernels in `:engine:video` commonMain `audio/`; `SoundClip.tailUs` (echo tail, cut at the video end); edits `setBassBoost`, `setDistortion`, `setEchoAmount`, `setEchoLength`, `setVoice` in `AudioEffectEdits.kt`; `PreviewSession.previewBass` (TECHNICAL_DESIGN → Audio effects, second half).
- Voiceover (P3-08, `:core:domain` `voiceover/`): `VoiceRecorder` opens a `VoiceTake` that writes `media/<project id>/<uuid>.m4a`; `StartVoiceTakeUseCase`, `DiscardVoiceTakeUseCase`, `VoiceRouteUseCase`, `MicrophoneAskedUseCase`; `placeTake` (µs placement from two monotonic readings) and `addVoiceover` (an `AudioClip` on an Audio lane, origin `MediaOrigin.Recording`, schema 12); `PreviewSession.setSilent` and `sampleClock`; `VoiceoverTuning` carries the hand-check offset and log switch; the editor side is `VoiceoverControl` and `VoiceoverPanel` in `:feature:video-editor` (TECHNICAL_DESIGN → Voiceover recording).
- Make it a video meme (P2-10, `:core:domain` `photo/`): `MakeVideoMemeUseCase` bakes the photo scene (all layers under the lifted text) into one JPEG through `ScenePictureBaker`, writes it to the new project's `media/<id>/` folder and saves a new video project (3 s `FILL` clip + one `TEXT` lane per lifted text); `splitForVideoMeme` is the lift rule (the contiguous top run of fully opaque text; everything else baked); all or nothing, no schema change, the picture's origin is `CatalogItem("video-meme-picture/<id>")`; `VideoEditorRoute(madeFromPhoto)` opens the Meme sounds sheet after arrival and `VideoMemeNoteUseCase` gates the one-time note (TECHNICAL_DESIGN → Make it a video meme).
- Export (P1-12): one `ExportVideoUseCase` single in the app's scope (state `Idle | Running | Done | Failed | Cancelled`, read by the Exporting screen, the editor and the notification); the engine fills `ExportCapabilities` per canvas (`exportCapabilities`); settings, learned speed and the unfinished-export record live behind `ExportPreferences` (`:core:data`, multiplatform-settings); the foreground service and notification behind `ExportForeground`, share behind `Sharer`, exit reasons behind `AppExitReasons` (`:platform:services`); the file goes to the gallery (`Movies/Memix`, MediaStore pending item), only the debug export hook writes `cache/exports/` (TECHNICAL_DESIGN → Export).
- Effects/filters/transitions = `id + params` specs rendered identically by both engines; each has a reference render in `docs/qa/references/`.
- Persisted shape change → bump `Project.CURRENT_SCHEMA_VERSION` and add a `ProjectMigration` step in `:core:data` (`ProjectMigrations.kt`); check by opening an old draft after upgrading. A table change adds `migrations/<n>.sqm`; CI runs `:core:data:verifySqlDelightMigration`.

## Engine interfaces (shape)

```kotlin
interface VideoEngine {   // app.memix.core.domain.video; members join with the ticket that first uses them
    suspend fun export(project: Project, settings: ExportSettings, onProgress: (Float) -> Unit): ExportOutcome  // P1-03; P1-12: Done(ExportedVideo) | Failed(ExportError), file into the gallery
    fun createPreview(project: Project): PreviewSession   // P1-04: play/pause/seekTo/update/close, playback + positionUs StateFlows; P1-05 setScrubbing; P1-06 showTrimFrame/endTrimFrames, playback.isCatchingUp; P1-08 previewVolume; P1-10 hideCaption
    fun openThumbnails(): ThumbnailReader   // P1-05: suspend thumbnail(source, timeUs, sizePx) -> one square JPEG tile; close()
    fun openSoundPlayer(): SoundPlayer   // P1-08: the sounds sheet's previews (one sound at a time); close()
    suspend fun waveform(source: MediaRef): AudioPeaks?                                     // P3-09a: ~100 peaks a second, cached on disk; null when unreadable
    suspend fun exportCapabilities(canvasSize: PixelSize): ExportCapabilities               // P1-12: per canvas, scanned once per process
    suspend fun discardUnfinishedExports()                                                  // P1-12
    fun openResultPlayer(location: String): ResultPlayer                                    // P1-12: the Exported screen's player
}
// Project → engine: CompositionPlanner (:engine:video commonMain) builds a plain CompositionPlan in µs;
// each platform only translates it (Media3CompositionBuilder on Android, AVFoundation in P7).
// Export plans drop 0% items; preview plans keep them (plan(keepSilentItems = true)) so a live gain can raise them.
// Captions (P1-10): CaptionClips in the plan, drawn by the engine's one caption renderer in a composition-level overlay;

    suspend fun modelState(): ModelState
    suspend fun prepareModel(onProgress: (Float?) -> Unit): ModelPreparation
    suspend fun segmentImage(sourcePath: String): SegmentationOutcome   // grayscale PNG mask; videoSession joins with P4-13
}
```

## Region and language (P3-11)

The region the screens read comes from `ObserveRegionUseCase` (confirmed region, else the phone's, else Global); never read `DeviceRegion` from a feature. The app language belongs to the platform (`AppLanguageSwitch`; Android 13+ `LocaleManager`, API 29 to 32 a stored tag from `LanguageOverride` applied in `attachBaseContext` plus `recreate()`, iOS stub): store the region only, and write names with `DeviceRegion.displayName(code, language)`. Feed cache keys are per region. Details: TECHNICAL_DESIGN → Region sheet. Compare language codes only through `AppLanguage.fromTag` and read the app language in UI with `appLanguageCode()` (`:core:ui`); Java reports Indonesian as "in".
- Shape masks (P4-03b, schema 17): `MediaClip.mask: ClipMask?`, `MaskCatalog` (`:core:model`); edits `MaskEdits.kt` (`setClipMask`, `setMaskShape`, `MaskStep`), `MaskBox.kt`, CPU twin `MaskMath`; engine `MaskEffect`, `LiveMask`, `PreviewSession.previewMask`; editor `MaskControl`, `masks/` (`MaskPanel`, `MaskStage`, `MaskGestureMath`, `MaskStageGeometry`); ids `mask`, `mask_adjust` (TECHNICAL_DESIGN → Shape masks).
